## 上下文

最初的 MVP 为求简单，将完整的代理循环放在 Electron 主进程中。

新的产品约束：

1. 偏好更强大的系统级后端
2. 保留 pi Agent Harness 作为模型/代理引擎
3. 提升长期隔离性与原生能力质量

## 原始决策

MVP 的代理循环运行在 Electron 主进程中。

## 修订方向

采用混合模型：

- **Rust 后端主机核心**负责桌面宿主服务、工具沙箱、插件宿主边界、持久化适配器以及特权操作
- **Node/TypeScript pi 运行时**仍是代理循环引擎（`pi-ai` + `pi-agent-core`），并作为受控的 sidecar/utility 进程运行
- **Electron 主进程**成为渲染器 IPC 与 Rust/Node 服务之间的轻量编排者

## 影响

### 正面
- 更优的原生/宿主能力基础
- 更清晰的权限边界
- 保留 pi 生态的复用优势

### 负面
- 相比纯 Node 主进程，集成复杂度更高
- 需要 Electron/Rust/Node 之间稳定的本地 RPC
