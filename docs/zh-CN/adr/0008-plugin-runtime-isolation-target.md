# ADR 0008：插件运行时在独立进程中隔离

> **翻译说明：** 本页是与 [英文源决策](/adr/0008-plugin-runtime-isolation-target) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受（2026-07-29 实现）
- 日期：2026-07-25

## 上下文

插件代码不受信任；我们必须防止其拖垮或侵入宿主。

## 决策

目标架构：插件主逻辑运行在**独立进程**中（UtilityProcess/子进程），并通过 RPC 访问宿主 API。

若 MVP 进度受限，可临时采用更轻量的隔离方案，但不得破坏：

- 权限网关
- API 允许列表
- 贡献点的统一注册
- 崩溃不致命

临时方案及其迁移计划必须记录在实现 ADR 中。

## 理由

1. 崩溃隔离
2. 更清晰的权限代理
3. 后续可加入资源限制

## 后果

### 正面
- 更好的安全性和稳定性

### 负面
- 更高的实现与调试成本

## 实现（2026-07-29）

目标架构已交付；不再保留过渡性的主进程内运行时。

- `apps/desktop/electron/main/plugin-host-process.mjs` 是每个插件各自的入口，
  通过 `utilityProcess.fork` 派生（每个插件一个进程，打包到
  `out/main/plugin-host-process.js`）。它只接收最小化的环境，因此宿主的 shell 环境
  和供应商密钥永远不会进入插件代码。
- `apps/desktop/electron/main/plugin-runtime.ts` 成为中介层：它维护
  命令/工具的注册表，每次 `pi.*` 调用都以 RPC 形式到达，依次经过
  `HOST_API_ALLOWLIST`、`assertPermission`、宿主服务，最后写入审计日志。
  插件代码不持有任何宿主对象，也不 `require` 任何宿主模块。
- 贡献点仅按描述符注册；可调用的那部分留在插件进程中，并带超时地
  通过 RPC 回调（命令 30s，工具 110s，生命周期钩子 5s，加载 15s）。
- 插件进程退出时其影响被控制在局部：挂起的调用以
  `PLUGIN_CRASHED` 拒绝，贡献点被注销，面板关闭，渲染器
  收到一条 toast 提示以及 `pluginChanged`。
- `onUnload` 现在会在进程被终止之前（在子进程中）执行。

已知限制，本次变更有意不涉及：

- 插件进程是 Node 环境；权限管控覆盖的是 `pi.*` 这一接口面，
  而非插件进程内直接使用 `require("node:fs")`。能力沙箱化（D009）
  仍属于未来工作。
- 资源限制（CPU/内存）尚未强制执行。
- 清单中声明的权限在加载时仍会自动授予。
