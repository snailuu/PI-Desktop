# ADR 0014：采用主机核心拥有的存储 schema v2

> **翻译说明：** 本页是与 [英文源决策](/adr/0014-host-owned-storage-schema-v2) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-07-26

## 背景

最初的桌面端持久化模型将持久状态分散在一个有限的 SQLite schema 与 Electron 拥有的 JSON 文件之间。会话消息存储的是有损的文本投影，项目身份被表示为一个单例工作区，定时任务绕过了 Rust 主机核心，而多个产品界面对于回合、工件、任务运行、模型元数据或索引搜索都没有持久化模型。

这些边界与 ADR 0011 中已冻结的主机核心所有权规则相冲突，并使协议可见的行为取决于最后写入本地文件的是哪个进程。就地扩展旧表还会留下归属不明以及迁移行为不一致的问题。

## 决策

在唯一由主机核心拥有的 `pi.sqlite` 数据库中采用 schema v2。

Rust 主机核心是以下内容的唯一写入方：

- 带命名空间的键/值配置；
- 项目及项目作用域的会话；
- 规范化的转录块与回合生命周期数据；
- 模型目录元数据；
- 工件；
- 定时任务与任务运行历史；
- 已索引、可裁剪的审计事件。

Electron 只能通过主机核心 RPC 协议访问这些状态。定时任务 JSON 会被导入主机核心数据库，不再具有权威性。

迁移是按 `PRAGMA user_version` 键控的、按顺序执行的 Rust 函数。v1 到 v2 的迁移会在重建不兼容的表之前创建一次性备份，保留可恢复的用户数据，并以事务方式完成。会话/项目导入与旧版定时任务导入都是幂等的。

## 后果

- 持久状态只有一个所有权边界和一个迁移机制。
- 转录块、回合、用量、工件、项目分组、任务历史与搜索都可以演进，而无需渲染器拥有的持久化。
- 迁移失败会被上报，而不是静默打开一个只部分升级的数据库。
- 在用户删除备份之前，备份会占用额外的磁盘空间。
- 协议、存储、迁移和 E2E 规格必须与未来的结构性变更同步调整。
- schema v2 取代了 D086 之前描述的存储实现，同时保留 ADR 0011 的 Rust 主机核心所有权边界。

## 备选方案

### 不重建而直接扩展 v1 表

拒绝，因为 v1 的消息形态是有损的，而且拆分所有权模型仍会保留。

### 将定时任务保留在 Electron JSON 中

拒绝，因为这违反了主机核心拥有的持久化边界，并阻碍任务/运行生命周期的原子更新。

### 让渲染器直接写入 SQLite

拒绝，因为并发写入方会把 UI 生命周期与数据完整性耦合起来，并绕过主机核心 RPC 校验。
