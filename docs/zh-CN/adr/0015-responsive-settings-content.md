# ADR 0015：让设置内容宽度响应窗口宽度

> **翻译说明：** 本页是与 [英文源决策](/adr/0015-responsive-settings-content) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-07-26

## 背景

D070 根据 1200px 宽的 Codex 黄金采集确定了 720px 的设置内容带宽度，D090 在简化设置目录的同时保留了这些视觉指标。尽管整页设置外壳和右侧面板已经随原生窗口调整大小，但这一固定上限在更宽的窗口上仍会留下越来越大的未使用空间。

设置卡片需要使用实际的桌面窗口尺寸，同时保留固定的导航栏、可读的面板边距以及现有的紧凑外壳。

## 决策

设置内容的内层容器填满右侧面板在扣除 275px 导航栏和面板边距后所剩宽度的 100%。CSS flex 布局负责调整尺寸；渲染器不添加窗口监听器、视口计算或 JavaScript 布局状态。

本决策仅取代 D070 的 720px 内容带宽度上限，以及 D090 中保留该上限的部分。D070 和 D090 中所有其他导航、界面框架、间距、卡片、主题和交互决策保持不变。

## 后果

- 设置卡片会随原生窗口调整大小而立即扩展和收缩。
- 宽窗口不再在内容右侧保留任意的空白区域。
- 最低支持的窗口宽度仍能保留固定导航栏和现有面板边距，且不会出现页面水平滚动。
- 设置规格和 E2E 覆盖必须验证窄、默认和宽三种窗口尺寸。

## 备选方案

### 保留 720px 上限

已拒绝，因为它忽略了可用的原生窗口宽度，并在更大的显示器上浪费空间。

### 在 React 中计算宽度

已拒绝，因为现有的 flex 布局已经暴露了正确的可用面板宽度，而 JavaScript 窗口监听器会增加不必要的状态和同步工作。

### 使用视口宽度公式

已拒绝，因为手动减去导航栏和边距会重复 CSS 布局知识，并可能漂移导致溢出。
