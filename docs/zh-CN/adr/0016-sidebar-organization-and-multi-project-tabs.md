# ADR 0016：围绕保留的多项目标签页组织侧边栏

> **翻译说明：** 本页是与 [英文源决策](/adr/0016-sidebar-organization-and-multi-project-tabs) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-07-26

## 背景

D088 将混合的“最近项”列表替换为一个当前项目分组加上无路径的临时会话。这使工作区边界变得可见，但也迫使每次项目切换都要替换唯一的项目分组，并移除了基本的组织控制。跨多个仓库工作的用户需要在侧边栏中保留这些项目、折叠非活动分组，并对项目和对话行进行置顶或归档，而不删除持久数据。

主机目前通过 `workspace.set`（渲染器桥接处的 `project.set`）暴露一个选中的工作区。代理回合、权限和对话记录已经按会话为键。将主机工作区替换为多工作区单例会扩大特权状态的暴露面，并使后台工具执行依赖于渲染器最近选择了哪个标签页。

## 决策

### 保留的项目标签页

- 渲染器保留一组有序的规范化项目路径。每个保留的路径在侧边栏中显示为可独立折叠的项目分组。无路径的临时分组保持独立。
- 打开项目会添加其路径，而不关闭其他标签页。选择标签页会通过现有的 `project.set` 操作激活该路径。主机仍然只有一个活动工作区，用于可见的 shell 上下文。
- 关闭标签页只会移除其在侧边栏中被保留的条目。它不会归档项目、删除会话，或移除主机所有的 `projects` 行。当活动标签页关闭时，渲染器会激活一个剩余的标签页，或清空所选工作区。

### 渲染器所有的组织元数据

- 项目元数据以规范化完整路径为键，包含 `pinned`、`archived`、`collapsed` 以及可选的手动 `order`。
- 对话元数据以持久会话 id 为键，包含 `pinned`、`archived` 以及可选的手动 `order`。
- 面向用户的侧边栏排序支持 `recent`、`created`、`oldest` 和 `name`。置顶行始终排在未置顶行之前；所选排序为次级顺序。为兼容性保留了持久化的 `manual` 值和可选的 `order` 字段，但本决策不引入拖拽或其他手动重排交互；没有显式既有顺序的行使用稳定的最近顺序回退。
- 归档是非破坏性的。已归档的行默认被省略，可通过显式的已归档视图恢复。删除仍然是独立的主机操作。
- 展示记录是尽最大努力的渲染器本地存储。它不包含任何对话记录、工具参数、供应商密钥或其他特权数据。

### 会话工作区隔离

- 与会话关联的项目是该会话工具根的权威来源。`tools.execute` 从持久化的 `session.projectPath`/`project_id` 解析工作区，而不是从可变的活活动标签页。
- 选择另一个项目或对话绝不会中止正在运行的回合。每个会话的运行状态和授权保持独立，后台工具调用仍然被沙箱限制在发起会话的项目内。
- 临时会话没有项目根。切换到临时对话会清空可见的活动工作区，且不会继承先前所选项目的工具访问权限。

本决策取代 D088 的单一当前项目和无多项目树的限制，并恢复了随 D068 被取代的按范围限定的项目/对话行操作。D088 的精确路径分组、按范围限定的草稿复用以及临时会话边界仍然有效。不需要新的渲染器 IPC 通道。

## 后果

- 侧边栏可以在一个可独立滚动的区域内显示多个项目分组，而主面板仍然显示一个目标/对话记录。
- 当渲染器偏好可用时，项目/会话的置顶、归档、折叠、排序以及打开路径在应用重启后仍保留。清除这些偏好只会重置展示；主机所有的项目和会话保持完好。
- 激活缺失或无法访问的保留路径会报告现有的工作区错误，而不会静默删除该标签页或其会话。
- 主机工具执行必须先加载会话，再解析其工作区。没有持久会话的遗留调用可以在兼容窗口期内回退到所选的宿主工作区。
- 项目索引仍然是持久项目目录，也是已关闭或已归档侧边栏标签页的恢复路径。

## 备选方案

### 只保留恰好一个项目分组

被否决，因为它会在每次项目切换时丢弃工作集，并使并行会话工作变得繁琐。

### 在主机 schema 中存储归档和置顶标志

在本迭代中被否决，因为这些标志仅影响本地展示。持久项目/会话的身份和删除仍然属于主机。

### 为每个打开的标签页添加一个主机工作区

被否决，因为只有工具执行需要工作区根，而持久会话已经标识了它。第二个主机工作区注册表会重复项目/会话状态。

### 在单独的本地窗口中打开每个项目

被否决，因为它会成倍增加窗口/进程状态，并且无法解决主工作台中的对话组织问题。
