## 背景

工作面板最初被引入作为用于工作区审查、嵌入式浏览器预览、文件浏览和交互式 shell 的停靠式界面。每个界面都需要由主机持有的边界，因为沙盒化的渲染器无法自行安全地执行工作区或窗口操作。

## 决策

保留的工作面板子系统包括：

1. **浏览器。** Chrome 和代理 CDP 作为捆绑插件 `pi.browser` 提供（ADR 0170）。Electron 主进程仍然持有访客 `WebContentsView`、导航策略、权限拒绝、外部弹窗处理以及实测边界钳制。
2. **审查。** 消息所拥有的审查快照和受保护的 rollback 仍是主机集成的界面，由成功的工作区 Write/Edit 工件打开。
3. **文件。** 项目浏览由捆绑的 `pi.files` 插件通过公共 contributed-view 和文件系统 API 提供。
4. **对话记录资源。** 文件和 URL 工件仍是由对话打开的会话级标签页，而不是通用启动器。

原先的交互式终端子系统不属于当前产品。其移除（包括桌面 IPC 和打包清理）由 ADR 0108 定义。代理 Bash 是一个独立的非交互式代理工具，不是工作面板子系统。

## 后果

- 渲染器保持沙盒化，原生浏览器/插件界面继续使用既有的实测边界和可见性规则。
- 审查和文件工件保留对话归属，而项目浏览使用捆绑的 Files 插件。
- 交互式 shell 访问由外部终端提供，而不是由 PI-Desktop 工作面板标签页提供。

## 考虑过的替代方案

- 将每个面板界面都做成代理工具被否决，因为用户驱动的浏览和审查会继承代理的权限、截断和审计语义。
- 为捆绑插件赋予私有主机能力被否决，因为这会绕过公共插件边界。
- 保留原先的交互式 shell 被 ADR 0108 否决，以移除其单独的原生界面和生命周期界面。
