# ADR 0020：配置供应商工作室

> **翻译说明：** 本页是与 [英文源决策](/adr/0020-configuration-provider-studio) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-07-26

## 上下文

Agent/Configuration 标签页此前以堆叠的设置行和密集的常驻表单来承载默认项与供应商。这种布局使就绪状态难以快速扫读，默认供应商被埋没，多供应商管理更像一个原始的 CRUD 表单，而非现代化的桌面控制界面。

紧凑设置目录已将 Providers 保留在 Agent/Configuration 内，不设独立的导航栏目的地。信息架构保持不变；只有该区块的呈现方式与交互密度需要改进。

## 决策

设置 → Agent/Configuration 呈现为一个**供应商工作室**：

1. 用于默认供应商/模型组合的紧凑默认项卡片
2. 供应商账户区块，每个 OAuth 账户一行，包含编辑、测试连接和移除操作
3. 模态的 OpenAI 兼容供应商添加/编辑 composer
4. 基于卡片的供应商管理，包含密钥徽章、思考预设、测试连接、设为默认和删除

密钥在保存后保持只写。不引入新的设置导航栏目的地。

## 后果

- 在存在多个供应商和账户时，配置更易于扫读
- 页面保持单一视觉层级，无需单独的概要主视觉区
- 空状态与有数据状态都有明确的下一步操作
- spec、e2e 与 i18n 描述了该工作室的呈现方式
- 未来的供应商预设可以以 composer 入口的形式加入，而无需改变导航栏的信息架构

## 备选方案

### 保留密集的堆叠表单
被否决，因为它只针对首次进入进行优化，一旦存在多个供应商就会劣化。

### 将 Providers 重新拆分为导航栏目的地
被否决，因为紧凑目录有意将 Providers 合并进 Agent/Configuration；本次重新设计改进的是既有区块，而不是重新扩大导航宽度。
