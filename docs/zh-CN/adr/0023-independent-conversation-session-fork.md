# ADR 0023：独立对话会话分叉

> **翻译说明：** 本页是与 [英文源决策](/adr/0023-independent-conversation-session-fork) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 状态

已接受。

## 上下文

PI-Desktop 已经可以在单个对话中保留线性重试变体。用户还需要一个 Codex 风格的命令，用于复制当前对话，以便后续的提示词和配置变更可以与源对话分叉，而无需重写源对话。

在渲染器中组合 `session.create` 与消息替换会暴露不完整的子会话、丢失规范化的转录块、遗漏每个会话的执行配置，并跨越 Rust 主机核心的持久化所有权边界。此外，在保留协议 v4 的情况下新增该操作，还会允许较旧的主机核心通过启动握手，却只在新命令被调用时才失败。

## 决策

- 协议 v5 新增必需的宿主进程 RPC `session.fork` 和渲染器 IPC `session/fork`。
- Rust 主机核心拥有单一的快照操作：默认情况下，它会把源会话完整的活动规范化转录复制到新会话中，并重新映射消息和工具调用标识符。可选参数 `throughMessageId` 使快照以该消息为终点（包含该消息）；未知边界不会创建任何子会话并返回 `NOT_FOUND`。
- 子会话继承项目、供应商、模型、模式、思考设置和权限模式。它不继承回合、重试修订、通知、工件、会话授权、临时数据、固定状态或实时运行时状态。
- 不存储父子血缘关系。这是一次独立的对话复制，既不是消息树，也不是线性重试历史记录的替代品。
- 助手响应的 Fork 直接使用有界快照。助手 Edit 使用同一个有界子会话，将原始/编辑后的响应尾部存储在该子会话已有的线性修订存储中，并激活编辑后的尾部。源转录、修订、运行时和供应商缓存状态均保持不变。
- 仅当源会话空闲时才可使用 Fork。Electron 暴露 `AGENT_BUSY`；主机核心保留一个已持久化的运行中回合 `CONFLICT` 守卫，Electron 在 IPC 边界对其进行规范化。
- 已处理的文件或索引故障会移除子会话转录，不留下可见的子会话。进程崩溃则继续遵循转录存储已有的孤儿文件恢复策略。

## 后果

- 协议 v4 的渲染器和主机核心二进制文件会在启动期间被拒绝，而不是在选中 Create branch 时才延迟失败。
- 源会话与子会话可以独立地演进、重新配置、持久化和删除。
- Fork 的存储成本与活动转录的大小成正比。
- 消息作用域的 Fork/Edit 存储成本与所选响应对应的规范化前缀加上任何子会话专属的修订负载成正比。
- 每个子会话都有新的会话 id，并首次创建/重新初始化自己的 pi 运行时；编辑后的上下文绝不会复用基于源转录构建的缓存状态。
- 初始实现有意不提供血缘 UI、合并操作或任意消息级分支树；Edit 的回滚仍然是一个包含两个条目的线性修订家族。

## 备选方案

- 渲染器自有的 `create + replaceMessages`：已拒绝，因为它在主机核心拥有的转录和索引之间不是原子的。
- 持久化的父子血缘关系：已推迟，因为所请求的工作流只需要一份独立副本，且 D109 保持消息修订导航为线性的。
- 复制重试修订：已拒绝，因为修订根和消息标识符将需要第二棵分支图和歧义的翻页历史。
