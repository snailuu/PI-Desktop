# ADR 0026：将项目索引作为归档移入设置

> **翻译说明：** 本页是与 [英文源决策](/adr/0026-project-archive-in-settings) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：目的地数量/顺序部分被 ADR 0036 取代
- 日期：2026-07-27
- 决策者：PI-Desktop 主机核心
- 相关：D066、D090、D093、D133、ADR 0013、ADR 0016

## 上下文

当前主页侧边栏同时暴露了一个独立的项目目的地和保留的项目分组。活跃工作通过保留的分组进行，而项目目的地主要充当一个持久目录，用于发现、归档、恢复、重新打开和关闭历史项目记录。

将两个界面都放在主导航中会重复项目概念，并使归档管理获得与任务创建和插件同等的突出地位。ADR 0013 中冻结的四个目的地设置目录没有地方容纳这个项目管理界面，因此移动它会改变设置信息架构，并需要修订基线。

## 决策

1. 从主页侧边栏、应用页面状态和全局页面搜索结果中移除独立的项目目的地。
2. 在设置中导入之后、信息之前添加 **项目归档**（`项目归档`）。设置现在有五个目的地：基础、模型配置、导入、项目归档和信息。
3. 在归档中复用持久的项目索引。它保留搜索、添加、激活、项目会话展开、固定、归档/恢复和关闭操作。
4. 设置归档始终包含已归档的项目记录。已归档的项目行保留其弱化呈现，并可从其现有操作菜单恢复。展开的项目详情不应用侧边栏的已归档会话可见性过滤器。
5. 激活项目或项目会话会离开设置并返回聊天。归档或关闭项目会使项目归档目的地保持可见，包括在必须选择回退工作区时。
6. 主页侧边栏保留保留的项目分组和持久的新建项目操作。项目存储、渲染器呈现元数据以及单可见工作区激活模型保持不变。
7. 设置和全局设置搜索索引项目归档及其归档、恢复、项目标题和项目搜索词。

## 后果

- 主页侧边栏少了一个主要目的地，并为活跃项目和会话工作提供了更多视觉优先级。
- 历史和已关闭项目仍可通过设置恢复，包括未作为侧边栏标签保留的导入路径。
- 设置从四个目的地增加到五个，仅在目的地数量和顺序上取代 ADR 0013。
- 没有 IPC、宿主 RPC、数据库、安全或项目激活契约变更。
- 现有持久化的项目/会话归档元数据保持兼容。

## 替代方案

### 在主页侧边栏和设置中都保留项目

被拒绝，因为重复导航导致归属不明确，并且不会减少主页侧边栏的主菜单。

### 只显示已归档行

被拒绝，因为已关闭但未归档的持久项目将失去其唯一的基于索引的恢复路径。归档是一个完整的历史目录，已归档行始终包含在内，而不是仅归档过滤器。

### 将项目管理放入基础

被拒绝，因为一个完整的可搜索项目索引是目的地级别的工具，而不是应用程序默认行或紧凑设置卡片。
