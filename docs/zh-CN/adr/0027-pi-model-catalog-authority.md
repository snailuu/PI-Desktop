# ADR 0027：让 pi-ai 成为模型元数据的权威来源

> **翻译说明：** 本页是与 [英文源决策](/adr/0027-pi-model-catalog-authority) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-07-27

## 上下文

PI-Desktop 此前从 pi-ai 读取推理提示，但会用桌面端自有的默认值和供应商级覆盖重建一个更小的运行时模型。因此，已知模型会丢失 pi 的上下文窗口、输出上限、输入模式、定价、请求头以及部分兼容性记录。设置中此前还允许用户独立于所选模型替换推理支持、思考等级、上下文大小、输出大小和温度。

这种所有权分裂使模型行为取决于两处配置。它还要求 PI-Desktop 针对单个模型的语义打补丁，例如 MiMo 的思考方言和 Claude 的自适应关闭行为。

## 决策

对于从 pi-ai 内置目录解析出的每一个模型，pi-ai 都是模型元数据和兼容性行为的唯一权威来源。

- Electron 主进程解析出一份完整、可序列化的 pi 模型快照：名称、base URL、推理标志、思考等级映射、输入模式、定价、上下文窗口、输出上限、请求头以及兼容性数据。
- sidecar 原样使用该快照，仅替换运行时连接标识：所选模型 id、已配置的供应商 id、所选 API 适配器以及显式配置的端点 URL。
- PI-Desktop 不再改写已知模型的推理支持、思考等级、上下文限制、输出限制、温度或兼容性标志。
- 供应商设置不再暴露模型参数覆盖项，模型菜单也不再为未知模型启用推理。
- pi 无法识别的自由格式模型 id 仍然允许使用。它采用显式的通用纯文本、非推理回退方案，并配以保守的运行时限制。这保留了开放的自定义供应商路径，同时不会声张 pi 尚未公布的模型能力。
- 缓存/发现的模型列表仍作为选择和离线发现数据；它们不会覆盖运行时模型语义。
- 对已知模型的更正应在上游 pi-ai 中完成，或通过升级 pi-ai 实现，而不是在 PI-Desktop 中做针对特定模型的补丁。

本决策取代 D102 以及 D096/D107 中的供应商覆盖条款。它不改变 ADR 0018 中持久会话的思考等级枚举或转录处理。

## 后果

- 在原生和兼容端点上，已知模型都保留其锁定版本的 pi-ai 所交付的完整元数据。
- PI-Desktop 少维护一份模型矩阵，也不会在无人察觉的情况下偏离 pi 的适配器。
- 升级 pi-ai 可能会刻意改变可用的思考等级或模型限制，因此必须由目录解析测试覆盖。
- 未知的自定义模型仍可用于文本，但针对特定模型的推理、视觉、定价和大上下文保证要等到 pi 识别它们之后才会提供。
- 出于兼容性考虑，旧版供应商覆盖字段在持久化记录中可能仍可读取，但它们不再影响运行时解析。

## 备选方案

### 将供应商覆盖合并到 pi 元数据之上

拒绝，因为它保留了双重所有权，并可能产生所选适配器或模型不支持的组合。

### 仅保留来自 pi 的思考兼容性

拒绝，因为它仍会丢弃上下文、输出、输入、定价以及其他模型特有的字段。

### 拒绝未知模型 id

拒绝，因为它会违反产品对自由格式自定义供应商的策略，并把随附的目录变成封闭的白名单。
