# ADR 0028：将工作面板运行时上下文限定到对话

> **翻译说明：** 本页是与 [英文源决策](/adr/0028-session-scoped-work-panel-contexts) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

渲染器此前拥有一个全局的工作面板标签页集合。按照 D128 的要求，选择另一个对话或工作区会关闭该面板并销毁其中的每个标签页。这样做虽然阻止了相对资源泄漏到另一个工作区，但当操作者返回某个对话时，也会丢弃其中有用的工具。

受权限门控的工具暴露了该模型中的竞态。某个工具可能在批准后完成，而此时另一个对话正在加载。如果完成事件到达时选择尚未提交，其工件会短暂打开全局面板随后被清除，从而造成可见的尺寸闪动。如果完成事件在选择提交后到达，后台会话守卫则会完全丢弃该工件。BrowserPreview 在到达渲染器之前也丢失了其来源会话身份，因此可能针对当前可见的工作区解析相对路径。

## 决策

每个对话拥有一个渲染器内存中的工作面板上下文，其中包含其打开状态、有序标签页、活动标签页、文件请求以及 Browser 资源。

- 选择某个对话时会保存当前投影，并原子性地恢复目标上下文。切换离开时绝不删除任一上下文。
- 新建和派生的对话以空上下文开始。删除某个对话会移除其保留的上下文。
- Review 和 BrowserPreview 工件按其来源 `sessionId` 记录，包括该对话处于后台期间。
- 后台工件仅更新保留状态。它们不会打开、激活、导航、调整大小或聚焦可见面板。
- BrowserPreview 事件携带 `sessionId`。Electron 主进程从该持久会话的 `projectPath` 解析本地预览路径，并且仅当来源对话的 Browser 标签页可见时才进行导航。
- 在没有活动对话的情况下选择工作区会隐藏当前面板投影，同时保留先前对话的状态。
- 工作面板上下文保持瞬态。重新启动会丢弃它们；仅面板宽度保持持久化。

本决策采纳 D142，并且仅取代 D128 中关于在可见会话/工作区变化时关闭并清除标签页的要求。D128 的工件触发、去重以及关闭/折叠规则保持不变；其无启动器规则由 ADR 0068 修订。Electron 主进程、preload IPC 以及渲染器的所有权边界保持不变。

## 后果

- 返回某个对话会恢复其工具，而不会针对另一个工作区重新解释路径。
- 权限完成和异步导航不再产生瞬时的面板打开/关闭循环，也不会丢失由此产生的工件。
- 渲染器会保留有界的按会话 UI 状态，直到删除或重新启动；它不新增持久化存储或 schema 迁移。
- 内嵌浏览器仍然是单个经过加固的主进程 WebContentsView。其可见资源跟随所选对话，而不是允许后台预览对前台视图进行导航。
- 先前的交互式终端进程/缓存不再是工作面板运行时的一部分；Browser 仍然是主进程拥有的原生资源。

## 备选方案

### 在每次上下文变化时继续清除标签页

被拒绝，因为它会失去任务连续性，并且无法同时避免权限完成导致的闪动与后台工件被丢弃的问题。

### 将面板上下文持久化到主机存储

被拒绝，因为标签页和 Browser 资源属于瞬态的呈现状态。实现持久化将需要 schema、清理以及陈旧资源策略，却无法改善所报告的进程内工作流程。

### 按对话为每个后端面板子系统设定键

本变更中拒绝。可见标签页上下文和 BrowserPreview 路由确实需要对话所有权；但这并不意味着每个后端资源都需要持久化。
