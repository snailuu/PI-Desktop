# ADR 0030：回合边界上下文检查点压缩

> **翻译说明：** 本页是与 [英文源决策](/adr/0030-turn-boundary-context-checkpoint-compaction) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受；软边界、模型工具与可见性条款部分被 ADR 0061 取代，随后由 ADR 0064 部分恢复
- 日期：2026-07-28
- 最后修订：2026-08-06
- 修订方：ADR 0049（故障恢复）、ADR 0061（后台压缩；移除软边界提示、`CompactContext` 工具，以及压缩活动的可见性）、ADR 0064（Codex 对齐；压缩重新内联，面向模型的工具和预算提醒回归，且每次压缩均可见）

## 背景

一次长时间的 pi 代理运行在 `agent_end` 之前可能包含许多模型/工具回合。仅在用户提示之间或运行已经终止之后才进行压缩，无法保护该循环内下一次对供应商的请求。观测到的 Bedrock 故障达到 1,077,172 token，而供应商上限为 1,000,000 token，因此供应商在 PI-Desktop 拥有恢复点之前就拒绝了该请求。

pi-agent-core 已经提供会话上下文重建、token 估算、切点选择、摘要生成、保留尾部处理和压缩记录。它并未定义 PI-Desktop 的渲染器生命周期、由 Rust 负责的持久化、供应商余量策略或长循环防护。

OpenCode Dynamic Context Pruning（DCP）（检视于提交 `85b6f5ceba144fee9e65eb28dc36cab1b960e418`）展示了一些有用的行为模式：每个回合都评估上下文，在紧急边界之前注入去重后的引导信息，并允许模型请求上下文管理。它是 AGPL-3.0 许可下的 OpenCode 插件，因此直接链接或复制它会为 PI-Desktop 引入不兼容的运行时和许可边界。

## 决策

PI-Desktop 使用 pi-agent-core 的公开压缩原语，并独立实现桌面端特有的控制器。

- 控制器在每次 `turn_end` 之后、pi 发起下一次供应商请求之前运行。`turn_end` 是模型/工具回合的边界；只有 `agent_end` 或 `error` 才会结束整个桌面端运行。
- 预算计算使用 pi-ai 的模型上下文/输出限制。请求余量至少为：配置的预留量、被限制在上下文 25% 的模型输出额度，或上下文的 5%。配置的预留量不得占用超过一半的窗口。保留尾部目标不得超过剩余硬预算的一半，因此小窗口模型仍可被压缩。*（ADR 0061 保留该余量规则，并从模型窗口而非设置中推导预留量与保留目标。ADR 0064 移除 ADR 0061 的后台限制，并将保留尾部替换为仅保留最近的用户消息，上限为 20,000 token。）*
- 在软边界处，一条临时的系统指令会要求模型以当前任务焦点调用 `CompactContext`。它仅在工具回合之后才有资格触发，且最多每三个符合条件的回合重复一次。该指令不会被持久化，也不会修改持久化的系统提示。*（已被 ADR 0061 取代：软边界与该指令均被移除。）*
- `CompactContext` 绕过 Rust 工具/权限桥，因为它改变的是模型上下文而非工作区。它的调用与结果使用常规工具事件，并作为一条工具活动行保持可见/持久。所请求的检查点仅在该工具回合结束后才生成，从而保持供应商有效的调用/结果配对。*（ADR 0061 移除了该工具；ADR 0064 以 `new_context` 之名将其恢复，语义相同，并恢复了转录中的一行——该行是由检查点拥有、而非工具活动行的分隔线。）*
- 在硬边界处，运行时确定性地生成检查点。候选上下文在持久化之前重新估算，并在继续之前再次估算。自动摘要失败或检查点无效时，首先尝试 ADR 0049 定义的保留尾部恢复；如果该恢复无法准备、无法持久追加，或无法降到安全预算之下，循环会在发起下一次供应商请求之前以 `CONTEXT_COMPACTION_FAILED` 停止。*（ADR 0061 将这条路径原样保留为安全网；在 ADR 0064 下它再次成为唯一路径。）*
- 最后一批工具结果会与其助手工具调用载体一起保留。如果该原子批次超过常规的保留尾部目标，运行时会允许 pi 将切点移动到该载体。如果该批次本身达到硬预算的一半，PI-Desktop 会创建一个仅用于检查点的有界副本：每个结果保留其工具标识/错误封装，以及带有显式检查点截断标记的头部/尾部文本公平份额，同时省略重复的诊断细节。原始持久消息和可见转录保持完整。有界副本在持久化之前会重新估算，且绝不会授权超大的供应商请求。
- 供应商精确溢出是最后的安全网。失败的助手消息为便于诊断保持可见，但会从模型上下文中移除；运行时会创建一个检查点并重试模型请求一次。第二次溢出即终止。
- 自动保护默认启用。禁用它会移除模型工具，并禁用阈值与溢出恢复。手动 `/compact` 对空闲会话仍然可用。*（ADR 0061 移除了面向用户的开关：保护始终开启，持久化的 `enabled: false` 值会被忽略。）*
- 协议 v6 新增了由主机拥有的 `session.appendCompaction` 操作以及压缩生命周期事件。主机会向会话 JSONL 文件追加一行带类型的检查点。可见消息绝不会被上下文压缩删除、改写或隐藏。
- 只有最新的有效检查点才会重建模型上下文。转录改写仅在其边界仍然存在时才保留它。分支仅在分支包含该边界时才复制并重映射它。

## 后果

- 长时间的工具循环在唯一能够在不中断进行中的模型或工具调用的前提下保护下一次请求的边界处获得上下文检查。
- 确定性的硬防护不依赖模型是否听从提醒。
- 重启和模型变更会保留压缩后的工作上下文，而不改变人类可读的对话。
- 压缩本身是一次额外的供应商请求，并且可能失败。自动失败有确定性、持久化的保留尾部恢复，而手动压缩仍是快速失败；该生命周期是显式的、可中止的，并通过稳定的事件/错误码呈现。
- 检查点可能会保留超大原子工具结果批次的、面向模型的缩短副本。这是在压力下对模型可见细节的损失，但它在上下文中是显式的，保留了每一组调用/结果配对，且不会改变用户可见的或诊断用的转录。
- 在重建检查点时，保留的助手消息上的供应商 token 计数会被清除，因为该用量描述的是压缩前的请求，否则会多算恢复后的上下文。
- OpenCode DCP 的更新不会自动流入 PI-Desktop。未来任何行为上的采纳都需要重新进行独立的实现评审。

## 备选方案

### 直接集成 OpenCode DCP

拒绝，因为它面向 OpenCode 的插件钩子和持久化模型，且采用 AGPL-3.0。PI-Desktop 需要 Rust 主机的持久性契约和 pi 特有的回合生命周期，因此适配器会保留大部分实现成本，同时增加许可与升级耦合。

### 仅在 `agent_end` 时使用 pi 压缩

拒绝，因为在一次长时间运行中，工具回合之间不会出现 `agent_end`。下一次供应商请求可能已经超大。

### 仅依赖模型提醒

拒绝，因为模型可能忽略、推迟或重复该请求。软性引导对摘要焦点有用，但无法强制执行供应商限制。*（ADR 0061 更进一步，完全移除了该提醒：在预计算检查点的情况下，它唯一剩下的效果就是浪费一个回合和一行转录。ADR 0064 以不同的形式恢复了提醒——两条与剩余 token 数相关的预算通知，而不是要求调用工具——并将硬边界保留为强制执行点，正是本拒绝条款所要求的。）*

### 删除较早的可见转录消息

拒绝，因为上下文管理不得破坏用户历史、修订族、分支输入、可搜索性或诊断信息。
