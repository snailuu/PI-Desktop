# ADR 0031：让输入框提示行不包含品牌图标

## 上下文

D054 在空草稿旁引入了可见提示标记，D094 将该标记统一为停靠在会话线程中的输入框里的标准 PI-Desktop logo。首页输入框后来移除了该标记，使两处提示行在视觉上不一致。在密集的对话记录中，残留的装饰性 logo 还会占用输入区的横向空间，却不提供任何导航、状态或运行时含义。

由于 D094 属于已冻结的产品基线，因此即便实现仅限于渲染器呈现层，移除其对停靠输入框的要求也需要一个明确的取代决策。

## 决策

1. 首页输入框与停靠在会话线程中的输入框的提示行均不渲染前置品牌图标。
2. 草稿文本与占位文本从输入行的标准内容边距处开始；不会为已移除的标记预留任何布局空间。
3. 渲染器 `BrandLogo` 组件在首页主视觉区、展开/折叠侧边栏和启动闪屏中继续使用该标准资源。原生 Dock、应用菜单和“关于”标识继续使用同一标准资源在各自平台上的特定形式。
4. 会话创建控件保留其专用的消息加号图标。
5. 本决策仅取代 D054 关于前置品牌提示标记的要求，以及 D094 关于停靠输入框中 logo 位置的规定。所有产品命名及剩余的品牌资源要求保持不变。

## 后果

- 首页与对话记录输入框共用同一个无图标的提示行边界。
- 文本域获得了此前被 15px logo 及其间距占用的宽度。
- 移除该渲染器节点的同时也移除了相关的主题专用 CSS。
- 品牌识别仍通过外围外壳得以延续，而无需在文本输入界面内重复产品标识。

## 备选方案

### 保留停靠的 15px logo

已否决。该方案保留了历史上的品牌约定，但也保留了不一致的输入行结构，并且在不传达状态或操作的情况下占用空间。

### 将 logo 重新加回首页输入框

已否决。在两个文本输入界面中重复该标识只会增添装饰性元素，而非简化提示路径。
