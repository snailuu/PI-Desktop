## 背景

插件路线图中列出了一个“MCP 插件类型”，但背后没有任何实现。如果某个插件想暴露某个 MCP 服务器的工具，就必须把每一个工具都重新实现为插件代理工具，并自行代理流量——这是重复劳动，而且代理发生在宿主机无法审查的插件代码中。

有两条约束塑造了该设计。首先，代理已经拥有一条可用的插件工具路径：`plugin_<pluginIdSafe>_<toolName>` 从模型出发，经由 sidecar 流向主机核心的权限门控，再回到 Electron 主进程（`07-plugins/12` 附录）。任何复用该路径的方案都能免费继承超时、审计轨迹以及按插件粒度的禁用开关。其次，MCP 服务器是顶着同一个名字的两种截然不同的事物：一种是我们启动的本地可执行文件，另一种是我们向其发送参数的远程端点。它们的失败方式不同，泄漏方式也不同。

## 决策

1. MCP 服务器**在清单中声明**，绝不在运行时打开。`contributes.mcpServers` 携带 `{ id, label?, transport }` 以及且仅有一种传输方式的字段——`stdio` 使用 `command` / `args` / `env`，`http` 使用 `url` / `headers`。混用二者的清单会在主机核心和 SDK 校验器中都无法通过校验。
2. 两种传输方式携带**各自的权限**：stdio 对应 `mcp.server.local`，HTTP 对应 `mcp.server.remote`。运行本地二进制文件与把工具参数发给第三方是两种不同的授权，因此权限说明文案会分别明确陈述二者。
3. 客户端位于 `apps/desktop/electron/main/plugin-mcp.ts`，使用协议 `2025-06-18`：`initialize`、`tools/list`、`tools/call`。分帧方式为基于 stdio 管道的 NDJSON，或带 SSE 响应的可流式 HTTP。预算：完成握手 10 秒，每次调用 100 秒（低于 110 秒的插件工具预算，而后者又低于主机核心的 120 秒），8 个 `tools/list` 分页，每行 stdio 数据 4MB，每个服务器 64 个工具，每个插件 8 个服务器。连接是惰性的——声明一个服务器在工具被调用之前不产生任何开销——并且拆除随卸载进行。
4. 发现的工具以 `plugin_<pluginIdSafe>_<serverId>_<toolName>` 注册进**现有的**插件工具映射，因此模型与服务器之间任何位置都不需要新增路由。
5. 每个发现的工具都以 `risk: "medium"` 注册。其名称、schema 与描述来自第三方服务器；来自该来源的自述风险等级不构成证据。
6. 凭证**仅**通过 `{ "setting": "<key>" }` 从插件自身的设置中解析（D018）。stdio 子进程接收 `PATH`、临时/区域设置相关变量、`PI_PLUGIN_ID` 以及所声明的值——而不接收宿主环境，因为宿主环境中存放着供应商密钥。`command` 必须是裸 PATH 名称，或位于插件目录之内；`url` 可以使用 `http` 或 `https`，非回环的 HTTP 受 ADR 0142 与插件网络允许列表约束。

## 后果

- 插件以一条清单条目的形式交付一个 MCP 服务器，其工具会以正确的命名空间、审计和超时出现在代理面前。
- 审查一个插件能触及什么，只需阅读它的清单：每一个端点和可执行文件都是声明式文本，而不是运行时决定。
- 工具数量上限和分页上限是有意为之的静默截断——一个拥有 200 个工具的服务器只贡献 64 个，并记录丢弃数量，而不是淹没提示词。
- 由于 MCP 工具与手写的插件工具位于同一张映射中，禁用插件会同时移除二者，插件崩溃也会同时丢失二者。
- 远程服务器会看到工具参数。宿主机侧做再多的谨慎处理也改变不了这一点；权限及其文案存在的目的就是让用户来决定。

## 备选方案

### 仅支持 stdio

已否决。托管式 MCP 端点很常见，而仅支持 stdio 会迫使插件作者把它们包装进一个本地 shim 进程——多出一个进程外加一个无法审查的代理，在这两方面都比一个声明式的 HTTP(S) URL 更糟。

### 单独的 `type: "mcp"` 插件类型

已否决。它需要自己的生命周期、自己的管理 UI，以及自己的工具路由。在现有插件类型上增加一个贡献点，可以原样复用安装、启用/禁用、权限与审计。

### 让插件进程自己持有 MCP 连接

已否决。这样连接就会位于插件自身代码之后、处于 broker 视野之外，于是宿主既无法限制工具集合，也无法让凭证远离插件的触达范围。

### 信任服务器自述的工具风险

已否决。风险驱动主机核心的确认流程。由被审查方选定的值不能用来决定审查行为。
