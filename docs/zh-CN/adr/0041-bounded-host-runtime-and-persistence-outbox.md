# ADR 0041：限制宿主运行时资源并解耦消息持久化

> **翻译说明：** 本页是与 [英文源决策](/adr/0041-bounded-host-runtime-and-persistence-outbox) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-01

## 上下文

此前，Rust 宿主会为每个 RPC 派生一个不受限的 Tokio 任务，并且可以启动任意数量的 shell 进程。在本地突发场景下，这会导致 `Resource temporarily unavailable`，随后引发并发的宿主重启以及向已销毁的 stdio 管道写入。由此产生的持久化错误掩盖了最初的资源故障。

## 决策

主机核心为 RPC 和工具执行持有一个有界准入预算。工具类别拥有各自独立的全局限制，每个会话也有一个限制，并且队列是有限的。对瞬时性的进程派生资源故障采用有界退避；已启动的命令绝不自动重试。超时的子进程在被释放其许可之前先被回收。

Electron 的宿主监督是单飞且具备代次感知的。过期的宿主代次无法发出通知，也无法接受新的 RPC 写入。助手消息和工具消息的追加会通过一个由 Electron 主进程持有、基于文件的发件箱（outbox）进行，并在宿主握手成功后按顺序刷新。握手会**等待**该排空完成之后才将宿主宣告为就绪，因此冷启动的 `session.get` 不会与排队的助手/工具行发生竞争（D327）。宿主端的消息追加按消息 id 保持幂等。

## 后果

- 突发请求会被拒绝或施加背压，而不是耗尽进程资源。
- 单个宿主失败不会引发重启风暴或数百个过期管道错误。
- SQLite 的所有权仍然专属于主机核心。
- 应用数据目录中增加一个小型恢复发件箱文件。
- 缺失的 sessions 行会从实时 JSONL 恢复（或以相同 id 创建为存根），以便排队的发件箱能够排空；`session.delete` 会丢弃该会话的发件箱条目，因此存根无法复活已删除的对话（D318）。
- 工具容量可通过 `app.health` 和结构化日志被观测到。

## 已否决的备选方案

- 提高重启次数上限：掩盖资源泄漏并放大崩溃循环。
- 仅在 `Bash` 周围加信号量：会让 RPC、插件、读取和持久化的扇出保持不受限。
- 仅内存中的持久化缓冲：如果 Electron 在宿主恢复之前退出，将丢失消息。
