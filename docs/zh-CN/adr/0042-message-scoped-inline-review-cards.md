## 上下文

此前，对话记录会在聊天底部渲染一个会话拥有的 Review changes 命令。该命令汇总整个脏工作树，因此在视觉上与引发更改的 Write/Edit 行相分离，并且不会告知用户应检查哪个文件。它还仅仅为了回答关于某个工具结果的局部问题而要求打开一个面板标签页。

现有的 Git diff 已经是有界的、竞态安全的，并且由 Review 标签页共享。此次重新设计应复用这一单一事实来源，而不是引入第二个由渲染器拥有的 diff 或持久化的归属映射。

## 决策

1. 成功的 workspace Write/Edit 行可以在同一活动折叠区域内、紧跟该行之后渲染一个紧凑的 `InlineReviewCard`。卡片的作用域由该工具结果中返回的 workspace 路径确定，因此无关文件及其他会话不会出现在其旁边。
2. 卡片头部显示新增、修改、删除、重命名和未跟踪文件的本地化文件状态，以及新增/删除总数。原生按钮通过 `aria-expanded` 和 `aria-controls` 就地切换匹配的当前 hunk。
3. 失败、被拒绝、草稿、干净、非 Git 以及缺失 workspace 的结果不会渲染卡片。后台会话的卡片仍附加到其自身的对话记录，绝不会出现在当前可见的会话中。完整的 Review 标签页仍作为所有文件的当前工作树视图可用，并继续通过成功的 workspace 工件打开。
4. 移除会话到工作区的评审归属映射。内联卡片的存在与否由对话记录消息、活动工作区和共享 workspace diff 推导得出；不新增任何评审专用的持久化或协议字段。

## 后果

- 评审入口紧邻产生它的操作，无需打开工作面板即可使用。
- 新增、修改、删除、重命名和未跟踪状态使用一致的 状态/计数/diff 呈现方式。
- Review 标签页仍然适合扫描每个当前文件，而卡片则在对话中提供路径作用域的检查。
- 卡片反映其路径的当前有界工作树 diff。因此，外部编辑或之后对同一文件的编辑会使卡片与 Review 标签页一同更新；渲染器不会虚构第二条 diff 时间线。

## 被拒绝的替代方案

- **保留一个全局对话记录入口：** 使操作与产生它的行相分离，并在单个摘要中暴露无关文件。
- **持久化单独的消息级补丁流：** 重复 Git diff 这一单一事实来源，扩展消息协议，并需要为外部编辑新增保留与失效规则。
- **每次点击卡片都打开 Review：** 为局部检查增加上下文切换，并使对话记录卡片依赖面板可见性。
