# ADR 0050：有界供应商流恢复与诊断

> **翻译说明：** 本页是与 [英文源决策](/adr/0050-bounded-provider-stream-recovery) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-04

## 上下文

供应商重试层覆盖了建立请求过程中的失败，但供应商也可能在助手流已经开始之后终止。之前的运行时将常见的 `terminated` 消息归类为通用的 `PROVIDER_ERROR`，结束该回合，并让重新生成来创建新的运行时并重新播种转录记录。这使得瞬时流失败的代价很高，也让长时间等待供应商的问题难以从日志中归因。

重复的变更失败也有相关代价：模型可能会不断修复一个已过时的补丁，或者使用陈旧的上下文重试 `Edit`，而不是对目标文件获取新的快照。

## 决策

PI-Desktop 应用以下有界恢复策略：

1. 将 `terminated`、流的过早关闭以及等价的未完成流消息归类为可重试的 `STREAM_FAILED` 错误。在 `AppError.details` 中仅保留安全的、低基数的供应商 status/code 字段。
2. 为 pi-ai 请求设置配置一个供应商级别的重试，以及上限为 8 秒的可中断延迟。转发持久会话 id，以便支持请求亲和性的供应商适配器可以复用它。
3. 当流已经开始之后发生瞬时的 `STREAM_FAILED`、`NETWORK_ERROR` 或 `TIMEOUT` 时，在同一个回合内经过 750 毫秒的可中止退避后重试一次。从下一个模型上下文中移除失败的助手，复用它可见的助手消息 id，并替换部分内容，而不是创建重复气泡。第二次失败即为终止。
4. 在可用时附加 `phase`、`providerWaitMs`、`streamMs`、供应商 status/code 以及 `retryAttempt`。这些字段仅用于诊断；消息保持脱敏且有界，除现有的上限摘要外绝不包含凭据或原始供应商响应体。
5. 变更指令对于一处小型唯一替换选择 `Edit`，对于连贯的整文件重写选择 `Write`。在编辑不匹配之后，代理获得一次全新的读取/重新生成尝试。在同一个提示中，同一路径的第二次失败 `Edit`，或 shell 补丁命令的第二次失败，会返回 pi-agent-core 的终止性工具提示，因此代理会以精确的不匹配信息停止。Shell 的 `apply_patch`、`git apply` 和 `patch` 被明确视为补丁命令；提示会引导代理改用 `Edit` 或 `Write`。它不得手工编辑 unified-diff 工件，也不得对同一路径发起并发变更。

## 后果

- 单次瞬时流终止不再强制重新生成或产生新的转录/运行时边界。
- 对于已恢复的回合，渲染器只看到一个助手气泡和一个终止生命周期。
- 供应商错误仍然可以从代理解析计时和应用会话日志中诊断，而不会暴露机密。
- 重试预算是有界的：持续中断、认证错误、上下文失败以及第二次流失败仍然可见且可操作，而不是进入无界循环。
- 变更恢复是确定且有条界的。真正过时的文件或无效的 shell 补丁需要在第二次失败后由用户/模型做出新的决策，而不是再进行一次自动工具回合。

## 备选方案

### 在同一个回合中重试所有供应商错误

已拒绝，因为认证、模型选择、格式错误的请求以及上下文错误无法通过重放同一请求来修复。

### 无限期地重试流失败

已拒绝，因为它掩盖持续中断、消耗供应商配额，并使用户无法重新掌控会话。

### 为每次流尝试都创建一个新的助手气泡

已拒绝，因为部分尝试和失败尝试看起来像多个回答，并且会使持久转录的对账变得复杂。

### 让补丁修复完全由提示驱动

已拒绝，因为仅靠措辞并不能可靠地约束模型的重试循环。主机的唯一上下文检查和按会话的变更串行化仍然是执行边界，而运行时的终止性工具提示在 pi-agent-core 中强制第二次 Edit 或 shell 补丁失败时停止。
