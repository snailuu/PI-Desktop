# ADR 0058：扩展页面密度与主题可读的按钮表面

> **翻译说明：** 本页是与 [英文源决策](/adr/0058-extensions-page-density-and-button-contrast) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- **状态：** 已接受（信息架构由 ADR 0112 修订）
- **日期：** 2026-08-05
- **决策：** D196

## 上下文

扩展（Extensions）目标是聚焦的双标签页插件界面：已安装与插件市场。MCP、技能（Skills）与子代理在 设置 > 代理 下独立管理。四数字概览条保留了已由标签页、分组与更新状态表示的派生计数，占用了垂直空间却没有增加决策点。共享按钮基元还依赖灰度别名与透明文本混合填充，导致次要操作和主题切换在深色模式下过于薄弱。

## 决策

1. 从扩展页面移除数字概览条及其四个派生计数器。保留已安装与插件市场这两个标签页，以相关计数、已安装状态分组与待更新提醒作为可操作的层级。
2. 使用语义主题 token 定义共享的主按钮与次按钮：
   主按钮使用 `--ds-accent` 与 `--ds-bg-primary`；次按钮
   使用 `--ds-bg-secondary`、`--ds-text-primary` 与 `--ds-border-default`。
   悬停状态使用 `--ds-accent-hover` 与 `--ds-bg-tertiary`。
3. 仅将其视为渲染器展示层变更。插件、MCP、技能、
   插件市场、权限、宿主、协议与存储契约均不
   变更。

## 后果

- 页面标题与分段控件能更快到达有用内容，并为扩展行、卡片与编辑器保留更多空间。
- 计数的唯一真相来源仍紧邻其所描述的界面。
- 主操作与次要操作在深色与浅色主题下都具有不透明、主题正确的表面以及可见的语义边缘。
- 未来任何概览摘要都必须引入独立的操作或决策点，而不是重复标签页或分组状态。

## 考虑过的替代方案

- 保留概览条并缩减为两张卡片：拒绝，因为它仍然重复状态，并使四标签页层级不均衡。
- 只修复扩展页面的按钮：拒绝，因为共享的 `Button` 基元在全应用范围内使用，对比度缺陷是系统性的。
- 添加按主题硬编码的颜色：拒绝，因为这会绕过语义 token 契约，并使未来的主题变更更难。
