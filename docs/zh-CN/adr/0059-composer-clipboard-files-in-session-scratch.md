# ADR 0059：在会话暂存区中持久化输入框剪贴板文件

> **翻译说明：** 本页是与 [英文源决策](/adr/0059-composer-clipboard-files-in-session-scratch) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-05
- 决策者：PI-Desktop 主机核心
- 相关：D197、D209、ADR 0024（输入框命令与 @ 文件引用）、ADR 0070（紧凑引用显示）、D114（会话暂存目录）、D119（transcript 文件存储）

## 背景

输入框是一个受控的 textarea。Chromium 将粘贴的操作系统文件和截图暴露为 `File` 对象，而原生选择器暴露的文件可能位于当前工作区之外。纯文本提示词契约没有二进制 `ImageContent` 通道，并且附件文件在提示词发送后必须仍可供代理使用。将字节写入项目会污染 git 状态，也不符合会话绑定的工作区/暂存区归属规则。

## 决策

1. 渲染器仅在剪贴板包含一个或多个 `File` 对象时拦截粘贴。纯文本粘贴保持原生 textarea 行为。
2. 渲染器通过 `composer/pasteFiles` 将受限的文件字节以及浏览器提供的名称和 MIME 类型传输到 Electron 主进程，并附带持久会话 id。主页输入框在传输前会创建或复用一个会话。原生选择器的选择项使用增量的 `composer/importFiles` 通道，并携带相同的会话 id；主进程在向渲染器返回引用之前会解析并复制这些源路径。
3. Electron 主进程会校验会话是否存在，将请求限制为 20 个文件、每个文件 64 MiB、总计 128 MiB，剥离目录部分和不安全的名称字符，并在以下路径下以独占创建语义写入唯一文件：

   ```text
   <data_dir>/scratch/<sessionId>/pasted/
   ```

4. 主进程返回每个以 UUID 为支撑的绝对路径，以及经过清理的原始叶子名称。在 ADR 0070 下，渲染器将该路径保存在临时引用状态中，将叶子名称显示为紧凑的 chip，并使用现有的空白引用规则将路径作为 `@` 引用序列化到提示词中。提示词和 transcript 携带的是路径，而不是剪贴板字节。
5. 粘贴的文件遵循现有的暂存区生命周期：删除会话或启动时的孤儿/过期扫描会移除它们。它们不是工作区工件，也绝不会改变项目的 git 状态。

## 安全与边界说明

- 渲染器无法选择目标目录；会话 id 在主进程中被校验，输出根目录基于主机数据目录构造。选择器源路径通过 `realpath` 解析，且必须是常规文件；它们永远不会成为提示词引用或目标路径。
- 渲染器提供的名称会被缩减为 basename 并经过清理。UUID 前缀和独占创建可防止冲突和按名称覆盖。
- 该桥接仅限 Electron。它不新增主机 RPC 方法，也不会向渲染器暴露任意文件系统写入访问权限。

## 考虑过的替代方案

- **仅插入浏览器文件名：** 丢失字节，且无法给代理提供可用路径。已拒绝。
- **写入工作区：** 使普通粘贴污染项目，并破坏会话暂存区隔离。已拒绝。
- **将二进制内联随提示词发送：** 改变纯文本提示词契约，膨胀上下文，并需要针对供应商的附件处理。已拒绝。
- **使用 Electron 文件选择器处理粘贴：** 不支持截图，并且为常见的剪贴板工作流增加了额外交互。作为粘贴路径已拒绝；单独的选择器上传操作现在对显式选择的文件复用此暂存区契约。

## 后果

- 文件和图片粘贴在主页和停靠输入框中均可工作，且不会修改项目文件。
- 可见草稿会获得紧凑的叶子名称引用；派发的提示词会获得相同的常规 `@absolute/path` 引用，因此现有的 Read/Glob/Grep 行为可处理这些已实体化的文件。
- 大型或格式错误的剪贴板负载会在输入框中可见地失败，且不会部分写入，因为字节在首次写入之前已经过校验。
