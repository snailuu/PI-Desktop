# ADR 0063：全局子代理定义的管理界面

> **翻译说明：** 本页是与 [英文源决策](/adr/0063-subagent-management-ui) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

ADR 0062 交付了子代理，但没有渲染器界面。用户只能把 Markdown 文档放到某个与实现相关的路径下才能创建个人代理，并且随应用发布的目录在设置中不可见。管理界面不得写入受跟踪的项目文件，也不得悄悄引入与运行时契约不一致的项目级来源。

## 决策

### 1. 全局文档是唯一由用户管理的子代理来源

用户自有的定义是位于以下路径的 Markdown 文件：

```text
~/.agents/subagents/<id>.md
```

不存在项目级子代理目录。应用不会为能力管理而扫描或写入 `.pi/agents`。`id == name` 仍然是模型的 `Task` 句柄，重复名称会被拒绝，运行时的全局用户目录与内置项合并，且没有项目能力层。

### 2. 启用状态仅存于应用本地

文档拥有提示词元数据（`name`、`description`、`tools`、`model`、`thinkingLevel` 和 `maxTurns`），但从不拥有 `enabled`。启用状态存储在 `<data>/agent-capabilities/subagents.json` 中。扫描全局文件夹会移除已删除文档的状态，因此文件缺失时不会留下可见的待处理行或孤立的覆盖项。

### 3. 设置页面仅涉及全局

设置 > 代理 > 子代理 是一个固定高度的全局列表。该界面中没有项目选择器、项目列，也没有添加/导入操作。每一行显示 frontmatter 摘要和本地启用开关；切换开关只会写入应用本地状态文件，并在下一次运行时目录加载时生效。

技能与 MCP 有各自的设置入口，而不是扩展中的标签页。扩展本身只包含已安装和插件市场。

### 4. 运行时仍是唯一事实来源

Electron 在下一次提示时将全局用户文档提供给 `loadSubagentDefinitions`。渲染器不会重新实现目录优先级，也不会凭空创造项目来源。内置项和格式错误的文档由运行时加载器处理；管理列表就是扫描得到的全局用户文档列表。

## 后果

- 个人代理会跨项目跟随用户，而无需修改任何仓库。
- 需要仓库特定提示词的团队必须使用项目常规的指令机制；`.pi/agents` 不是能力来源。
- UI 可以展示并持久化本地启用状态，而无需修改 Markdown 文件。
- 不存在项目范围的子代理开关，因此项目优先级仅适用于技能和 MCP。
