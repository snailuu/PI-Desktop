# ADR 0065：平滑 shell 布局与流反馈

> **翻译说明：** 本页是与 [英文源决策](/adr/0065-smooth-shell-layout-and-stream-feedback) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

shell 的侧边栏和工作面板此前已使用进入/退出关键帧，但这些关键帧只改变了不透明度和一小段 transform。元素一经挂载，其 flex 分配就立即变为最终宽度，因此 MainChat 在第一个可见帧出现之前就已经移动，并在退出动画之后才移回。这让面板和侧边栏操作感觉像是一次跳变，随后才伴随一次表面上的淡入淡出。

代理流也存在类似的时序问题。每次 `message_update` 和 `tool_update` 都会立即替换渲染器消息数组，同时 transcript 会重建其分组条目投影并执行跟随滚动工作。因此，一个高速的供应商可能在同一帧内把多次更新花在历史 transcript 上，而无法流畅地呈现最新的尾部内容。

停靠式输入框还会在下方 transcript 之上绘制一层全宽的渐变遮罩。输入框已经预留了自身测量得到的高度，并拥有不透明的抬升表面，因此这层遮罩只是增加了视觉噪声，而并未承载任何状态。

## 决策

1. 侧边栏和工作面板的挂载/退出动画在固定范围的不透明度/transform 反馈之外，还会将 `width` 和 `flex-basis` 从零动画到已提交的停靠宽度。面板仍保持为文档流内的固定宽度列，操作系统窗口预留契约不变。
2. 渲染器按流目标将高频 `message_update` 和 `tool_update` 事件合并到下一个动画帧。每个目标只应用最新的一个事件。任何非流的控制事件或终止事件都会先刷新待处理批次，因此生命周期顺序和最终状态保持同步。
3. `ChatTranscript` 对繁重的分组条目投影和小地图输入使用 React 的延迟值。即时控件、权限状态、运行状态和终止结果保持同步。
4. 停靠式输入框使用透明外层停靠容器，底部空间由 transcript 预留；输入框外壳仍是唯一的抬升表面。
5. 活动分组只有在其活动运行结束之后才会获得终止失败样式。中间的错误行仍然可见，但供应商/工具重试不会让整个仍在运行的分组看起来已经结束。

## 后果

- 打开和关闭辅助列现在会在固定范围的动画时长内持续对 MainChat 重新布局，而不是在动画开始前就发生跳变。
- 当事件到达速度快于显示刷新速度时，流可能会晚一次绘制才显示最新的部分内容，但冗余的中间载荷会被丢弃，终止事件绝不会被延迟。
- 长 transcript 仍然需要未来真正的虚拟化处理；本决策降低了更新压力，但不改变消息持久化或分组方式。
- 移除停靠遮罩使 transcript 表面在视觉上更安静，并使输入框的区隔感依赖于其测量布局与抬升层级。

## 备选方案

### 仅使用 transform 的停靠动画

否决，因为它会让 flex 分配在第一个绘制帧之前就停留在最终值，而这正是可见布局跳变的根源。

### 将工作面板叠加在 MainChat 之上

本次变更中否决，因为当前冻结的 shell 契约是固定已提交宽度的停靠第三列。将其叠加会遮挡 transcript 内容，并需要更广泛的自适应与可访问性决策。

### 对所有代理事件防抖

否决，因为生命周期、权限、规划和终止事件需要立即排序。只有可替换的部分流更新才会被合并。
