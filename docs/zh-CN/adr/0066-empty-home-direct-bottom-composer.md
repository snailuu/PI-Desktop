# ADR 0066：空主页直接底部输入框

> **翻译说明：** 本页是与 [英文源决策](/adr/0066-empty-home-direct-bottom-composer) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受，待实现
- 日期：2026-08-07
- 决策者：PI-Desktop core
- 修订：D111
- 被修订：ADR 0067（仅涉及起始网格的呈现；已被 D206 取代）

## 上下文

空聊天主页曾把上下文提示按钮放在 hero 与输入框之间。这些控件在首个任务之前增加了一层额外决策，并使输入框成为可滚动内容堆叠的一部分。因此，可选的引导内容可能把主要的任务入口界面从聊天区域底部推开。

## 决策

1. 移除原有的空主页上下文快捷操作行及其打开项目按钮。当前界面也不包含 ADR 0067（D206）引入的独立开发者起始网格。
2. 将 hero 和可选的引导清单保留在 `.home-scroll` 内，这是空主页内容唯一的垂直溢出区域。
3. 将主页输入框渲染在滚动区之后的同级 `.home-composer-wrap` 中。该包裹层以现有内容宽度和底部间距，通过 flex 固定在 `home-main-content` 底部，因此在内容区域独立滚动时输入框仍保持可见。
4. 保留清单现有的内联操作与关闭行为。窗口高度不足时清单可以滚动，但输入框不得遮挡它。

## 后果

- 空主页只有一条直接的任务入口路径，其上方是更简约、专门构建的引导界面。
- 无论处于空主页还是对话记录状态，输入框都稳定停留在底部。
- 可选的引导内容仍可访问，无需遮罩层或第二个滚动区域。
- 原有的提示模板行、快捷操作样式和开发者起始卡片不属于渲染器界面的一部分。

## 考虑过的备选方案

### 保留快捷操作行，仅移动输入框

已否决。所要求的界面是直接任务入口；保留这些按钮会保留额外的决策层及其未被使用的提示预填充路径。

### 将输入框保留在滚动区内，并用 `margin-top: auto` 对齐

已否决。可选清单的增长仍会推动输入框，而窗口高度不足时的溢出会使主要输入框的位置更难以预测。

### 将主页输入框绝对定位在滚动区之上

已否决。除非每个内容块都为输入框不断变化的多行高度预留空间并跟踪该高度，否则底部覆盖层可能遮挡清单行。
