## 上下文

D128 将工作面板改为仅展示工件，并明确移除了全局快捷键。这让启动过程保持安静，但也导致用户在折叠面板或关闭其最后一个资源后，没有任何直接方式返回会话保留的面板。现有的面板头部已经提供了资源选择器，因此缺失的能力是面板入口，而不是新的资源协议。

## 决策

1. 添加快捷键 `openWorkPanel`，默认绑定为 `Cmd/Ctrl + J`。现有的快捷键设置界面可以使用与其他快捷键相同的冲突和保留键校验来覆盖和重置它。
2. 当存在活动会话时，该快捷键将该会话保留的面板上下文设置为以已提交宽度打开，而不创建或激活资源标签页。现有标签页、活动资源和 Browser 资源保持不变。
3. 空面板头部仍然是 Browser 和范围内插件视图的手动资源选择器。工件触发器继续原子地创建并激活资源，后台会话的工件无法打开可见面板。
4. 当设置处于活动状态时忽略该快捷键，没有活动会话时不做任何操作。不添加宿主协议、IPC 通道或原生应用菜单命令。

## 后果

- 用户无需等待另一个工件即可重新打开工作面板。
- 打开面板不再意味着存在资源；空头部是有意的选择器状态。
- 该变更仍限于渲染器本地，并保留会话范围的归属、宽度预留和启动重置行为。
- macOS 应用菜单保持不变；该快捷键可在设置 → 快捷键中发现和编辑。

## 考虑过的替代方案

### 保持仅工件入口

已否决。折叠或关闭最后一个资源的面板即使会话上下文仍然有效，也无法直接重新打开。

### 将 `Cmd/Ctrl + J` 设为切换

*（由 ADR 0085 修订：该快捷键现在用于切换。）* 当时被否决。折叠已有专门的面板控件，且显式打开操作可避免在用户试图显示面板工具时意外隐藏面板。

### 在快捷键上创建 Review

已否决。快捷键应当显示工作界面，而不应凭空创建一个工作区变更资源或强加默认工具选择。
