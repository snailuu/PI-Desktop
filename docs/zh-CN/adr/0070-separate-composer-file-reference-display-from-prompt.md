# ADR 0070：将输入框文件引用显示与提示词序列化分离

> **翻译说明：** 本页是与 [英文源决策](/adr/0070-separate-composer-file-reference-display-from-prompt) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受，待实施
- 日期：2026-08-10
- 决策者：PI-Desktop 核心
- 相关：D124、D197、D209、ADR 0024、ADR 0059

## 背景

工作区自动补全和剪贴板粘贴都会生成规范文件路径，而代理必须以纯文本 `@` 引用的形式接收这些路径。在受控的输入框 textarea 中直接渲染这些路径，会暴露冗长的工作区路径，对于粘贴的文件，还会暴露以 UUID 为后端的绝对暂存路径。这些路径可能跨多行换行并挤占实际任务内容，但在派发时仍然是必需的。

原生 textarea 无法让某个子串的渲染方式与它的底层值不同。缩短后的 textarea 值也无法通过基名查找来还原：重复的叶子名是合法的，而且暂存文件需要其精确的绝对路径。

## 决策

1. 一次完成的文件选择以及每个已物化的剪贴板文件，都会成为渲染器拥有的临时输入框引用。可见的 textarea 只保留用户的普通文本。目录自动补全仍保持字面形式，以便能够继续补全更深的路径片段。
2. 每个引用存储其规范路径和一个紧凑的叶子标签。工作区引用保留完整的相对索引路径；粘贴引用保留以 UUID 为后端的绝对暂存路径，同时显示 `composer/pasteFiles` 返回的、经过清洗的原始叶子名。
3. 输入框将引用渲染为 textarea 上方的紧凑可移除 chip。chip 始终只显示其叶子标签；其规范路径仍可通过工具提示和可访问名称获取。重复的标签仍保持为各自独立、拥有不同规范路径的引用。
4. 在现有的提交派发器运行之前，渲染器按稳定的添加顺序追加引用，并使用现有的 `formatFileInsert` 引号规则对每个引用进行序列化。生成的提示词仍为纯文本，并包含 pi 和代理已经在消费的精确 `@relative/path` 或 `@absolute/path`。
5. 仅含引用的草稿可以发送。引用被追加在可见文本之后，因此斜杠模板以及 `/agent-mode`、`/plan-mode` 和 `/goal-mode` 在草稿开头仍可被识别。本地派发或提示词派发成功会清空当前编辑器，而被拒绝或失败的派发则保留它。被接受的提示词还会保留一份仅属于渲染器、以会话和回合为作用域的快照，记录其序列化前的文本和引用，直到该回合离开未应答的智能停止窗口。
6. 在助手文本、思考内容或工具行开始之前停止，会移除刚发送的用户行并恢复结构化快照。规范路径回到其叶子名 chip 之后，绝不会作为 textarea 文本出现。一旦回复开始，中止会保留部分对话记录，且不恢复任何草稿。该快照不会从持久化的消息内容重建，也不新增任何 IPC、主机 RPC 或存储字段。
7. 引用以持久化会话 id 为作用域，并在其工作区变更时清除。移除一个 chip 只会移除草稿中的该引用；暂存字节仍遵循现有的会话生命周期。
8. `ComposerPastedFile.name` 是经过清洗的原始叶子显示名。唯一的 UUID 存储名由 `path` 表示，不会重复写入显示标签。这是在现有 Electron 专属结构内部的一次增量语义澄清；不涉及主机协议或存储 schema 变更。

## 考虑过的替代方案

- **只将基名插入提示词：** 被否决，因为重复的名称和外部暂存文件将无法再被可靠解析。
- **在透明 textarea 上叠加缩短后的文本：** 被否决，因为显示文本与原生文本长度不一致，会破坏光标、选区、换行、输入法和可访问性行为。
- **用 `contenteditable` 替换 textarea：** 针对这一聚焦的改动被否决，因为这会重新打开完整的输入法、选区、撤销、粘贴和可访问性契约。
- **从未应答的用户消息中反向解析序列化后的 `@path` token：** 被否决，因为用户自行编写的引用与渲染器追加的引用无法区分，且持久化文本不再携带原始显示标签或重复引用的身份。
- **发送供应商专属的二进制附件：** 被否决，因为文件工具已经在消费物化后的路径，而且提示词契约保持为与供应商无关的纯文本。

## 影响

- 冗长路径和以 UUID 为后端的路径不再占用可见的提示词行。
- 规范引用在持久化消息和模型上下文中保持精确。
- 除 textarea 文本之外，渲染器还需持有临时引用状态。
- 剪贴板存储的隔离、限制、清理和安全边界与 ADR 0059 保持一致。
