# ADR 0071：采用受 Apple 启发的全局圆角层级

> **翻译说明：** 本页是与 [英文源决策](/adr/0071-apple-inspired-global-corner-hierarchy) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 日期：2026-08-11
- 决策者：PI-Desktop 核心
- 相关：D072、D210

## 上下文

PI-Desktop 强制使用统一的圆角 token 尺度，但该尺度保留了一组历史遗留的
5/6/7/8/10/12/14/16/18/22px 取值。紧凑端的单像素级差难以分辨，而且共享的按钮
基元使用了胶囊形，尽管其大多数 28–32px 的操作属于密集的桌面界面。

Apple 当前的设计指南将固定圆角矩形、胶囊形和同心形状区分开来。它继续为 Mini、
Small 和 Medium 的 macOS 控件使用圆角矩形，仅将胶囊形保留给强调场景与合适的
组件族，并根据容器圆角半径和内边距来定义子元素的同心圆角半径。应用这套几何
规则，比把同一个半径复制到每个组件上更重要。

渲染器固定使用 Electron 37 / Chromium 138。CSS `corner-shape` 及其 `squircle`
取值自 Chromium 139 起才提供，因此依赖它们会在打包后的应用中静默回退。

## 决策

1. 用 4/6/8/10/12/14/16/18/20/24px 取值替换固定圆角阶梯。为胶囊形保留
   `--radius-full`，为圆形保留 `--radius-round`。
2. 标准紧凑型和中型控件使用固定圆角矩形。共享的按钮与字段基元使用
   `--radius-sm`（10px）。
3. 药丸标签、徽章、分段选择、开关、轨道、状态圆点以及等宽圆形图标控件保留其
   显式的胶囊形或圆形几何。
4. 表面随尺寸和层级提升而增大圆角半径。当子元素圆角靠近并平行于容器的圆角时，
   使用同心关系 `outer radius = inner radius + inset`。
5. 全宽的结构性外壳表面在窗口边缘保持直角。
6. 输入框将其既有的 20px 半径别名指向 `--radius-xl`，在保持可见输入框几何不变
   的同时将其纳入全局阶梯。
7. D072 的仅限 token 的 lint 约束保持不变；仅修订冻结的像素取值与共享基元的
   赋值。

## 后果

- 界面拥有更易辨识的由小到大的圆角层级，同时紧凑型 macOS 控件不再看起来千篇
  一律地呈胶囊状。
- 现有的 token 使用方会全局获得修订后的取值，无需组件本地的字面量。
- 设计师和实现者必须有意识地选择药丸形或圆形 token，而不是把它们当作默认
  半径。
- 在打包后的 Chromium 运行时支持 `corner-shape` 之前，真正的连续圆角渲染仍不
  可用；兼容的回退方案是标准化的固定圆角阶梯。

## 备选方案

### 将所有组件都做成胶囊形

已否决，因为 Apple 仍为紧凑型 macOS 控件保留圆角矩形，并有选择地将胶囊形用于
强调场景和特定控件族。

### 现在就加入 `corner-shape: squircle`

已否决，因为打包后的 Chromium 138 运行时并不支持它。只在较新的开发浏览器中生效
的声明，会导致视觉验证与发布行为出现偏差。

### 保留历史取值，只修改个别组件

已否决，因为该诉求是全局性的，而保留间距极近的 5/6/7/8px 级差会继续让层级难以
感知和维护。

## 补充说明（2026-08-14）：`corner-shape` 阻塞已消除

上述上下文与备选方案按原记录保留。其运行时前提已不再成立：外壳已迁移到
Electron 43，其中捆绑 Chromium 150，并且在打包后的渲染器中
`CSS.supports("corner-shape", "squircle")` 返回 `true`。后果中的推迟处理与“现在就
加入 `corner-shape: squircle`”的否决，都仅与可用性有关，因此重新审视它们已无任何
障碍。

本补充说明不改变决策。固定圆角阶梯仍按规格保留；采用连续圆角是一项设计变更，
需要其自身的决策，而不是依赖升级的副作用。
