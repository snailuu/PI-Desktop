## 上下文

已安装的插件面板可以从插件目的地访问，但打开其中一个会打断用户当前的工作，并且需要指针导航。系统级快捷键需要一个专用的原生窗口：当 PI-Desktop 未获得焦点时，常规渲染器无法接收按键，而现有的插件面板宿主应当继续作为打开插件 UI 的唯一权威。

中文插件名称也需要可用的键盘搜索能力，而不必要求作者为每个 manifest 添加别名。

## 决策

1. 添加共享的、可自定义的 `openPluginLauncher` 快捷键，默认值为
   `Alt+Space`。Electron 在 macOS 上将其渲染为 Option+Space，在
   Windows/Linux 上渲染为 Alt+Space，并在应用启动后通过 `globalShortcut` 注册。
   Windows 将 Alt+Space 保留给活动窗口的系统菜单，因此主机核心还会为该确切的默认绑定
   安装一个范围极窄的低级键盘钩子。该钩子消费该组合键，并向
   Electron 发出宿主通知，使启动器在另一个应用获得焦点时也能工作。获得焦点的主窗口
   仍作为最后的兜底手段。
2. Electron 主进程在距离指针最近的显示器上拥有一个居中的、无边框的 620×440 工具窗口。
   ADR 0080 以启动后隐藏预热取代了其最初首次使用时惰性创建的做法。该窗口不可调整大小、
   不出现在任务栏中、可见时始终置顶，并在失焦或按下 Escape 时隐藏。macOS 使用
   一个跨工作区可见的面板窗口；所有平台都不提供原生窗口控件。
3. 沙箱化的启动器渲染器使用现有的 preload 以及新增的仅限 Electron 的 toggle、
   dismiss 和 shown 通道。它通过现有的插件 API 列出插件，并通过现有的沙箱化
   面板宿主打开结果；插件权限或主机核心边界均无变更。
4. 只有已启用、处于就绪状态且带有面板的插件才作为候选。搜索会规范化名称、id 和
   描述，并从显示名称中推导出无声调全拼和拼音首字母。Up/Down 用于选择，Enter 或点击用于
   打开，Escape 用于关闭，IME 组词期间绝不派发。成功的打开记录会保存在渲染器本地的
   设备存储中（D219）：查询为空时按最近使用顺序列出插件，而输入查询时
   优先按相关度排序，仅将最近使用作为平局裁决依据。

## 影响

- 无需离开当前任务即可打开插件面板。
- 该快捷键在设置 → 快捷键中始终可见且可重置。
- `pinyin-pro` 被打包进渲染器产物中，而不是作为运行时包树分发。
- 自定义快捷键继续使用 Electron 的全局快捷键 API。主机核心钩子仅针对 Windows 保留的
  默认组合键启用，钩子安装失败会被记录日志；在这种情况下，聚焦窗口的兜底方案
  仍然可用。
- 渲染器 IPC 的新增内容仍局限于 Electron 且为增量式；原生兜底方案新增了一个
  宿主方法/通知，但未更改协议 v9 或存储 schema v11。

## 考虑过的替代方案

### 复用全局搜索

已否决。全局搜索是主渲染器的一部分，在不先恢复整个主窗口的情况下，无法在
应用未获得焦点时出现。

### 直接从原生菜单打开插件

已否决。静态菜单无法提供中文/拼音模糊搜索，并且每次插件生命周期变化
都需要重建。

### 在插件 manifest 中放置拼音别名

已否决。这会使搜索质量取决于每个插件作者，并重复了本可在查询时
一致推导出的数据。
