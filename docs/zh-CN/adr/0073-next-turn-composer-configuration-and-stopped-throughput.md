# ADR 0073：暂存下一回合的输入框配置并保留已停止的输出吞吐量

## 上下文

输入框此前在整个代理运行期间将其草稿、模式、思考与权限控件设为只读。这阻止了用户在运行期间准备下一条提示和下一回合配置，而这样做本是为了保留一条正确的安全规则：主机核心不得修改进行中的回合所固定的配置。

用户发起的 Stop 也可能在供应商的最终 usage 记录到达之前到达。部分助手回答被保留下来，但其流式时长和输出计数未出现在持久化转录元数据中，因此对话统计无法显示生成吞吐量。

## 决策

1. 在回合进行期间，输入框草稿以及模式、思考、权限选择器保持可编辑。仅 Send 保持禁用，Stop 操作仍然可用。待处理的 Plan/Goal 审批会继续阻止草稿与配置控件，因为它掌握着会话的决策边界。
2. 渲染器为每个运行中的会话保存最新的完整会话配置，并以乐观方式投影。在 `agent_end`、`error` 或手动压缩完成时，它通过现有的仅限空闲状态的 `session/configure` API 提交该配置。新的选择会替换较早的排队选择；它们绝不修改正在运行的运行时。
3. 运行时终止消息保留 `responseDurationMs`。如果被中止的响应没有供应商报告的正面输出 usage，运行时与渲染器的对账按每 token 四个 Unicode 码点估算可见的思考文本加回答文本，并附带可选的 `responseOutputTokens`。
4. Rust 转录转换会将这两个可选字段持久化到消息元数据中。供应商提供的精确 usage 优先于估算值；在对话元数据中，估算值会被如此标注。缺少任一字段的旧记录仍然有效。

## 后果

- 用户无需等待当前回答即可准备下一个请求并调整其运行配置，但无法发送并发的提示。
- 主机的仅限空闲状态准入、每会话单回合、Plan/Goal 审批以及权限强制执行保持不变。
- 已停止的部分回答会显示稳定的近似每秒 token 值，并在重新加载后保留；完整回答则继续使用供应商提供的精确 usage。
- `responseOutputTokens` 是一个附加的共享字段，存储在现有的消息元数据中，因此协议 v9 与存储 schema v11 均无需变更。

## 考虑过的替代方案

### 在运行期间立即配置主机

已拒绝。这要么违反仅限空闲状态的准入，要么可能改变已为活动回合固定的权限/工具/模型配置。

### 保持控件禁用，但仅允许输入草稿

已拒绝。模式、思考和权限都是准备下一条提示的一部分；只让文本可编辑会使工作流不必要地被串行化。

### 在缺少最终 usage 时隐藏吞吐量

已拒绝。可见的部分输出和已测量的流式时间区间提供了有用的估算值，并且 UI 可以将其与供应商报告的 usage 区分开来。
