# ADR 0075：开发插件权限上限的手动重载

> **翻译说明：** 本页是与 [英文源决策](/adr/0075-manual-development-plugin-reload) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-12

## 上下文

开发插件会被监视，并从其本地文件夹热重载。监视器会有意拒绝加载那些新增权限超出文件夹加载时已批准上限的 manifest。在此操作存在之前，开发者必须通过选择器重新加载该文件夹，以审阅变更后的 manifest 并继续开发。

## 决策

新增一个从渲染器到主进程的 `pi-desktop/plugin/reload` invoke 通道。Electron 主进程通过主机注册表解析插件 id，使用注册表当前的权限加载已注册的路径，并在加载成功后重新启用开发监视器。Plugins 页面仅对 `source: "dev"` 的行暴露该操作，并在 invoke 完成后刷新其列表。

自动监视器仍保持保守：它不能扩大权限上限。手动重载是显式的开发者操作，它确认当前 manifest，并使其声明的权限成为之后自动重载的新上限。

## 后果

- 开发者可以从受权限限制的热重载中恢复，而无需重新选择文件夹。
- 已安装插件和插件市场插件不会获得手动重载控件。
- 现有的监视器、插件运行时和主机核心存储契约保持不变；新通道是附加性的 Electron IPC 接口。

## 考虑过的替代方案

- 复用文件夹选择器：已拒绝，因为它会重复路径选择，并使恢复过程产生不必要的干扰。
- 允许自动重载扩大权限：已拒绝，因为文件编辑不得静默授予新能力。
