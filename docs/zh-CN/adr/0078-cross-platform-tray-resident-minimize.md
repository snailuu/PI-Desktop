# ADR 0078：跨平台托盘常驻最小化

> **翻译说明：** 本页是与 [英文源决策](/adr/0078-cross-platform-tray-resident-minimize) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：接受实施（由 ADR 0117 和 ADR 0123 修订）
- 日期：2026-08-12
- 决策者：PI-Desktop 核心
- 相关：D216、D252、D256、E2E-124、ADR 0117、ADR 0123

## 上下文

PI-Desktop 在 Windows/Linux 上已有自定义窗口控件，在 macOS 上使用原生
交通灯控件。这些控件的最小化操作当前使用原生窗口最小化，这使应用消失在不
同的操作系统窗口界面中，并且没有提供一致的方式来保持后台工作常驻。Electron
主进程已经负责窗口生命周期和关闭流程，因此托盘集成应属于主进程，而不是
渲染器桥接层。

## 决策

1. Electron 主进程在每个受支持的桌面平台上创建一个托盘图标。
   打包构建将现有产品 PNG 作为额外资源携带，用于 Windows/Linux。macOS
   携带一个单独的透明单色模板资源，该资源派生自 PI 标志；浅色应用图标不
   属于菜单栏剪影的一部分。
2. 主进程拦截主窗口的 `minimize` 事件，并且仅针对 macOS 交通灯最小化将其
   隐藏到托盘。在 Windows/Linux 上，原生最小化转换——包括渲染器和原生菜单
   操作——作为普通的操作系统最小化完成，因此任务栏条目仍然可用。
   隐藏不会关闭窗口，也不会释放任一后端。
3. 托盘单击和双击、Show 菜单项以及 macOS 应用激活会恢复并聚焦现有窗口。
   如果窗口已关闭，它们会通过现有窗口工厂创建一个新窗口。
4. 托盘菜单包含本地化的 Show PI-Desktop 和 Quit PI-Desktop 项。
   Quit 调用 `app.quit()`，因此遵循现有的 `before-quit` 关闭流程。
   关闭主窗口仍然是显式的退出操作。

## 后果

- macOS 保留其托盘常驻最小化行为，而 Windows/Linux 对显式最小化操作使用
  正常的任务栏最小化/恢复功能。关闭到托盘仍然可通过用户可配置的关闭行为
  使用。
- 渲染器不需要新的特权 IPC 接口。
- 托盘图标是必需的打包资源；图标缺失会被记录日志，应用保持可用而不是在
  启动期间崩溃。
- 窗口边界持久化保持不变，因为隐藏的窗口保留其正常边界，不会被视作新的
  窗口状态。
