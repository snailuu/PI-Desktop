# ADR 0079：使用 VitePress 构建双语文档站点

> **翻译说明：** 本页是与 [英文源决策](/adr/0079-vitepress-documentation-site) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- **状态：** 已接受（镜像范围由 ADR 0188 扩展）
- **日期：** 2026-08-13

## 上下文

仓库中积累了越来越多的规格、ADR、项目笔记和插件编写材料。纯 Markdown 文件易于评审，但当前目录没有共享导航、本地搜索、响应式阅读体验或清晰的语言入口。

## 决策

将 `docs/` 作为 pnpm 工作区中的一个独立 VitePress 项目。保留现有的 Markdown 文件作为唯一事实来源，并新增一个自定义响应式主题，具备本地搜索、英文和简体中文语言环境入口以及精选导航。

英文站点是完整的，并且保持为权威版本。中文站点提供翻译后的导读、主题地图，以及每个规格逐路径对应的完整配套内容。翻译页面保留代码和协议标识符，带有指向对应英文来源的可见链接，并使用相同的生成式侧边栏结构，以便覆盖率缺口可被检测到。

共享主题在落地页、指南、规格、ADR、项目和插件页面上使用统一的居中布局系统。阅读宽度独立于侧边栏和大纲轨道进行限制；表格和代码块在该宽度内滚动。首页在移动端保持文本先于系统视觉图，并支持浅色和深色外观且无水平溢出。

## 后果

- 贡献者可以使用 `pnpm docs:*` 命令运行、构建和预览文档。
- 文档拥有稳定的静态站点形态，且无需增加服务器运行时。
- 新的用户可见文档行为必须在 E2E 测试计划中覆盖。
- 英文仍然是规格、ADR、协议术语和面向代码的文档的权威语言。
- 改变行为的英文规格修改必须在同一逻辑变更中更新其中文配套内容。
- VitePress 成为开发依赖，docs 包加入现有的 pnpm 工作区。

## 考虑过的替代方案

- 仅保留纯 Markdown：保持了最小的工具链，但无法解决导航、搜索、响应式呈现或双语入口问题。
- 只翻译导读和主题落地页：降低了维护成本，但让中文导航恰好在读者接触技术细节时切回英文，并且使语言环境覆盖率无法验证。
- 使用托管文档平台：增加了外部发布依赖，并使本地预览与仓库源文件之间的代表性降低。
