# ADR 0081：主机核心所有的跨平台插件面板外壳

> **翻译说明：** 本页是与 [英文源决策](/adr/0081-host-owned-plugin-panel-chrome) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-13
- 决策者：PI-Desktop 核心
- 相关：D118、D129、D218、ADR 0021、ADR 0025

## 上下文

插件面板运行在独立的沙箱化 `BrowserWindow` 实例中，并加载插件自有的 HTML。
这些窗口此前使用 Electron 的默认边框，因此其标题栏与 PI-Desktop 主窗口不匹配，
并且在 macOS、Windows 和 Linux 之间存在显著差异。

面板页面不可被授予主渲染器 preload 或任意的窗口控制桥接。主机核心外壳同样
不能依赖插件 CSS，而现有插件布局需要从新的标题栏下方开始，同时不丢失其原始
的顶部内边距。

## 决策

1. 插件面板采用与主窗口相同的平台区分策略：macOS 使用 `hiddenInset`，交通灯
   按钮位于 `{x:16,y:16}`，而 Windows 和 Linux 使用无边框窗口，由渲染器绘制
   控件。
2. 现有沙箱化的插件面板 preload 在封闭的 Shadow DOM 中安装主机核心所有的
   46px 标题栏。它渲染 manifest 中的面板标题，并在插件主体计算出的顶部内边距
   之外额外将其偏移 46px。它还发布 `--pi-plugin-titlebar-height: 46px`，供必须
   位于主机核心外壳下方的固定/粘性插件 UI 使用。
3. Windows/Linux 通过一个 Electron 本地固定的 action 元组暴露最小化、最大化/
   还原和关闭。仅当发送方属于一个存活的插件面板时，Electron 主进程才接受该
   action，并且仅向该面板发布最大化状态。
4. 公开的 `window.pluginBridge` 接口不增加窗口原语。现有的按插件会话分区、
   沙箱、上下文隔离和经过权限检查的面板桥接保持不变。
5. 控件带有本地化的无障碍名称、可见的键盘焦点、主题感知的浅色/深色表面，
   以及减少动效行为。重新打开已最小化的面板会还原并聚焦现有窗口。
6. 开发面板会收到一条仅面向主机核心的标题栏提醒，用于说明 46px 安全区域。
   已安装的面板不会显示此作者提示。

## 后果

- 插件面板在三个发布平台上都能与主应用外壳在视觉上对齐，且不会向插件授予
  更宽泛的 Electron 访问权限。
- 插件 CSS 无法为封闭的标题栏树设置样式，但插件仍可以替换自己的文档，从而
  移除 preload 注入的视觉元素。这不会授予任何能力，也不会跨越面板沙箱。
- 主机核心在插件内容上方保留 46px。故意将视口固定内容固定在 `top: 0` 的面板
  必须考虑标题栏，使用注入的 `--pi-plugin-titlebar-height` 变量。
- 私有窗口控制通道仍位于主机核心协议 v9 之外。

## 备选方案

### 保留 Electron 的默认面板边框

已拒绝，因为它保留了不一致的产品外壳，并使 Windows/Linux 面板在视觉上与主
应用脱节。

### 向插件 JavaScript 暴露主窗口控制 API

已拒绝，因为插件桥接应仅限于已声明的插件能力，且不得获得通用的原生窗口
权限。

### 将插件内容托管在主渲染器 DOM 中

已拒绝，因为为了一个纯视觉变更而削弱现有的独立窗口、独立分区隔离模型。
