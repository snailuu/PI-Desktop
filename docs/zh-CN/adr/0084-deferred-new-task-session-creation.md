# ADR 0084：将新任务创建会话推迟到第一条消息

> **翻译说明：** 本页是与 [英文源决策](/adr/0084-deferred-new-task-session-creation) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- **状态：** 已接受
- **日期：** 2026-08-14
- **相关：** D220 · D088 · D093 · E2E-011b · E2E-011d

## 上下文

点击 New Task 会立即创建一个会话，因此即使用户从未输入任何消息，侧边栏历史中也会增加一行默认标题为 `新建任务` / "New task" 的记录。复用规则（D088/D093）会在每个项目或临时作用域中最多保留一个空草稿，但第一行空记录仍然会出现，并一直可见，直到用户发送提示词使其重命名。空草稿会话还会在主机数据库的磁盘上留下记录行。

## 决策

New Task 会打开一个未持久化的草稿，而不是创建会话：

- `newSession()` 将渲染器重置为首页空状态（保留请求的项目作用域），不再调用 `session.create`，也不再复用遗留的空草稿。`activeSessionId` 保持未设置，渲染器已将其作为初始状态和项目切换状态来支持。
- 第一条消息（`sendPrompt`）或粘贴的文件（必须附加到会话）会通过共享的 `materializeDraftSession` 辅助函数将草稿实体化，该函数会创建会话、应用任何保留的工具栏配置，并提交与急切路径相同的导航/运行状态。
- 在草稿上做出的输入框和顶部栏模型工具栏选择会保留在新的 `draftConfiguration` store 切片中，并在实体化时应用，而不是在仅工具栏交互时就实体化一个会话。
- 侧边栏历史过滤器现在会丢弃标题仍为默认未命名值的会话，以隐藏遗留的空草稿和任何意外为空的会话，作为纵深防御。

## 后果

- 侧边栏历史只记录实际携带输入的任务；被放弃的 New Task 草稿不会留下记录行，也不会留下已持久化的会话。
- 主机数据库中不再累积新的空会话；遗留的空草稿仍保留在磁盘上，但从历史中隐藏。
- 渲染器 store、Composer 和 Sidebar 有所变更；协议 v9、主机 RPC 和存储 schema v11 未受影响，因此较旧的渲染器仍然兼容。

## 考虑过的替代方案

- 保留急切创建，仅在侧边栏中隐藏空草稿：改动更小，但会在磁盘上留下不可见的会话，并让复用机制继续为用户本不应看到的记录行而存在。
- 在草稿第一次按键输入时创建会话：仍然会为从未发送的消息创建记录行，而这正是该需求要求避免的情况。
