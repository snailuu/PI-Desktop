## 背景

`Edit` 目前接收 `old_string` / `new_string`，并要求 `old_string` 在文件中恰好匹配一个位置
（`crates/host-core/src/tools/mod.rs:1278`）。`Read` 刻意返回不带行号的字节，以便从其 `content`
中复制出的文本仍能匹配（`crates/host-core/src/tools/mod.rs:1225`）。该契约导致三种失败模式，且三者都无法在该契约内部修复：

1. **模型必须重新输入现有代码。** 每次编辑的正确性都取决于能否复现它此前看到过的字节。一个空格出错就会令调用失败；观察到的后果是重新读取加上重新生成编辑，而 §4d 已将此固化为预期恢复路径，并限制为两次尝试。
2. **歧义要由模型来解决。** 重复片段迫使模型不断扩大 `old_string` 直到其唯一，这增加了重新输入的篇幅，因而也提高了输错的概率。
3. **没有任何机制证明模型读取过它正在编辑的内容。** 只要记忆中的片段唯一匹配就会成功，即使模型在本会话中从未显示过该区域，甚至即使在该编辑所依据的那次读取之后文件已经改变。这正是那类会静默产生看似合理但实为错误编辑的失败，而当前契约完全无法检测它。

`Grep` 已经返回 `{path, line, text}`；行号在搜索路径上存在，但编辑路径无法消费它们。

`oh-my-pi` 的 `hashline` 包正是通过反转模型所提供的内容来解决这一问题：模型报告**位置**（行号与间隙）加上**仅新增内容**，而工具提供版本与来源的证明。锚点是整个规范化文件的 4 位十六进制指纹，携带在节标题（`[path#TAG]`）中，由展示该内容的任一工具生成。

## 决策

### 1. `Edit` 变为行锚定的补丁工具

`Edit` 接收 `path`、`tag` 和 `ops`。`old_string` / `new_string` 被移除；没有兼容垫片，没有按模型选择变体的机制，也没有第二个写入工具。单一的高风险写入契约使权限矩阵、审查快照、工件记录、审计面和按会话的变更串行化都保持单一取值。

操作面即完整的 `hashline` 操作面：范围替换（`PUT N.=M:`）、间隙插入（`PUT <N:` / `PUT >N:` / `PUT >$:`）、语法块替换与同级插入（`PUT N*:` / `PUT >N*:`）、捕获并删除（`CUT N.=M` / `CUT N*`）、寄存器粘贴（`PUT <N @name` / `PUT N.=M @name`），以及文件级的 `REM` / `MV DEST`。正文行是带 `+` 前缀的最终内容；不存在 `-old` 行和裸上下文行，因为范围本身已经表达了删除。

### 2. Read 与 Grep 生成标签；Read 输出行号

`Read` 为每一返回行加上 `N:` 前缀，并在开头加上 `[path#TAG]` 头。这推翻了 ADR 0069 中保持字节忠实的 `content` 决策，该决策的唯一目的是让复制的文本仍可被 `old_string` 匹配。`Grep` 对每个匹配文件获得相同的头。`Write` 返回写入后的头，因此紧随其后的 `Edit` 无需额外的 `Read`。

### 3. 主机核心持有按会话限定的快照存储

一个有界的内存存储将 `(session, canonical path)` 映射到全文件版本的简短历史，每个版本携带其标签以及生产者实际**显示**过的行号集合。这使得当前契约无法表达的两项保证变得可强制执行：

- **版本。** 若 `Edit` 的 `tag` 与实时文件的哈希不符，则不会仅凭模型的说法就应用该编辑。
- **来源。** 锚定在会话从未显示过的行上的 `Edit` 会被拒绝，并在错误中内联该行的真实内容，以便直接重试即可成功而无需再次 `Read`。

该存储驻留内存、按会话划分、有界，并随会话一并丢弃。它不同于 ADR 0043 的审查快照——后者位于磁盘、按工具调用划分，且用于回滚；两者仅共享 `crates/host-core/src/review.rs` 中已有的哈希原语。

因此 `execute_tool_with_path_access` 增加一个会话身份参数。目前只有 `BashExecutionOptions` 携带 `session_id`，所以 Read/Edit/Grep 无法触及按会话的状态；这正是整个特性所依赖的唯一一处签名变更。

### 4. 为块解析向主机核心引入 Tree-sitter

`PUT N*:`、`PUT >N*:` 和 `CUT N*` 需要从第 `N` 行开始的语法结构的行跨度。主机核心引入 `tree-sitter` 以及一组有界的语法。解析是 (text, language, line) 的纯函数，对于不支持的编程语言、无效的行、没有开启符的行或无法解析的文件，返回 `None`；随后工具会拒绝该块操作，并给出指明普通范围替代方案的可操作消息。块操作会降级；但绝不猜测。

每个解析出的跨度都会在工具结果中回显，使模型能看到自己锚定了错误的开启符。

### 5. 寄存器按会话限定且具名；匿名寄存器为调用局部

跨文件移动使用具名寄存器（一次调用中 `CUT 1* @fn`，下一次调用中 `PUT <1 @fn`），这是 `hashline` 自身认可的跨调用机制。`Edit` 保持单路径：PI-Desktop 的权限门、审查快照、工件行和变更许可都以同一个 `args.path` 为键，而多节补丁会让这四者分叉。匿名寄存器仅存活于单次 `Edit` 调用内。

### 6. 失败是显式的，且恢复必须可证明

过期的标签会尝试快照恢复：通过从带标签的快照到实时文件之间未改变的行重映射每个锚点，验证周边上下文，并且所有锚点必须移动同一个一致的偏移量。任何发生变化、被拆分或有歧义的情况都会以闭锁方式失败，并返回携带当前内容的不匹配错误。仅头部/尾部的插入是位置稳定的，会带警告应用而不是失败。空操作的应用是错误。

## 后果

- 模型不再为编辑现有代码而重新输入代码。重新输入的篇幅缩小到它实际写入的行，这消除了 `Edit` 的主要失败原因，而不是为其规定恢复方式。
- 针对会话从未显示过的内容的编辑从不可检测变为不可能。§4d 的 “一次重读，然后停止” 循环守卫仍然保留，但触发它的情形缩小为真正的漂移。它也不再在三个可恢复错误码首次出现时就将其计入：每个错误码都会向重试交出它所需的信息，因此每条路径各获得一次宽限，而真正耗尽预算的失败会以一条可见的 `MUTATION_RETRY_BUDGET_EXHAUSTED` 行结束回合，而不是静默完成回合。
- `Read` 的输出因行号前缀的宽度而变长，其 `content` 也不再字节忠实。任何逐字复制 `content` 的消费方都必须剥离前缀；`Write` 在粘贴头时已经需要同样的剥离。
- 主机核心增加一项按会话的内存开销（受存储上限约束），并在二进制中加入 tree-sitter 及其语法。语法足迹是块操作的代价，并且由一个显式的语言列表加以限定，而不会采取 “不断添加语法直到每个文件都能工作” 的做法。
- 每个面向 PI-Desktop 的模型都必须学习一种新语法。没有回退契约，因此无法产出该语法的模型就无法编辑；这一点是被刻意接受的，以避免无限期地维护两套提示、两个校验器、两个渲染器和两种审计形态。
- 渲染器的 Edit diff 渲染（`apps/desktop/src/lib/tool-presentation.ts:501`）不能再从 `old_string`/`new_string` 推导出 diff，必须改为从审查记录的 hunk 渲染，而 ADR 0043 已经产出这些 hunk。

## 已拒绝的替代方案

- **在现有 `old_string` 契约上增加标签。** 修复了版本与来源问题，但仍让模型重新输入代码，而这是更大的代价。它以大致相同的管道工作换取了收益中较廉价的那一半。
- **用模式开关同时保留两种契约。** 需要永远维护两套提示、两个校验器、两个渲染器、两种审计形态以及一份按模型的排除清单，只为容忍无法遵循一种有文档的语法的模型。
- **新增第二个独立的行锚定写入工具。** 构建成本最低，但拥有成本最高：两个并发的高风险写入工具会使权限矩阵、审查快照边界、工件账本和变更许可发生分叉。
- **统一 diff / `apply_patch`。** 要求模型计算 hunk 头并重新输入上下文行——既有重新输入又有算术。`Bash` 指导正是出于这一原因而引导避开 `git apply` 和 `patch`。
- **在单次 `Edit` 调用中支持多节补丁。** 只有同调用跨文件移动才需要它，而按会话限定的具名寄存器已在两次调用之间覆盖了这一点；况且它会使以单个 `args.path` 为键的四个子系统发生分叉。
- **用花括号计数或缩进来做块解析，而不是 tree-sitter。** 在字符串、注释、宏、JSX 和 Markdown 上会静默出错。一个通常正确的块操作比一个会拒绝执行的块操作更糟。
