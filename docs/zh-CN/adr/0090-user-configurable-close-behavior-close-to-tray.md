# ADR 0090：用户可配置的关闭行为与关闭到托盘

> **翻译说明：** 本页是与 [英文源决策](/adr/0090-user-configurable-close-behavior-close-to-tray) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受，进入实现
- 日期：2026-08-12
- 决策者：PI-Desktop 核心
- 相关：D230、D256、ADR 0021、ADR 0025、ADR 0078、ADR 0123

## 背景

在 Windows/Linux 上，关闭主窗口会调用 `app.quit()`（`window-all-closed`），因此应用会退出，其任务栏条目也随之消失。最小化已经会把窗口隐藏到 D216（ADR 0078）在各平台上保持常驻的托盘中，但运行着长时间对话的用户期望关闭窗口也能让应用继续可用。不同用户想要不同的默认值，而固定的关闭到托盘行为会让期望关闭即退出的用户感到意外。

该应用目前没有任何关闭拦截，也没有面向用户的选项来处理这一生命周期决策。macOS 不在范围内：原生 Dock 生命周期（关闭后应用仍保留在 Dock 中，`activate` 重新创建窗口）已经符合期望行为。

## 决策

1. Windows/Linux 的关闭行为变为一项持久化的、用户可配置的偏好设置，共有三个取值，其中两个可被设置：
   - `ask`：瞬态的未设置状态——首次关闭时提示一次。做出选择后它会被永久记住，且无法回退到提示机制（`closeBehavior/set` 会拒绝 `ask`）。
   - `tray`：关闭窗口时将其隐藏到常驻的 D216 系统托盘图标下，并保持应用运行；托盘菜单可恢复窗口或退出应用。
   - `quit`：旧有行为——关闭窗口即退出应用。
2. 当偏好未设置时，首次关闭会显示一个原生模态对话框（主进程），其中包含 取消 / 关闭到托盘 / 退出。选择非取消的选项会将其永久持久化；取消则保持窗口打开并让偏好维持未设置状态（因此下次关闭时会再次提示）。
3. 该偏好由 Electron 主进程存储在 `<data>/close-behavior.json`（与 `window-state.json` 相同的归属模式），而**不是**存储在主机核心设置中：它属于应用外壳的生命周期状态，只由主进程读写，无需主机 RPC 或 schema 变更。
4. 两个增量 IPC 通道将其暴露给渲染器：`pi-desktop/window/closeBehavior/get`（返回 `{ behavior, supported }`）和 `pi-desktop/window/closeBehavior/set`，后者只接受 `tray` 与 `quit`（`ask` 及未知取值会以 `INVALID_ARGUMENT` 失败）。`supported` 在 macOS 上为 `false`，此时设置行会被隐藏，且 `set` 本身也会以 `INVALID_ARGUMENT` 失败——渲染器并非唯一调用方，因此守卫放在主进程中。
5. 设置（通用标签页）仅针对 Windows/Linux 渲染一个二选一的单选段——关闭到托盘 / 退出应用；偏好未设置时不显示任何选中项。更改后立即生效。托盘图标不做协调：它由 D216 拥有，且在两种选择下都保持常驻，因为无论关闭行为如何，最小化到托盘都需要它。
6. 关闭处理器会拦截每一个非 macOS 的、且尚未成为已批准退出的 `close`；`before-quit`（`quitting`）和 macOS 上的关闭始终直接放行，因此显式退出、托盘中的“退出”菜单项以及自动化启动探测都不受影响。在 `quit` 模式下，处理器会自行调用 `app.quit()`，而不是依赖 `window-all-closed`；而 `window-all-closed` 以该偏好为依据——它只在 `tray` 模式下保持静默，从而在窗口被托盘隐藏或意外销毁时让应用继续存活；其他情况下则退出，即便 D216 的托盘图标依然存在。若 `tray` 模式的关闭发生时托盘图标不存在，则回退为真正的退出，而不是在没有返回途径的情况下把窗口隐藏起来。
7. 边界看门狗（`ensureStableBounds`）会跳过最小化和已隐藏的窗口，因此最小化始终保持最小化，被托盘隐藏的窗口也绝不会被 Stage-Manager 的搁板恢复机制强行还原。
8. 已知限制：在 Windows 系统关机/注销时，操作系统可能送达一个 `close`，而当偏好为 `ask` 或 `tray` 时该事件会被拦截。Windows 会在自身的关机超时后强制终止会话，因此不会丢失数据，但关机过程不会因该应用而加速。

## 考虑的备选方案

- **将偏好存储在主机核心设置（`AppSettings`）中：** 否决，因为这会为纯外壳生命周期状态新增一个 Rust schema 字段和主机 RPC 接口，而该状态只由 Electron 主进程消费。
- **由渲染器绘制首次关闭对话框：** 否决，因为此时窗口正在关闭；原生模态对话框把决策留在拥有关闭生命周期的进程中，并且在渲染器挂载之前就能工作。
- **始终关闭到托盘，不提供选择：** 否决——对于期望退出的用户而言，这会改变关闭按钮的含义。
- **让托盘图标与偏好保持协调：** 否决；D216 在每个平台上都保留一个常驻托盘图标以支持最小化到托盘，因此在关闭行为为 `quit` 时销毁它会破坏一个不相关的功能。关闭行为决定的是关闭时做什么，而非托盘是否存在。

## 后果

- Windows/Linux 的显式最小化使用常规的任务栏过渡；关闭选择为 `tray` 时仍会把窗口隐藏到常驻的 D216 托盘图标下。macOS 的原生最小化在 D216 下仍保持托盘常驻。
- Windows/Linux 上的关闭要么隐藏到托盘、要么退出，取决于用户选择，跨启动保留，并可在设置中修改。
- 托盘菜单和首次关闭对话框复用现有的 `@pi-desktop/i18n` 目录（英语和简体中文）。
- 主机协议、存储 schema 以及 macOS 行为均无变更。
