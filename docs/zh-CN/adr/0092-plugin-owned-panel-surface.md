# ADR 0092：使用插件自有表面与宿主窗口控制胶囊

## 上下文

第一次插件面板 chrome 修订让宿主渲染了一个完整的 46px 标题栏。它仍然按平台拆分行为：macOS 保留原生交通灯按钮，而 Windows 和 Linux 则获得一条扁平的 112px 控制带。宿主还渲染了 manifest 标题和一个仅用于开发的 safe-area 提醒。

这种 chrome 占用了插件面板的视觉顶层层级。插件作者无法构建自己的工具栏，否则就会与宿主标题竞争，而平台拆分也让同一个插件在每个桌面平台上感觉不同。

## 决策

1. 插件面板在 macOS、Windows 和 Linux 上使用无边框的 `BrowserWindow` 实例。原生交通灯按钮和原生面板菜单不属于面板窗口表面。
2. 沙箱化 preload 预留一个透明的 46px 安全区域，并在右上方渲染一个固定胶囊。该胶囊恰好包含三个按钮：最小化、最大化/还原和关闭。宿主不渲染面板标题，也不渲染开发提醒。
3. 插件拥有其标题、工具栏、背景、内容以及其他所有可见面板 UI。正常流内容会自动偏移；固定或粘性插件 UI 使用 `--pi-plugin-titlebar-height: 46px`。插件自有的工具栏可以选择加入 `-webkit-app-region: drag`，而其中的交互子元素则通过 `no-drag` 退出。
4. 该胶囊仍保留在由 preload 拥有的封闭 Shadow DOM 中。其本地化无障碍标签、主题自适应颜色、键盘焦点、减弱动态效果行为，以及发送方验证的私有窗口控制通道保持不变。`window.pluginBridge` 不会获得窗口原语。

## 后果

- 面板在所有支持的平台上呈现相同的紧凑右上角控制语法，同时让每个插件完全拥有其可见头部。
- 46px 安全区域仍然是稳定的布局契约，因此现有的正常流面板不会移到控件后面，固定插件工具栏也有了文档化的锚点。
- manifest 标题仍可作为原生窗口身份和启动器元数据发挥用处，但它不再是宿主渲染的视觉元素。
- 开发面板不再需要仅由宿主提供的提醒；devkit 和插件文档必须教授安全区域变量和拖拽区域契约。

## 备选方案

### 保留原生 macOS 控件和宿主标题栏

拒绝，因为这保留了平台拆分，并将插件的主要视觉层级留给宿主 chrome。

### 将窗口控制暴露给插件 bridge

拒绝，因为插件 JavaScript 仍然不需要通用的原生窗口权限；preload 本地的、发送方验证的通道已经足够。

### 完全移除安全区域

拒绝，因为宿主控制覆盖层仍然需要稳定的点击和拖拽带，而现有的固定/粘性插件布局会与胶囊发生冲突。
