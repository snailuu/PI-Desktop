# ADR 0099：为设置目录添加带标题的视觉分组

> **翻译说明：** 本页是与 [英文源决策](/adr/0099-titled-settings-navigation-clusters) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- Status: Accepted
- Date: 2026-08-18
- Deciders: PI-Desktop core
- Related: D238, D241, ADR 0096

## 上下文

设置侧边栏被有意设计为扁平、可搜索的八个目的地目录。这些行是正确的，并且保持在同一导航层级中，但未加分隔的列表在视觉上过于密集。此前的纯视觉间距使用了分隔线，这在深色侧边栏背景下尤其容易丢失，也无法提供有用的浏览定位标记。

## 决策

保持目的地索引扁平，并保留其顺序、ID、搜索行为和归属关系。在现有的行分组上方渲染四个本地化、非交互式的标题：

- Personal / 个人：Basics, AI, Shortcuts
- Agent / 智能体：Instructions, Model configuration
- Workspace / 工作区：Import, Project archive
- About / 关于：Info

在分组之间使用柔和的排版与留白。不渲染分隔线，也不添加嵌套导航。搜索继续将目的地作为单一扁平索引进行过滤；当某个分组中不再有目的地时，该分组及其标题一并消失。

## 后果

- 侧边栏获得了清晰的浏览定位标记，而没有引入另一个交互式导航层级。
- 这些标题在两种受支持的 UI 语言中均可用。
- 侧边栏不再依赖边框对比度来在任一主题中传达分组关系。
- 现有的目的地排序和深链行为保持稳定。

## 备选方案

### 保持完全扁平的侧边栏

被否决，因为紧凑的行作为一个整体仍然难以浏览。

### 在分组之间使用分隔线

被否决，因为此前使用的线条在深色模式下显著性低，并且只增加了装饰性元素，却没有为分组命名。

### 添加交互式嵌套导航

被否决，因为设置的信息架构被有意设计为扁平的目的地索引，而这些分组并不拥有额外的导航状态。
