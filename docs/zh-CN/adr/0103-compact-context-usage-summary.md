# ADR 0103：紧凑的上下文用量摘要

> **翻译说明：** 本页是与 [英文源决策](/adr/0103-compact-context-usage-summary) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受（由 D347 / ADR 0184 修订）
- 日期：2026-08-18
- 决策者：PI-Desktop 渲染器与 UX 维护者
- 修订：D103、D184、ADR 0047

## 上下文

上下文用量检查器暴露了有用的 token 数据，但其默认面板变成了一份密集的诊断报告：堆叠的 KPI 卡片、多个来源徽标、供应商行、解释性的估算文案，以及每个工具一行的可视化行。这使快速容量检查与对话内容相互争夺注意力。

## 决策

1. 保留现有的点击/键盘触发、剩余容量状态、感知视口的主体 portal、点击外部关闭以及 Escape 行为。
2. 保留面板的核心摘要：剩余 token 及百分比、已用/窗口计数、回合总计、已完成回合的生成速度、精确的供应商用量值、聚合的工具类型/调用次数/token，以及存在时的最新压缩摘要。
3. 将回合和速度值渲染为无边框的行内统计信息。将供应商和工具用量渲染为两行紧凑的摘要行，不带区块卡片或来源徽标。聚合工具总数上的 `~` 标记仍作为估算信号。
4. 从默认面板中移除逐工具行、占比条、供应商/工具来源徽标、解释性的估算段落以及已用容量计量条。底层的用量聚合与持久化保持不变，因此这只是渲染器层面的展示工作。
5. 保持触发器和面板的可访问性：本地化标签、对话框语义、键盘激活、Escape/点击外部关闭时的焦点返回，以及碰撞感知的定位均保持不变。

## 后果

- 常规的上下文检查可在一个简短、易扫读的面板中完成，而不再是冗长的诊断列表。
- 精确的供应商数据和聚合工具成本仍然可见，而详细的逐工具归因不再是默认界面的一部分。
- 不涉及主机协议、存储 schema、运行时统计或模型元数据契约的变更。
- E2E 和组件规格必须验证紧凑摘要，而不是已移除的诊断行。

## 被拒绝的备选方案

- **保留所有行，仅缩小字号：** 保留了密度问题，并使面板更难扫读。
- **完全移除工具用量：** 会丢失工具对大回合有贡献这一有用信号；聚合行以较低的视觉成本保留了该信号。
- **立即将每个细节都放到第二个展开区之后：** 为状态检查增加了另一次交互，因此推迟到用户表明确有下钻归因需求时再考虑。
