## 上下文

工作面板此前包含一个交互式 shell，由 Electron 主进程中的 PTY 和工作面板 UI 中的
终端渲染器提供支持。该界面与代理的非交互式 `Bash` 工具相互独立，但它为桌面应用
增加了一个原生模块、渲染器依赖、终端专用 IPC、打包规则以及第二套 shell 生命周期。

产品无需拥有交互式 shell 也能让 Agent Bash 保持有用。需要交互式 shell 的用户可以使用
其操作系统或开发环境提供的外部终端，而命令调用和有限输出仍可在对话中查看。

## 决策

1. 移除工作面板的交互式终端。面板保留插件贡献的视图，包括内置的 Files 和 Browser
   视图（ADR 0170），以及由对话工件打开的 Review/文件标签页。
2. 保持 Agent Bash 不变。它仍然是一个权限感知、非交互式的代理工具，其命令、输出、
   状态、复制行为以及 `IconTerminal` 呈现保留在对话记录中。计划刷新状态中的通用生命周期
   值（如 `"terminal"`）与之无关，仍然有效。
3. 删除仅用于终端的 Electron 主进程管理器、渲染器组件和样式、IPC
   调用/事件通道、共享终端载荷类型以及终端专用测试。移除 PTY/xterm 依赖及其构建、
   unpack 和 lockfile 配置。
4. 不要用插件 PTY API 替代被移除的界面。交互式 shell 访问被有意委托给外部终端，
   不引入新的插件权限或私有内置插件通道。
5. 不要递增已冻结的桌面协议版本。被移除的通道是桌面 IPC 的附加项；Agent Bash、
   主机 RPC 以及共享生命周期协议保持不变。

## 后果

- 工作面板没有交互式 shell 标签页或终端启动器，其空状态仅列出 Browser 和范围内的
  插件视图。
- 桌面打包不再包含 PTY 原生模块或终端渲染器依赖，减少了原生构建和发布面。
- 交互式 shell 工作流需要使用外部终端。Agent Bash 仍然是应用内进行有限、模型导向的
  命令执行的路径。
- 历史 D099/D249 记录作为历史仍然有用，但其终端实现和保留条款已被本决策取代。

## 考虑过的替代方案

### 将 PTY 保留在主机中

已拒绝：这为一个产品不再需要拥有的界面保留了第二套 shell 生命周期和原生依赖。

### 将 PTY 移入插件

已拒绝：插件 PTY 权限会授予以用户身份任意执行的能力，而仅限内置的通道会创建私有的
信任边界例外。

### 将 Agent Bash 变为交互式终端

已拒绝：Bash 有意保持有限、权限感知且由对话记录拥有。将其改为长期运行的交互式会话
会改变代理协议和安全模型，而不仅仅是移除工作面板界面。
