## 上下文

内置的 `pi.files` 查看器此前使用其标题栏操作，通过操作系统关联的应用程序打开选中的文件。这种交接方式并非对每种文件类型或平台都可靠，也不符合定位项目文件这一主要浏览意图。该查看器已经知道所选文件的根相对路径，而主机也具备原生的文件管理器显示操作。

## 决策

1. 添加 `pi.fs.reveal(pathFromRoot)` 以及匹配的面板桥接通道 `fs.reveal`。
2. 使用现有的 `fs.read` 权限以及完整的已声明文件作用域检查对该操作进行门控：根包含关系、符号链接解析、受保护路径、拒绝列表，以及清单作用域或用户同意。仅接受存在的常规文件，且插件不提供绝对路径。
3. Electron 主进程在门控通过后调用 `shell.showItemInFolder`。在平台支持的情况下，文件管理器可以选中该文件。
4. 内置的 Files 查看器将其标题栏操作替换为 **Show in folder**，并在显示失败时报告本地化的 toast。`fs.openDefault` 仍作为附加的公共 API 提供给明确需要交接给关联应用程序的插件。
5. 显示成功和失败都会以插件 id 和根相对路径进行审计。没有桌面 IPC 或主机核心协议版本变更。

## 后果

- 选中的文件可以在不依赖文件关联的情况下被定位。
- 该操作无法显示凭据、受保护的应用程序数据、工作区或所选根之外的文件，或插件已声明读取作用域之外的文件。
- 第三方插件可以使用与内置 Files 插件相同的有界操作；不会引入私有的内置插件能力。
