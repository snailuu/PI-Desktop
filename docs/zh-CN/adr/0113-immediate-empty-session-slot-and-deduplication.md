# ADR 0113：立即持久化「新建任务」的空槽位并按消息数去重

> **翻译说明：** 本页是与 [英文源决策](/adr/0113-immediate-empty-session-slot-and-deduplication) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- **状态：** 已接受
- **日期：** 2026-08-21
- **取代：** ADR 0084 / D220
- **相关：** D088 · D093 · D305 · E2E-011b · E2E-011d · E2E-011e · E2E-011g
- **修订自：** ADR 0154（首帧展示空会话；无需阻塞式列表刷新即可复用）

## 背景

ADR 0084 将会话创建推迟到第一条提示词。这消除了闲置的空行，但也让「新建任务」操作在侧边栏中不可见，并移除了按范围限定的空会话复用行为。产品现在要求在保留每个项目或临时侧边栏分组仅一个空槽位的同时，提供一个真实、立即可见的空会话。

标题无法定义「空」状态，因为用户可以重命名空会话，而且第一条消息也可以独立生成标题。主机核心已经在 `sessions.last_seq` 中存储了当前对话记录序号，它就是在追加和重写操作之后的当前消息数。

## 决策

当针对某个项目或路径缺失的临时分组触发「新建任务」时：

1. 将该分组中未归档的会话按 `updatedAt` 降序排序。
2. 如果最近的会话为空（`messageCount = 0`，且渲染器没有实时行、正在运行的回合或已提交的草稿），则选中它，并在首帧展示其空对话记录。选中已经处于活动状态的行是空操作。
3. 否则，在首帧展示空白首页，通过 `session.create` 创建一个真实的空会话，并将返回的摘要插入侧边栏。不要阻塞等待 `session.list` 或 `session.get`（ADR 0154）。

针对同一分组的渲染器请求会被串行化。这使得快速重复点击会观察到第一个已完成的空槽位，而不是竞争发起多个 `session.create` 调用。项目路径继续通过现有的分组辅助函数进行规范化，而路径缺失的会话使用同一规则，而不是单独一种会话类型。

`SessionSummary.messageCount` 被加入共享的 IPC/会话协议。Rust 主机从 `sessions.last_seq` 推导该字段；无需存储迁移，且协议 v9 保持兼容，因为这是一个增量式的会话摘要字段。标题启发式仍仅用于展示：侧边栏渲染空行，而复用决策从不调用 `isDefaultSessionTitle`。

应用的启动首页仍是未持久化的渲染器草稿，因此仅打开应用不会创建槽位。显式的「新建任务」操作才会创建或复用持久槽位。当第一条提示词或粘贴的附件需要会话时，启动草稿仍会实体化。

## 影响

- 新会话在第一条用户消息之前即可见、可选中。
- 同一分组中重复点击「新建任务」是幂等的，而不同项目分组保持相互独立。
- 当更新的非空会话是该分组的最新会话时，较旧的空会话可能仍然保留；该规则有意只考虑那个最新会话。
- 空会话会一直持久存在，直到用户删除或归档它们。
- 协议 v9 增加了一个增量式摘要字段；存储 schema v11 与主机归属保持不变。

## 备选方案

- 保留 ADR 0084 中未持久化的草稿：被否决，因为该操作在侧边栏中没有即时的存在感，也无法提供持久可用的槽位。
- 继续使用默认标题作为空状态判定条件：被否决，因为手动重命名改变的是展示，而不是对话记录状态。
- 新增主机侧的特殊 `session.createOrReuse` RPC：被否决，因为现有的渲染器导航边界无需扩展主机方法目录即可实施所要求的分组规则。
