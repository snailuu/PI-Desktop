# ADR 0115：将插件剪贴板历史保持为主机所有并存于内存中

> **翻译说明：** 本页是与 [英文源决策](/adr/0115-plugin-clipboard-history-is-host-owned) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受（2026-08-21 修订）
- 日期：2026-08-21
- 相关：Issue #9、ADR 0008、ADR 0059

## 上下文

插件可以读取和写入当前剪贴板，但插件进程无法访问 Electron 剪贴板。因此，剪贴板历史插件过去只能轮询 `readText()` 并维护第二份存储，同时主机也在轮询原生剪贴板以捕获图像。这样的做法会反复读取并编码未发生变化的截图，在空闲时也消耗资源，而且仍会漏掉采样间隔内发生的复制。

剪贴板历史也比当前剪贴板更为敏感：它可能留存截图、凭据或私人文档。为每个插件各自配备记录器会导致数据重复、留存策略不一致，并削弱权限边界。

## 决策

Electron 主进程维护一份滚动、位于内存中的历史记录，并通过 `pi.clipboard.getHistory()` 将其暴露给插件。该 API 复用 `clipboard.read`，返回按最新优先排序的文本与图像条目，并对每次调用按条目数量进行审计。插件进程仅通过现有 broker 接收类型化结果；它们不会获得 Electron 对象或新的能力。

主机不轮询系统剪贴板。它记录通过 `writeText` 写入的文本，并记录来自输入框用户主动触发的 `paste` 事件的内容。渲染器将它在上述事件中已经收到的字节传给主机；对于同一次粘贴，主机绝不会再次读取操作系统剪贴板。图像仅在该次粘贴请求期间被规范化为 PNG。

内容连续相同时会被折叠并刷新时间戳。历史记录在应用退出时清空，并受以下边界约束：

- 保留 30 天；
- 500 个条目、总负载 256 MiB；
- 每个条目 100 KiB 的 UTF-8 文本或 50 MiB 的 PNG 图像字节。

## 后果

- 空闲应用不会读取或编码剪贴板内容，输入框的粘贴处理也不会执行第二次原生剪贴板读取。
- `getHistory()` 包含主机的写入内容以及粘贴到输入框中的内容；从未被粘贴的复制操作按设计不会被捕获。应用启动前已复制的内容无法恢复。
- 历史记录仍归主机所有、仅存在于内存中，并受现有 `clipboard.read` 权限保护。这在不变更插件 API 的前提下限制了隐私暴露。
