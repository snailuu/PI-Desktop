# ADR 0117：为原生最小化保留 Windows 任务栏条目

> **翻译说明：** 本页是与 [英文源决策](/adr/0117-windows-taskbar-native-minimize) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受（由 ADR 0123 修订）

## 上下文

D216 中的托盘驻留最小化决策会将主窗口从操作系统的窗口列表中隐藏。在 Windows 上，点击当前聚焦窗口的任务栏按钮是一种原生的最小化/恢复切换操作。Electron 会通过主窗口的 `minimize` 事件上报该切换中最小化的那一半。而当前的处理器随后调用 `window.hide()`，这会移除任务栏条目，只剩下托盘图标作为恢复路径。

## 决策

1. 在 Windows 上，主窗口的原生 `minimize` 事件不会被转换为 `window.hide()`。由操作系统完成最小化，因此主窗口仍由其任务栏条目表示。
2. 渲染器绘制的 Windows 最小化按钮和 Windows 原生菜单的最小化操作使用相同的原生最小化过渡。Linux 的渲染器与原生菜单最小化操作同样使用该过渡。macOS 的原生最小化事件仍保持托盘驻留。
3. 现有的恢复路径继续恢复并聚焦同一窗口。因此，当窗口只是被遮挡时点击任务栏条目会保持其现有的置于最前行为；无需新增 IPC、存储或宿主协议契约。

## 后果

- Windows 对操作系统任务栏切换和显式应用内最小化操作采用同一种原生任务栏最小化模型。
- 在 Windows/Linux 上，任务栏最小化的窗口仍可从任务栏访问；关闭到托盘的窗口仍可从驻留的托盘图标访问。
- 后台工作和窗口边界持久化保持不变。
