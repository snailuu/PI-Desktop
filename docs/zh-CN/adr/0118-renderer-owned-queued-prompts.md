# ADR 0118：让队列中的提示词由渲染器持有，并在回合边界停止运行

> **翻译说明：** 本页是与 [英文源决策](/adr/0118-renderer-owned-queued-prompts) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受（2026-08-24 实现）
- 日期：2026-08-24
- 相关：Issue #11、ADR 0073

## 上下文

桌面宿主强制每个会话同一时间只运行一个回合。在该回合运行期间禁用输入框会让用户不得不等待，或中止一个有用的回复，然后才能提供下一条指令。将第二个提示词移入主机核心或持久化存储会引入重放和生命周期归属问题，而这些对于一个临时的编辑器队列并不需要。

## 决策

渲染器持有一个以会话 id 为键的内存 FIFO 队列。队列项包含其可见提示词和输入框草稿快照，因此文件引用仍可独立移除，并可通过正常的提示词通道发送。该队列不持久化，在应用重启或会话删除时会被丢弃。切换会话只会改变在活动输入框上方投影的是哪个队列。

在一次运行处于活动状态时，发送和停止控件同时存在。正常的发送会添加一个队列项。渲染器在所属会话收到 `agent_end` 之后，逐个取用队列项；每一项都使用现有的 `agent/prompt` 路径，从而保持宿主单运行回合的不变式。现在，发送会将其项移到队首，并调用新增的 `agent/stop` IPC。sidecar 将该请求映射到 pi-agent-core 的 `shouldStopAfterTurn` 钩子，因此当前回复和已完成的工具批次会正常结束，持久化回合以 `completed` 关闭，然后优先项才开始。

立即中止仍然独立存在：它会立即取消活动运行时，并保持队列项不受影响，以便之后显式发送。

## 后果

- 用户可以在长时间的模型/工具运行期间继续输入，并排队多条下一回合的指令。
- 发送现在具有精确的下一边界语义，而不会产生第二个并发的持久化回合或 `AGENT_BUSY` 竞态。
- 队列内容会在重启时有意丢失，且对其他会话不可见；如果未来的产品需求需要，可以单独考虑持久化。
- 优雅停止的精确度仅限于 pi-agent-core 的边界：活动的供应商流会被允许完成，而待处理的权限仍可等待其正常解决。
