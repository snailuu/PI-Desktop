# ADR 0119：事件驱动的子代理超时

> 为 300 秒，而非 600 秒。决策 4 中列为无限制的内置项现在
> 带有回合兜底限制。下文对“仅使用空闲时间”的否定针对的是

## 上下文

最初的委派循环使用默认回合上限。因此，某个每回合进行一到两次
有用工具调用的委派可能会在其正在积极工作时被终止，而且无法区分
真正空闲的工作者与正在等待长时间运行工具的工作者。

## 决策

1. 委派有两个独立的看门狗：600 秒无活动，以及
   21,600 秒的总运行时长。总计时器包含工具执行时间。
2. 活动是指任何委派回合、消息或工具生命周期事件。空闲
   计时器在 `tool_execution_start` 与其匹配的
   `tool_execution_end` 之间暂停，因此长时间的 Bash 调用由工具超时
   管控，而不是由委派空闲时间管控。
3. 看门狗以 `timed_out` 终止委派，并附带
   `SUBAGENT_IDLE_TIMEOUT` 或 `SUBAGENT_DURATION_TIMEOUT` 之一。报告在存在
   最新的部分助手输出时会携带该输出。提供商故障、
   父级中止以及显式回合上限保留其既有结果。
4. `maxTurns` 是可选的。省略、`none` 和 `0` 表示无限回合；
   正数显式值仍作为有界兜底，上限为 80。
5. 定义可以覆盖 `idle-timeout` 和 `max-duration`。空闲值被
   钳制到 10–21,600 秒，时长值被钳制到 60–21,600 秒；
   非数值会发出警告并使用默认值。
6. 内置 `explorer` 获得 `Bash`，用于诸如 `git log` 之类的有界只读检查；
   `code-reviewer` 保持只读。由于 Bash 可能造成变更，Explorer
   继续使用现有的变更/权限分类。
7. 共享状态契约和桌面拓扑会暴露 `timed_out`；
   渲染器以英文和简体中文为其加标签，并将其呈现为
   警告结果。

## 考虑过的替代方案

- **提高回合上限：** 遭否决，因为任何固定上限仍会终止
  正在积极工作的委派，并且在不同模型和工具密度下扩展性很差。
- **仅使用总时长：** 遭否决，因为提供商或委派可能
  无限期卡住，同时仍低于总体上限。
- **仅使用空闲时间：** 遭否决，否则持续的模型/工具活动可能
  在没有硬性资源上限的情况下一直运行。
- **让 Explorer 保持只读而不使用 Bash：** 遭否决，因为这会阻止
  原生搜索工具无法表达的无害仓库检查命令；
  现有权限路径对 Bash 仍然具有权威性。

## 后果

- 委派在保持活动时可以突破此前 20–24 个回合的行为，
  同时空闲和总运行时故障仍然有界且可诊断。
- 超时报告对 `TaskWait`、`TaskList` 和委派
  拓扑可见，包括其结构化错误码和计时日志条目。
- 显式设置 `maxTurns` 的定义为专用或不受信任的工作负载
  保留确定性的硬性停止。
