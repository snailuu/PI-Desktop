# ADR 0121：保持 Composer 提示增强为一次性且由主进程拥有

> **翻译说明：** 本页是与 [英文源决策](/adr/0121-one-shot-composer-prompt-enhancement) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-24
- 相关：Issue #14

## 上下文

Composer 需要一种便捷方式来改进草稿，而无需发送消息、更改对话记录，或将供应商凭据暴露给渲染器。该功能还需要遵循 Composer 中显示的模型，同时在该选择在请求进行中发生变化时保持安全。

## 决策

提示增强是一项加入允许列表的渲染器到 Electron IPC 操作。渲染器发送草稿以及供应商/模型/思考快照。Electron 主进程验证草稿，通过现有运行时启动解析器解析有效的供应商和凭据，并直接调用 agent-runtime 执行单次补全。该补全仅接收静态增强系统提示和一条 `Draft:\n<draft>` 用户消息；它没有会话历史、工具、附件、持久化回合或对话记录副作用。

渲染器拥有交互状态：加载中、一级撤销、可关闭的分类错误，以及一个编辑代际守卫，用于丢弃迟到的结果。主进程仍然是 API 密钥和供应商 OAuth 解析的唯一拥有者。供应商失败复用现有分类和有界设置重试行为；仅含空白字符的输出是一种专门的终止错误。

## 后果

- 草稿改进快速且可逆，不会创建隐藏消息或代理运行。
- 供应商/模型快照使请求相对于可见选择器是确定性的，而主进程侧回退则使过期或不完整的快照保持安全。
- 渲染器只接收文本和分类错误数据，从不接收机密。
- 该功能有一个新的类型化 IPC 契约，并且必须保持其 UX 和 E2E 场景与运行时行为同步。

## 考虑过的替代方案

- 复用 `agent/prompt`：被拒绝，因为它会持久化一个用户回合，使用对话上下文，并启动正常的代理生命周期行为。
- 在渲染器中运行供应商调用：被拒绝，因为凭据和供应商 OAuth 绑定是主进程拥有的安全材料。
- 存储增强历史：v1 中被拒绝；一个精确的撤销快照就足够，并避免增加持久化所有权。
