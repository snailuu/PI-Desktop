# ADR 0122：在工作面板可见时保留原生宽度

## 上下文

工作面板作为文档流内的 flex 同级元素渲染是正确的，但渲染器已开始为每个状态请求 `0` 的原生保留宽度。因此当面板折叠时，Electron 窗口仍保持较大的尺寸，主聊天窗格扩展进入释放出的面板列。这导致应用程序的右边缘保持固定，而不是回到仅聊天时的窗口边界。

目标交互是一个停靠面板，在可见时保持稳定的聊天宽度：当显示器工作区允许时，窗口扩大以腾出空间；折叠路径则对称地将窗口恢复到面板出现前的边界。

## 决策

1. 在渲染器中保持工作面板为固定宽度的文档流内 flex 列。
2. 在呈现已打开的面板之前，通过 `window/setWorkPanelReservation` 请求等于其已提交宽度的原生保留宽度。
3. 让面板在退出动画期间保持挂载，然后请求保留宽度 `0`，且仅在该请求成功后卸载。这样折叠时会从原生窗口释放面板宽度，而不会出现中间状态的呈现跳变。
4. 继续根据渲染器测量出的面板矩形来定位原生 Browser `WebContentsView`；原生保留宽度只是为文档流内的面板腾出空间，并不拥有其内容几何。
5. 保留现有的目标状态、感知显示器的保留行为：当工作区受限时，主进程会限制增加的宽度，撤销任何由保留引起的 x 方向偏移，并将原生边缘缩放交由主进程负责。

## 后果

- 只要显示器能够提供已提交的保留宽度，面板打开时对话宽度就保持稳定。
- 折叠或关闭面板会将应用程序收缩回其基础边界，而不是让聊天占用释放出的面板宽度。
- 在受限显示器上，面板保持固定，聊天只吸收不可避免的保留宽度缺口。
- 现有的渲染器到主进程的 IPC 接缝、幂等几何规划器和退出动画生命周期继续使用。
- 临时的可见面板保留宽度会从持久化的启动边界中移除，因此重新启动仍会从用户仅聊天时的窗口尺寸开始。

## 备选方案

### 保留 ADR 0033 的固定窗口内部停靠

被拒绝，因为折叠面板会使应用程序窗口比用户面板出现前的边界更宽，并导致聊天扩展到面板的空间中。

### 叠加面板而不进行 flex 分配

被拒绝，因为面板会覆盖聊天内容，并失去现有的键盘、缩放和原生 Browser 几何契约。
