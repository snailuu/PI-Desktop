# ADR 0123：对 Windows/Linux 窗口控件使用原生任务栏最小化

> **翻译说明：** 本页是与 [英文源决策](/adr/0123-native-taskbar-minimize-controls) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-25
- 决策者：PI-Desktop 主机核心
- 相关：D216、D230、D252、D256、E2E-124、ADR 0078、ADR 0090、ADR 0117

## 上下文

Windows/Linux 使用无边框窗口，其最小化、最大化和关闭控件由渲染器绘制。最小化操作此前调用的是 `window.hide()`，这会把窗口从任务栏中移除，使该操作表现得像关闭到托盘。关闭按钮已经拥有独立的、持久化的 `tray`/`quit` 选择，因此两个不同的控件意外地共用了同一种隐藏窗口行为。

## 决策

1. Windows/Linux 渲染器的窗口控件 `minimize` 操作调用 Electron 原生的 `BrowserWindow.minimize()` 转换。Windows/Linux 原生菜单的最小化操作使用同样的转换。
2. 主窗口的 `minimize` 事件不会把 Windows/Linux 的原生最小化转换为 `hide()`。操作系统会保留任务栏条目，以便用户能够正常还原同一窗口。
3. macOS 保持其现有的“交通灯”式常驻托盘最小化行为。Windows/Linux 的关闭行为仍由 ADR 0090 负责：关闭按钮在 `tray` 下隐藏到托盘，在 `quit` 下退出。
4. 常驻托盘、关闭行为的持久化、IPC 操作允许列表、主机协议以及后台进程生命周期均不变。

## 后果

- Windows/Linux 的三个窗口按钮现在符合预期的桌面模型：最小化进入任务栏，最大化切换窗口状态，关闭遵循用户已记住的托盘/退出选择。
- 托盘仍可用于关闭到托盘以及 macOS 现有的最小化行为；不会引入第二套托盘生命周期。
- 无需新增特权桥接或协议版本，因为现有的 `minimize` 操作只改变了其由主进程拥有的 Electron 效果。

## 考虑过的替代方案

- **将显式最小化保持为隐藏到托盘：** 已拒绝，因为在选择关闭到托盘时，它会使最小化和关闭控件难以区分，并且移除了标准的任务栏还原路径。
- **移除常驻托盘：** 已拒绝，因为关闭到托盘和 macOS 最小化仍然需要一个可靠的还原入口。
