# ADR 0124：将临时会话绑定到其自身的临时工作区

> **翻译说明：** 本页是与 [英文源决策](/adr/0124-temporary-session-scratch-workspace) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-26
- 相关：Issue #16、ADR 0059、ADR 0118

## 上下文

临时会话有意保持 `projectPath` 为空，这样它们就不会继承或修改当前可见的项目。但这使得它们的原生工具没有根目录，尽管每个会话已经拥有一个确定性的 `<data_dir>/scratch/<sessionId>` 目录。空主页在临时对话和没有活动会话这两种情况下还使用了相同的 hero 文案。

## 决策

1. 主机核心将持久化的无路径会话的工具工作区解析为其自身的 `<data_dir>/scratch/<sessionId>` 目录，并在首次解析该绑定时创建该目录。会话 schema 保持不变，`projectPath` 仍然缺失。
2. Read、Glob、Grep、Write、Edit 和 Bash 将该临时目录用作临时会话的工作区根目录。该根目录绝不会取自可变的全局工作区，且现有的包含检查与权限检查仍然适用。对于缺失会话的兼容性调用，可以保留旧的全局工作区回退。
3. Plan 和 Goal 的工作区校验仍然要求存在持久化的项目绑定，因此临时工作区不会扩大 contract 模式执行的适用范围。
4. 渲染器根据所选会话推导空主页的 hero 状态：项目会话保留带项目下划线的欢迎语，临时会话显示专用的临时对话文案且不提供项目操作，而没有活动会话时显示通用欢迎语。

## 后果

- 临时对话可以安全地使用原生工具，而不会触及项目或继承最近活跃的项目。
- 临时对话中的相对工具路径可以立即使用；临时数据保持短暂性，并遵循现有的会话删除/启动清理机制。
- 临时会话在视觉上和结构上仍然与项目会话保持区分，同时不引入新的会话类型或持久化迁移。
- Plan 和 Goal 保持其现有的项目根目录边界。

## 考虑过的替代方案

- **继承可见项目：** 已拒绝，因为这违反临时会话隔离的不变式，并且可能修改无关的项目文件。
- **新增一种持久化会话类型：** 已拒绝，因为现有的无路径会话模型已经提供了正确的生命周期和分组。
- **让工具保持不可用：** 已拒绝，因为这会使临时对话无法执行原本可隔离的检查和临时工作。
