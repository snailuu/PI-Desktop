# ADR 0126：代理能力页面是一个可进行创作的统一工作台

> **翻译说明：** 本页是与 [英文源决策](/adr/0126-agent-capability-workbench) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-27
- 相关：ADR 0063、ADR 0112、D193、D194、D202
- 基线：`0.10.8`

## 背景

`d24e1ee0` 将 Skills、MCP 和 Subagents 从扩展中移到了设置 > 代理中。这次迁移带走了列表和启用开关，但沿途删除了 `SkillEditorSheet.tsx` 和 `SubagentEditorSheet.tsx`。宿主侧从未被削减：`skills.create`、`skills.update`、`skills.remove`、`skills.read`、`skills.reveal`、`subagents.create`、`subagents.update`、`subagents.remove` 和 `mcp.remove` 仍然通过 `api.ts` 与 `rpc/mod.rs` 端到端解析。只是渲染器不再调用它们。

这些页面被留下的形态随之带来了三个问题：

1. **层级曾是结构，而非过滤器。** 每个页面都堆叠了一个全局卡片块和一个项目卡片块，各自拥有自己的标题、自己已解析的路径、自己的计数和自己的操作。一个只有四项技能的页面把大部分高度花在了两个标题上，而项目选择器只能在第二个块内部、第一个列表之下去触达。
2. **一个待处理请求就锁住了整个页面。** 行以 `busy={loading || busyKey !== null}` 和 `disabled={loading || busyKey !== null}` 渲染，因此切换任意一项能力都会禁用页面上的每一个控件，包括无关层级中的行。
3. **一次切换就会闪过骨架屏。** `toggle()` 在成功时等待 `load()`，而 `load()` 无条件设置 `loading`，于是一次开关把整个列表替换为骨架行，随后再重新构建出来。

这些问题合在一起，让这些页面读起来像是一个罗列能力的地方，而不是管理能力的地方。D202 还进一步把 Subagents 页面固定为“一个固定高度的全局列表”，从而把只读形态写进了决策日志。

## 决策

1. **每个页面一个工作台。** Skills、MCP 和 Subagents 各自在一个抬升的面板上方渲染一个工具栏。工具栏承载层级过滤器（一个带实时计数的分段控件）、一个搜索字段、项目选择器以及该页面的主要操作。层级成为一个列表之上的过滤器，而不再是一对分区；在面板内部，每个层级是一行分组表头（层级名称、已解析的 `.agents` 路径、计数），其后跟着它的各行。每一行还携带自己的层级徽标，因此当某一行滚动到远离其分组表头的位置时，仍能表明它属于哪里。
2. **这些页面具备创作能力。** 针对这三种能力，创建、编辑和删除都回到设置中，通过恢复的编辑面板和本已存在的宿主调用来完成。新建的能力会落在过滤器所指向的层级上，主要操作的 tooltip 也会写明该目标位置。破坏性的行操作位于每行自己的溢出菜单中，并在执行前先进入待确认状态：第一次按下会把该菜单项改名为确认提示，而该待确认状态会在几秒后自行失效，或在菜单关闭时失效。这仅在 Subagents 页面的呈现层面覆盖了 D202 的“一个固定高度的全局列表、没有项目选择器”；subagent 仍然只支持全局层级，这正是该页面没有层级过滤器、也没有项目选择器的原因。
3. **忙碌状态按行隔离，刷新也不等同于首次绘制。** 只有正在进行请求的那一行处于忙碌状态；页面其余部分保持可交互。页面会记录自己是否曾经完成过数据填充：骨架屏只在首次绘制时渲染，之后的每次加载都保留屏幕上已有的行，并让列表变暗，同时向辅助技术播报正在刷新。
4. **启用状态采用乐观更新。** 开关先在本地翻转，随后发出宿主调用，只有当宿主拒绝时才恢复之前的位置。成功时无需重新加载，因为本地补丁已经与宿主所做的改动一致——这既消除了骨架屏闪烁，也消除了每次切换一次的往返。
5. **`skills.reveal` 接收层级。** `revealUserSkill` 和 `IPC.invoke.skillReveal` 处理器现在接受 `{ id, level?, projectPath? }` 并将其转发给 `skills.read`，后者一直都能解析这两者。处理器仍然接受裸 id 字符串，因此没有调用方会被破坏。

## 影响

- 查看能力和管理能力发生在同一处，设置页面不再为宿主本就支持的创作功能而依赖扩展。
- 定位项目层级的技能会打开该项目的文件。此前只发送 id，因此若某个项目技能在全局层级没有相同 id 的对应项，就无法被解析。
- D202 固定的页面形态在呈现层面已被取代。它所设定的数据边界——`~/.agents/subagents` 下仅含全局文档、启用状态位于 `<data>/agent-capabilities/subagents.json`、不向 Markdown 写入任何内容——保持不变。
- `maxTurns` 在 Subagents 编辑器中可以表达为“无限制”。该字段旧的渲染器默认值（24）来自 `f8868b81` 已移除的 `DEFAULT_SUBAGENT_MAX_TURNS` 常量；解析器现在把缺失的 `maxTurns` 视为无限制，`UserSubagentInput` 把 `0` 视为清除覆盖值，因此编辑器会让该字段保持为空，而不是强加一个手写文档本不会施加的上限。
- 除 `skillReveal` 的载荷被拓宽外，本次变更只涉及渲染器。没有主机核心的改动，没有新的 RPC，没有存储或 schema 的改动。
