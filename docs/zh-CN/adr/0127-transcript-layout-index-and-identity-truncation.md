# ADR 0127：转录布局索引与基于身份的截断

## 背景

ADR 0120 限定了打开会话时向渲染器发送的内容，但明确保留了“用于定位所请求页面的顺序扫描”。这块残留正是用户感知到的剩余问题：打开会话仍然是随整个对话线性增长的，而且随着对话变长而劣化，因为最新 100 条消息只能通过先解析它之前的每一行才能找到。该扫描还会逐行反序列化 `type` 判别字段，因此一个很大的工具结果仅仅为了被分类并跳过就要被完整遍历一遍。

在同一路径中还发现了另外两个缺陷，二者都是坐标空间混淆，而非性能问题：

- 该窗口用 `SessionSummary.message_count` 来钳制 `messageBefore`，而它其实是 `sessions.last_seq`——一个去重后的逻辑计数。转录位置是物理文件行号。某条消息的持久化文件追加成功但其索引提交未成功（一个有文档记录的崩溃窗口）会使该计数器永久低于行数，于是尾部窗口会截掉最新的消息：它们存在于磁盘上，却从未到达渲染器。
- 重新生成与编辑后重发把 `truncateBefore` 作为
  `sessionHistory[sessionId].messageStart + userIndex` 发送，即把一个物理文件偏移量加到一个指向渲染器去重且经过显示过滤的数组的索引上。只有当渲染器持有完整历史时，这个和才指向预期的消息，因此在从分页回溯的转录中重新生成时，可能在错误的位置截断，并把错误的尾部作为修订归档。

另外，一次在主机上已提交的会话分支可能会在 UI 中消失：两个分支操作在其导航意图（D139）被取代后都会提前返回，而此时 `api.forkSession` 已经创建了子会话。该分支仍留在磁盘上，却不在侧边栏中，直到手动刷新。

## 决策

1. **布局索引。** host-core 为每个会话维护一份*转录布局*：每条消息行与压缩行的字节偏移量，以及记录这些偏移量时所依据的 `file_len`。一个有界窗口直接定位到它选中的第一行，因此服务该窗口的代价是窗口本身，而不是它之前的历史。该布局是缓存在内存中的派生数据：`file_len` 用于检测增长（只扫描尾部）、收缩或被替换（重新扫描），而每一条重写与删除路径都会丢弃该条目，因为重写可能产生相同的长度。不完整的末尾行既不计入偏移量也不计入 `file_len`，这样后续刷新会在写入方完成该行后将其纳入。
2. **低成本分类。** 转录行通过对*顶层* `type` 键进行一次深度感知扫描来分类，绝不把整行解析成值。深度很重要：工具结果和检查点详情是开放式 JSON，可能嵌套一个自身 `type` 恰好也命名了某种行类型的对象，而按位置或首次匹配的检查会误读它。在每一新行中 `type` 都写在最前面，因此扫描通常会在第一个键处停止；而在先前排序下写出的行把 `type` 放在其负载之后，也同样由该扫描读取，因此无需迁移。
3. **单一坐标空间。** 读取窗口的偏移量是物理消息行位置，并依据布局进行钳制。`last_seq` 绝不用于此目的。压缩链仍然随任何窗口整体返回，因为最新的检查点决定模型上下文。
4. **基于身份的截断。** `agent/prompt` 接受 `truncateFromMessageId`，主机针对自己的转录解析该身份；无法解析的 id 会以 `NOT_FOUND` 拒绝，而不是在一个猜测的位置上截断。`truncateBefore` 仍为旧调用方保留，并已说明其正确性条件。
5. **持久化的分支提交。** 记录分叉出的子会话（会话列表、缓存的转录、检查点标记）是无条件的，因为当调用返回时它已经在主机上持久化了。只有可见的切换——活动会话、转录、工作面板、历史条目——仍以导航意图是否仍然有效为条件。

## 考虑过的替代方案

- **把布局持久化到 SQLite：** 已否决。重建成本很低，而一份持久副本会带来 schema 迁移，以及一个在崩溃后可能与文件不一致的第二事实来源。
- **通过让 `last_seq` 成为文件位置的权威来修复钳制：** 已否决。按设计它是一个去重计数器；让文件去迎合它意味着要重写转录来修复一个派生索引。
- **保留基于索引的截断，并始终先重新加载完整历史：** 已否决。这恰好重新引入了本次改动所移除的完整历史读取，而且发生在产品中对延迟最敏感的操作上。
- **在被取代的分支操作之后刷新会话列表：** 作为丢失分支的补救措施已被否决。它依赖一次额外的往返来修复渲染器本来已经持有的状态。

## 影响

- 打开会话以及每一页更旧的内容，代价都是所请求的窗口，而不是对话长度；一个很大的工具结果不再为了被跳过而解析。在 3,000 条消息 / 32 MB 和 12,000 条 / 129 MB 的合成转录上实测，热尾部窗口保持在约 0.7-0.8 ms，而先前的顺序读取从 6 ms 增长到 25 ms，因此代价不再随历史长度增长。会话的首次打开仍然要付出一次索引扫描。
- 该布局是一个带有显式有效性标记的缓存，因此崩溃或重写后的正确性不依赖于它是否存在或是否新鲜。
- 拥有未索引文件行的会话，其最新消息再次可见，向后翻页也能到达真正的第一条消息。
- 从分页回溯的转录中重新生成会替换用户所选的那个回合。
- 在用户导航离开时创建的分支仍然会被列出并可以打开。
