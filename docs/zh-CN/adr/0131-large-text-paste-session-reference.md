# ADR 0131：将过长的输入框粘贴文本溢出至会话暂存区

> **翻译说明：** 本页是与 [英文源决策](/adr/0131-large-text-paste-session-reference) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- Status: Accepted
- Date: 2026-08-28
- Deciders: PI-Desktop core
- Related: Issue #20, D262, ADR 0059, ADR 0070, ADR 0124

## 上下文

原生 textarea 粘贴对于简短提示词很有用，但超大的粘贴文本块会让输入框难以编辑，并使可见提示词膨胀。应用已经具备有界的 Electron 到主进程粘贴桥接，以及用于剪贴板文件的会话自有暂存目录。该方案必须保留精确的粘贴字节，在光标位于草稿中间时依然可用，避免修改项目，并让面向模型的提示词可通过现有 `@path` 文件语义被寻址。

## 决策

1. 新增持久化的 `largePasteThreshold` 应用设置。其默认值为 600 个字符，接受 1 到 1,000,000 之间的整数值。处于或低于该阈值的纯文本粘贴保留原生 textarea 行为。
2. 超过阈值的纯文本粘贴由输入框拦截，并通过现有的 `composer/pasteFiles` 桥接作为单个 UTF-8 `text/plain` 文件发送。Electron 主进程校验持久会话，并使用现有的有界、经净化、唯一文件策略将其存储在 `<data_dir>/scratch/<sessionId>/pasted/` 下。
3. 输入框在原始选择位置插入 `@<temporary-name> `，并将仅渲染器使用的 token 到规范路径映射随草稿一起存储。该 token 保持内联可见，因此现有草稿的前缀和后缀仍可编辑。它在派发之前立即被原地解析且仅解析一次；它不会作为第二个引用被追加，也不会作为重复的结构化附件被包含。
4. 该映射保持会话作用域，在其所属会话的项目/工作区切换后依然存在，参与草稿缓存和未应答 smart-Stop 恢复，并在 token 从文本中移除时被删除。会话暂存区的生命周期与清理保持现有由主机拥有的行为。
5. 剪贴板文件和图片保留其现有的紧凑 chip 与结构化附件流程。本决策仅改变超过所配置阈值的纯文本粘贴。

## 影响

- 大量粘贴文本块不再占据可编辑的提示词主体；用户会在精确的粘贴位置看到一个紧凑、可寻址的引用。
- 代理可以通过规范暂存路径读取精确保存的字节，而项目树、工件存储和主机协议 schema 保持不变。
- 该设置向后兼容，因为较旧的应用设置通过主机归一化而非数据库迁移获得默认值。
- 渲染器必须保留少量草稿元数据，以区分生成的 inline token 与用户键入的 `@` 文本，并避免重复序列化。

## 考虑过的替代方案

- **将所有文本保留为内联：** 拒绝，因为大文本块仍然难以编辑，且不必要地扩大了提示词内容。
- **直接写入工作区：** 拒绝，因为粘贴是临时输入，不得污染用户的项目。
- **仅使用 chip：** 拒绝，因为所要求的交互能力是在粘贴位置的内联引用，并且周围的草稿必须保持可读。
- **将 token 作为 basename 发送或追加第二条路径：** 拒绝，因为暂存文件需要其规范路径，而这两种选项都可能产生歧义或重复同一输入。
