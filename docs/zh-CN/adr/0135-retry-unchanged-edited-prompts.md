# ADR 0135：重试未修改的已编辑提示词

> **翻译说明：** 本页是与 [英文源决策](/adr/0135-retry-unchanged-edited-prompts) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-08-31
- 决策者：PI-Desktop 核心
- 相关：D137、D274、E2E-073、issue #23
- 修订：D137

## 上下文

用户消息编辑器是一个“编辑并重新发送”的工作流，但其主操作曾被标记为“发送”，并将未修改的提示词视为无操作。这导致当用户明确要求重放所选回合时，即使内容与原文本一致，确认操作看起来也像是失效了。同时，这也让内联操作看起来像是一次新的普通输入框发送，而不是对现有提示词的重试。

## 决策

1. 确认一次有效的用户提示词编辑时，无论去除首尾空白后的提示词文本是否与原文不同，始终通过已有的 `editUserMessage` / Regenerate 路径分发。
2. 内联主操作本地化为“重试”（zh-CN 中为 `重试`）；其进行中标签为“重试中…”（zh-CN 中为 `重试中…`）。次要操作仍本地化为“取消”（zh-CN 中为 `取消`）。Escape 保留其现有的取消行为，Cmd/Ctrl+Enter 则触发“重试”。
3. “重试”保留现有的附件处理、斜杠命令展开、基于身份的截断以及 D109 修订归档。不引入任何 IPC、存储、宿主协议或运行时契约的变更。

## 后果

- 重放未修改的提示词会创建一个新的助手回合，并在现有修订分页器中归档被替换的答案尾部，与该操作的重发语义保持一致。
- 内联标签将“重试所选回合”与“发送新的输入框提示词”以及“取消编辑”区分开来。
- 用户仍可通过 Escape 或“取消”放弃编辑且不改变对话记录。

## 备选方案

### 将未修改的编辑保持为无操作

已拒绝。这正是 issue #23 中报告的行为，并且会让一次明确的重新发送确认看起来毫无反应。

### 将主标签保持为“发送”

已拒绝。该操作不会追加一条新的普通提示词；它通过 Regenerate 路径重放所选提示词。“重试”更能传达这一边界。
