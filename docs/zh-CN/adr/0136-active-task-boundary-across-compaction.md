# ADR 0136：在上下文压缩过程中保留活动任务边界

> **翻译说明：** 本页是与 [英文源决策](/adr/0136-active-task-boundary-across-compaction) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

Codex 形态的压缩会保留若干最近用户提示，同时丢弃建立这些提示是否已完成的助手消息和工具消息。因此，在一个已完成的任务之后，下一个提示可能看起来像又一条裸用户消息，模型可能恢复旧任务（issue #22）。

## 决策

1. 检查点携带不透明的 `details.retainedTailMode`，其值为 `active_turn` 或 `completed_turn`。
2. 当供应商必须在工具结果、`toolUse` 或溢出恢复之后继续时，使用 active-turn 检查点。它只保留最新的用户消息，并受现有 20,000-token 上限和截断约束。
3. 在终末回合边界、新提示之前以及手动压缩时，使用 completed-turn 检查点。其保留尾部为空；摘要对已完成工作具有权威性，下一个用户提示是唯一的新任务。
4. `fresh_window` 家族仍然是 ADR 0064 的无摘要例外，并且始终携带空尾部。
5. 不带此字段的旧检查点会被规范化为仅保留最新用户消息。可见转录、持久检查点链、宿主所有权和协议形态均不改变。

## 后果

- 已完成的用户请求在压缩或重启后，不会作为裸历史上下文被重放。
- 活动工具循环保留继续当前任务所需的那一个提示，而助手消息/工具消息仍由摘要表示。
- 现有检查点无需迁移即可保持可读，并带有保守的最新用户回退策略。

## 备选方案

- 保留多条最近用户消息可以保存更多字面的提示文本，但当完成消息被压缩掉时会丢失任务边界。
- 保留助手消息和工具消息可以保留更多上下文，但可能搁置未完成的工具调用，并违反 Codex 形态的检查点形式。
