# ADR 0141：使展开的侧边栏宽度可由用户调整

> **翻译说明：** 本页是与 [英文源决策](/adr/0141-sidebar-width-resize) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-01

## 上下文

侧边栏固定的展开宽度使得较长的项目名称和会话标题难以查看，而永久加宽的侧边栏又会为紧凑的工作区浪费空间。外壳（shell）已经负责侧边栏布局和折叠状态，因此宽度偏好状态也应归属于同一渲染器边界。

## 决策

展开的侧边栏在其右边缘暴露一个调整大小的手柄。指针移动会预览一个以指针按下位置为锚点的宽度，主面板随之连续重排。宽度会取整并被限制在 `240px..520px` 范围内，默认值为 `275px`；只有在指针释放时才将偏好宽度持久化到侧边栏渲染器偏好存储下。

该手柄是一个 ARIA 垂直分隔条。它支持 ArrowLeft/ArrowRight（步进 16px）、Home 和 End。键盘操作会立即提交更改。Escape、指针取消、失去所有权以及组件卸载都会恢复在指针按下时捕获的宽度。折叠侧边栏会保留偏好的展开宽度。

## 后果

- 用户可以选择舒适的侧边栏宽度，而不会改变原生窗口边界或工作面板的预留行为。
- 渲染器仍然是侧边栏宽度的唯一所有者，避免了新的 IPC 契约，并使原生窗口边缘缩放保持独立。
- 较小的边缘命中区域和可见的聚焦/悬停样式增加了一个可发现的控件，同时不改变密集的侧边栏行布局。

## 考虑的替代方案

- 固定宽度：被拒绝，因为它阻止用户容纳较长的项目/会话标签，也无法回收未使用的侧边栏空间。
- 原生窗口预留或第二条调整大小通道：被拒绝，因为侧边栏是文档流中的渲染器列，其宽度只应触发主面板重排。
