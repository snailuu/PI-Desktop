# ADR 0142：允许非回环 HTTP MCP 端点并明确披露风险

> **翻译说明：** 本页是与 [英文源决策](/adr/0142-allow-non-loopback-http-mcp) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

自托管的 MCP 服务器通常部署在私有局域网中，并且只暴露一个纯 HTTP 端点。现有的 MCP 客户端已经支持 streamable HTTP，但校验逻辑会拒绝所有非回环的 `http://` URL。这就阻止了诸如 `http://192.168.1.20:8080/mcp` 这类常见配置，即使用户已经有意配置了该服务器。

旧的限制同样适用于插件声明的 MCP 服务器。移除该限制不得移除插件权限或插件出站边界：HTTP 端点可以观测到凭证、工具参数和工具结果，而纯 HTTP 无法提供机密性或完整性。

## 决策

1. 用户自有和插件声明的 MCP 服务器接受绝对的 `http://` 和 `https://` URL。不支持的 scheme 和格式错误的 URL 仍然无效。
2. 用户 MCP 编辑器对非回环 HTTP 显示明确的警告：凭证和工具调用可能被拦截。该警告仅作提示；输入并保存用户自有的 MCP 端点即视为用户同意。
3. 插件声明的 HTTP MCP 服务器仍然需要 `mcp.server.remote`，且其 host 必须被 `manifest.net.domains` 覆盖。面向插件的审核界面中显示相同的警告。现有的高风险权限仍是向远程端点发送工具调用的同意依据。
4. MCP HTTP 客户端禁用自动跟随重定向，将重定向限制为五跳，仅允许 HTTP(S) 重定向目标，并对每一跳调用可选的端点策略。插件重定向到其声明网络允许列表之外的 host 时，会在下一次请求前被阻止。
5. 插件市场目录和包下载策略保持不变。非回环 HTTP 的包下载仍然被拒绝，因为本决策涉及的是 MCP 运行时连通性，而非插件分发。

## 后果

- 部署在局域网中的自研 MCP 服务器无需 TLS 终止即可工作。
- 网络允许列表对插件持有的出站流量（包括重定向目标）仍然具有权威性。
- 用户和插件审核者可以看到连接是否未加密，但主机无法使纯 HTTP 服务器在网络拦截面前变得安全。可信的网络部署位置仍然是一项运营要求。
- SDK、渲染器、主机核心、客户端测试、安全文档和 E2E 场景必须描述一致的 HTTP 策略。
