# ADR 0143：使会话标题可由用户重命名

> **翻译说明：** 本页是与 [英文源决策](/adr/0143-user-renamable-session-titles) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-01

## 上下文

任务是持久化会话，但其标签目前由默认标题和首次提示自动标题流程控制。一旦任务积累了历史记录，用户就需要一个稳定的标签，以便在侧边栏、项目归档、顶部栏和搜索结果中更容易识别。Issue #27 请求在不改变任务本身的情况下重命名项目任务。

## 决策

将任务名称视为会话元数据，并提供一个共享的重命名对话框。该对话框可从侧边栏会话溢出/右键菜单以及项目归档任务行打开。它会裁剪输入，接受 1–80 个 Unicode 码点，并在值为空时保持保存操作不可用。主机端校验相同规则，因此直接调用 IPC 的调用方无法持久化无效标题。

重命名仅更新 `sessions.title`。它不会修改转录记录、消息数量、项目绑定、空会话判定条件或 `updated_at` 活动时间戳。非默认标题会继续选择退出首次提示自动标题生成。使用现有的 `session.rename` IPC 和主机 RPC 通道；无需更改 schema 或协议版本。

历史通知标题快照保持不变。新渲染的界面会读取当前会话摘要，因此在本地存储更新后以及重启后，重命名后的标题会显示在侧边栏、顶部栏、项目归档和搜索结果中。

## 后果

- 用户可以从主要任务导航和项目索引中为任务命名。
- 主机端校验为渲染器及未来的客户端提供了一致的持久化契约。
- 重命名不会意外改变任务在最近活动顺序中的位置，也不会改变代理上下文。
- 渲染器负责模态框焦点、错误呈现，以及在主机确认会话存在后立即更新本地标题。

## 考虑过的替代方案

- 仅从顶部栏重命名：拒绝，因为任务在打开之前就可以从侧边栏或项目归档中发现和管理。
- 重命名项目文件夹或项目记录：拒绝，因为请求针对的是单个任务/会话，而不是工作区身份。
- 添加命令面板命令：推迟；现有的行操作就是可发现的界面，此操作不需要新的全局命令。
