# ADR 0144：允许用户配置思考级别覆盖

> **翻译说明：** 本页是与 [英文源决策](/adr/0144-user-configurable-thinking-level-overrides) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-01
- 决策者：PI-Desktop 核心团队
- 更新 ADR 0114 和 ADR 0134

## 上下文

供应商模型列表将已发布的模型元数据与持久化的 `ModelBinding` 合并。Electron 主进程在将 `ModelInfo` 返回给设置之前应用了该绑定。因此，一个没有启用任何思考级别的现有绑定，会让 models.dev 的推理记录看起来不支持推理，即使目录正确地将该模型描述为具备推理能力。

同样的交集也导致：当某个兼容代理或新发布的模型，其端点支持的思考级别未在当前目录快照中发布时，便无法对其进行配置。

## 决策

保持 `ModelInfo` 为 models.dev 发布的原始记录。存储的绑定值不得改写其已发布的推理字段或能力标签。有效的供应商和会话能力，会单独根据所选模型的确切 `ModelBinding` 来解析。

设置选择器始终渲染七个规范思考级别：`off`、`minimal`、`low`、`medium`、`high`、`xhigh` 和 `max`。已发布的级别会为新增的已知模型绑定提供种子值。对于非推理或未知模型，相同选项会以未选中状态显示，并附有一条简洁的手动覆盖提示。用户的显式选择按原样保存，不会与 models.dev 列表取交集。空绑定或仅包含 `off` 的绑定表示禁用思考；至少一个非 `off` 选择会为该供应商/模型启用推理。

输入框在渲染其推理菜单之前，会解析所选模型的确切绑定。运行时钳制使用该绑定中启用的级别。这是一种显式的端点配置，而不是自动声称上游模型支持所选级别；用户负责选择代理或端点所接受的级别。

## 后果

- 正确的 models.dev 推理元数据仍会在设置中可见，即使存在较旧或手动清空的绑定也是如此。
- OpenAI 兼容代理和新发布的模型无需等待目录更新即可选择启用思考。
- 目录元数据仍是已发布模型事实的唯一来源；它只提供默认种子值，不会静默抹除显式的端点配置。
- 无需更改 IPC、存储 schema 或主机协议。
- 端点可能会拒绝显式启用的级别；桌面端不会根据用户的选择推断或保证上游支持。

## 曾考虑的替代方案

- 将 models.dev 视为绝对的思考能力门控：已拒绝，因为它使有效的代理配置变得不可能，并导致存储的绑定隐藏已发布的推理元数据。
- 自动将每个 OpenAI 兼容模型标记为具备推理能力：已拒绝，因为兼容端点的行为各不相同，且发现机制不得推断不受支持的行为。
- 为每个模型添加单独的“启用思考”布尔值：已拒绝，因为现有的 `thinkingLevels` 集合已经同时表达了启用的级别和确定性默认值。
