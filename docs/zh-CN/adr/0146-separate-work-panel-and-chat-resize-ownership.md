# ADR 0146：按边界分配工作面板外部与内部的尺寸调整归属

> **翻译说明：** 本页是与 [英文源决策](/adr/0146-separate-work-panel-and-chat-resize-ownership) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：被 ADR 0151 取代
- 日期：2026-09-02
- 相关：ADR 0122、ADR 0132

## 上下文

可见的工作面板是一个参与文档流的右列，由原生宽度预留支撑。它的渲染器分隔条和原生窗口的右边缘都是尺寸调整的可操作点，但把两种手势都归给同一个维度，就会出现不改变对话宽度就无法调整面板、或者不改变面板偏好就无法调整对话的情况。

## 决策

工作面板打开时：

- 外层原生右边缘（包括 Electron 上报的右角区域）负责面板目标。主进程保持基础对话宽度固定，向渲染器预览受约束的 `244..720px` 面板目标，并在原生调整尺寸流稳定后提交该目标。原生最小尺寸会被临时下调，以便面板目标能够到达其最小值。
- 内层渲染器分隔条负责基础对话宽度。指针和键盘操作使用受约束的 `window/setWorkPanelChatWidth({width})` 目标状态通道（`1040..10000px`），并保留当前生效的面板预留。请求会被串行化，因此快速的指针流不会打乱原生边界更新的顺序；当工作区过于局促时，对话目标会在即将压缩面板之前停止。取消操作会再次发送按下时的目标。
- 左侧边缘和非右原生边缘保留其既有的基础窗口行为。显示切换、最大化/全屏延迟、持久化的基础边界以及工作区预留钳制继续遵循 ADR 0122 和 ADR 0132。

该事件是 Electron 本地的，不改变主机协议版本。

## 后果

两种尺寸调整手势都有了明确归属的维度。在任一手势进行期间，渲染器必须临时屏蔽合成后的 Browser 视图和插件视图，并且面板分隔条的可访问值描述的是对话目标，而不是面板目标。Linux 使用主进程的右边缘光标位置作为回退，因为 Electron 的 `will-resize` 边缘细节在该平台上不可用。

## 被否决的替代方案

- 保留旧的渲染器分隔条作为面板尺寸调整器，让原生边缘调整对话尺寸：这不满足所要求的边界归属。
- 暴露不受限制的 BrowserWindow 调整尺寸 IPC：这会削弱目标状态与校验边界，而两种手势都不需要它。
