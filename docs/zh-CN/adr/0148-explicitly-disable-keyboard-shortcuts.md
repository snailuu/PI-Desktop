# ADR 0148：显式禁用应用程序快捷键

> **翻译说明：** 本页是与 [英文源决策](/adr/0148-explicitly-disable-keyboard-shortcuts) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-03
- 决策者：PI-Desktop 主机核心
- 相关：Issue #31、E2E-072、ADR 0072、ADR 0076

## 上下文

共享的应用程序快捷键设置支持缺省覆盖或自定义绑定，但删除覆盖项总是会恢复默认值。用户无法有意解绑某个操作，而类 null 值会被视为无效，随后被静默解析回默认值。

## 决策

`AppSettings.keybindings` 为每个应用程序快捷键使用三种状态：

- 属性缺省时使用平台默认值；
- 有效的可移植绑定字符串覆盖默认值；
- 显式的 JSON `null` 表示 `Unbound`，并禁用分发。

无效字符串仍回退到默认值，以免损坏或手动编辑的设置静默禁用产品操作。设置 UI 将“禁用”与“恢复默认”分开展示，显示本地化的 Unbound 状态，并让已解绑的操作不参与冲突检查。应用程序快捷键映射由渲染器分发、macOS 菜单加速键和插件启动器共享。

当 `openPluginLauncher` 被解绑时，Electron 会注销任何先前的全局加速键；Windows 还会禁用主机核心的 `Alt+Space` 钩子及聚焦窗口回退。可配置的 macOS 原生角色项在解绑时使用无角色的可点击项，因为当省略 accelerator 时，Electron 会恢复角色的默认加速键。

该设置仍保留在现有的 JSON 设置对象中。不新增 IPC 方法、协议版本、存储迁移或插件本地快捷键行为。该值是可移植的，不是 Electron 加速键字符串。

## 后果

- 用户可以禁用任何内置应用程序快捷键，同时不会失去恢复其默认值或录入新绑定的能力。
- `resolveKeybinding` 返回 `string | null`，因此所有消费方都必须显式处理无绑定状态。
- 现有设置保持其行为；缺省项和有效字符串项保持不变，只有新持久化的 `null` 值会禁用操作。
- 即使 macOS 菜单项的可配置快捷键被解绑，其点击操作仍然可用。
