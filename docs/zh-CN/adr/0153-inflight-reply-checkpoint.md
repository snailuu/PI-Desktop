# ADR 0153：在转录记录旁边对“流式回复”做检查点

## 上下文

规范 04 让 assistant 行与 tool 行在各自的结束事件时变为持久化的：代理运行时只发出一次
`message_end`，随后 Electron 主进程通过持久化 outbox 追加该行。用户在这之前看到的
所有以流形式输出的内容，只存在于渲染器和 sidecar 的内存中。代理型回复会以流形式
持续输出数分钟，而应用会被频繁退出或重启。因此，退出、sidecar 崩溃或回复过程中途重启，
都会丢失整个回复：启动扫描会把该回合标记为 `aborted`，重新打开的会话只显示提示词，
其下什么都没有。本周的会话日志表明，一天之内就出现了八个这样的回合。

两个较小的缺陷又加剧了这一问题。`before-quit` 先销毁主机核心，然后直接杀掉 sidecar，
因此即便是已经到达最终消息的回复也无法被持久化。而且，渲染器的 Stop 路径对长会话
会重新读取持久化转录记录，用其替换自己的实时行，并基于该快照重写转录记录；运行时
被中止的最终行通常仍在 outbox 中，所以这次重写会立即隐藏该回复，并且如果追加操作
恰好在此期间落盘，还可能将其删除。同一次重写还会把渲染器受 64 KB 显示上限约束的行
写回覆盖完整行。

## 决策

1. **检查点文件，而不是转录记录行。** 主机核心拥有
   `sessions/<id>.inflight.json`：一个以原子方式替换的对象，保存该会话正在流式输出的
   assistant 消息及其回合 id。Electron 主进程观察 `message_update`，保留最新的快照，
   并至多每 1.5 秒调用一次 `session.saveInflightMessage`，并做尾部写入。
   以转录记录行形式追加检查点被否决：一段持续数分钟的回复会留下数十个近乎副本，
   使文件膨胀并打乱物理行分页窗口。
2. **落定规则。** 同一 id 的最终 `session.appendMessage` 会删除该文件。`session.endTurn`
   在 `completed`/`error` 时删除它；在被要求 `recoverInflight`（sidecar 已消失）时，
   将其提升为一条 `aborted` assistant 行；对于单纯的 `aborted`（用户 Stop），
   则保持不动，以便运行时自己的最终行可以取而代之。主机启动时会提升每一个最终行
   从未落盘的遗留项。对于已被索引的 id，其检查点会被丢弃，因此当最终行落盘时
   仍在进行中的写入无法将其复活。检查点绕过 outbox；委托回复不做检查点。
3. **退出时先落定回合。** `before-quit` 会冲刷检查点、通过 sidecar 中止活动回合，
   并在主机核心仍存活时最多等待 2 秒让被中止的行排空，然后销毁主机和 sidecar。
4. **渲染器 Stop 绝不重写已开始的回复。** 落定在内存中进行；持久化副本是运行时
   的被中止行或已提升的检查点。未应答提示词的撤销与消息删除只会基于完整持久化
   转录记录与实时行的合并结果重写，并且撤销会在该合并之上重新评估。

## 后果

- 退出或崩溃造成的丢失被限制在回复的最后 1.5 秒加上仍在运行的 tool 行；重新打开的
  会话会在一个 `aborted` 回合下，以一条 `aborted` 行显示提示词和部分回复。
- 每个流式会话每个时间间隔产生一次小文件写入；SQLite 中没有新增内容。
  `session.endTurn` 新增 `recoverInflight` 和 `recovered`。
- 会话删除时，检查点文件会随其他会话文件一起被删除。
- 规范 01 §5.3、04 §2.1 和 §4.7、06、07 §5；E2E-171；D299。

## 修订（2026-09-06）——已完成回复在进程重启后得以保留（D327）

Issue #42 显示：在一次完整退出之后，出现与 D324 为进程内会话切换所修复情形相同的、
只有用户行的转录记录。两条落定规则丢弃了一段已完成但仍只在 outbox 中的回复：

1. `message_end` 在入队之前就调用了 `settle()`，因此主机检查点最多滞后 1.5 秒，
   而已完成快照的尾部写入被取消。
2. 针对 `completed`/`error` 的 `session.endTurn` 会删除检查点，即便该 id 尚未被索引。
   启动恢复随后拒绝提升一个回合已经是 `completed` 的遗留项。再结合握手之后
   即发即忘的 outbox 冲刷，一次冷启动的 `session.get` 就只绘制出了用户行。

修订内容：

- Electron 主进程对已完成的 `message_end` 快照做检查点，然后调用 `settleIf`，
  以免在该写入期间启动的更新的回合被清掉。
- `completed`/`error` 的 endTurn 只在最终行已被索引时才删除检查点。未被索引的遗留项
  会保留给 outbox 或启动流程。
- 启动/恢复时提升一个回合为 `completed` 的遗留项，会将该行写为 `complete`，
  而不是 `aborted`。其他遗留项仍保持 `aborted`。
- 主机握手会**等待**持久化 outbox 排空之后，渲染器才能执行 `session.get`，随后调用
  `session.recoverInflightMessages`（修订 ADR 0041）。启动恢复会跳过已完成的遗留项，
  以便已完成的 outbox 行胜出。同一 outbox 中的 tool 行由该排空覆盖；它们仍然
  不会被检查点化。

退出时仍会（有界地）等待活动回合。在 outbox 文件写入之后发生的硬杀，会由被等待的
握手排空来恢复。在该持久化之前发生的硬杀，会从已完成检查点恢复。
