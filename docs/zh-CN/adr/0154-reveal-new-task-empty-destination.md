# ADR 0154：在宿主 IO 之前先显示新建任务的空目标

> **翻译说明：** 本页是与 [英文源决策](/adr/0154-reveal-new-task-empty-destination) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## Context

ADR 0113 让新建任务持久化一个持久化的空会话（或复用该分组最新的空行）。渲染器实现该逻辑时，会依次等待 `session.list`、`session.create`、再一次 `session.list`，然后 `session.get`，之后才更改可见的对话记录。在这一链路期间，上一个对话仍停留在屏幕上：冷切换规则（ADR 0137）在打开已有会话时是正确的，但对于全新的空目标而言，会让人觉得点击没有反应，随后聊天界面又突然跳转。

`session.list` 之所以存在，是为了避免片刻前刚发出的首条消息在 `messageCount` 仍为 0 时被误认为是空槽位。渲染器已经能够识别这种情况：会话正在运行、存在实时行，或输入框中已有已提交的草稿。

## Decision

1. **首帧即显示空态。** 创建会话会在 `session.create` 之前同步清空上一个对话记录和保留的面板。空白的首页输入框即为目标。复用空槽位时，会在同一帧提交空对话记录，而不是等待 `session.get`。
2. **复用时不刷新列表。** 新建任务根据内存中的会话列表以及渲染器信号（`runningSessions`、实时/缓存行、已提交草稿）做出判断。宿主的 `messageCount` 仍是持久的空态判定条件；内存中的信号仅用于避免把刚刚开始的回合当作空会话。
3. **以 `session.create` 为准提交。** 创建出的摘要会像 fork 子项那样插入侧边栏列表。对于新的空会话，不再有后续的 `session.list` 或 `session.get`：其对话记录已知为空。被取代的导航仍会记录该行。
4. **每个分组同时只允许一个进行中的创建。** 发送和粘贴操作会等待同一作用域下的新建任务 promise，而不是实际创建出第二个会话。在创建期间于空白首页输入的按键会转移到新的会话 id 上。

协议、存储和宿主 RPC 均未改变。`session.create` 仍是持久 id 的来源。

## Consequences

- 新建任务不再把上一个对话留在屏幕上。
- 快速连续点击新建任务以及首条消息竞态，仍按分组串行化。
- 复用空会话时，在空面板已经可见之后，仍会通过 `selectSession` 重新校验。
- 规格 `04-ux/09-interaction-patterns.md` §1.6、`04-ux/08-component-spec.md` §11、E2E-011a / E2E-011d / E2E-011g；D305 修订的是 D252 的“先刷新再选择”时序，而非复用规则。

## Alternatives considered

- 在 `session.create` 上由客户端生成会话 id：可以首帧就有 id，无需首页草稿的过渡间隔，但会新增一个协议字段；若旧版宿主忽略该字段，还需要重新映射。
- 保留上一个面板并显示进度条：这是针对已有对话记录的冷切换规则，也正是本请求要消除的卡顿。
