# ADR 0158：保持审批卡片聚焦并记住所选模式

## 上下文

Plan/Goal 审批卡片重复展示了已提交的问题、状态和截止时间，并与工件打开入口并列。审批模式也会在每次提案时重置为 Ask，即使用户刚刚选择了其他模式也是如此。

Plan 工件文件名对 ASCII 标题采用标题派生，但对非 ASCII 标题回退到通用的 `plan`/`goal` 词干，使得本地化工作区更难浏览。

## 决策

1. 待处理审批卡片仅渲染提案标题、宿主创建的工件路径/打开操作、Reject 以及 Approve 拆分按钮。问题或描述文本、状态、有效期/截止时间以及内联安全警告均不属于卡片内容。
2. 选择 Ask、Accept edits 或 Auto 会将该选择存储到渲染器本地的设备偏好中。之后的每次审批都以存储的选择作为默认值；当存储不可用或无效时，仍以 Ask 作为回退。
3. 宿主生成的工件文件名保留字母数字的 Unicode 标题字符，将分隔符规范化为连字符，并保留时间戳和冲突后缀。路径校验继续仅接受 `.pi/<kind>/` 下生成的该安全文件名形态。
4. 现有的宿主审批截止时间仍是内部兼容性与故障关闭边界；它不再作为审批卡片概念暴露。

## 后果

- 卡片更紧凑，让注意力保持在决策和可审查的工件上。
- 经常使用 Auto 或 Accept edits 进行审批的用户，在同一设备上不必为每个提案重复该选择。
- 本地化标题可生成可识别的工件名称，同时保留唯一、由宿主拥有的不可变文件。
- 线缆/存储契约保持兼容；旧版截止时间数据不会由渲染器展示。

## 考虑过的替代方案

### 将选择持久化到宿主设置表

本次变更中已拒绝。该选择是渲染器 UI 偏好，将其加入宿主设置会扩展协议和设置所有权边界，且不会带来额外的审批安全性。

### 将问题和截止时间保留在折叠的卡片区域中

已拒绝。所要求的审批界面有意限制为标题、工件审查和两个决策；完整的 Markdown 仍可通过打开宿主创建的文件来获取。
