# ADR 0163：对话记录中的文件引用渲染为可预览的 chip

> **翻译说明：** 本页是与 [英文源决策](/adr/0163-transcript-file-reference-chips) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-05
- 决策者：PI-Desktop 核心
- 相关：D124, D209, D320, ADR 0024, ADR 0070, ADR 0019

## 上下文

输入框中的文件引用在草稿中是紧凑的叶子名称 chip（ADR 0070）。发送时，它们会序列化为规范的 `@path` / `@"path with spaces"` 文本，以便代理能够 Read 它们。对话记录随后将这些 token 渲染为完整路径，这挤占了用户气泡，并隐藏了用户刚刚放入输入框的节点。

点击路径会打开工作面板的文件查看器，而它无法将 HTML 渲染为页面，也无法打开 PDF、office 或其他由操作系统处理的类型。scratch 绝对路径也无法通过工作区相对路径的预览门禁，因此粘贴的文件根本无法点击。

## 决策

1. 对话记录解析序列化后的 `@path` token（带引号和不带引号、相对和绝对），并将每个 token 渲染为与输入框节点匹配的紧凑 chip：文件族图标、省略显示的叶子名称、工具提示与可访问名称中的规范路径。HTTP(S) URL 保持为内联文本链接。
2. 点击工作区中的 `.html` / `.htm` chip 会打开工作面板浏览器（现有的本地文件预览）。点击任何其他允许的文件则通过新的只读 Electron 通道 `pi-desktop/fs/open`，使用该后缀对应的操作系统默认应用程序打开。
3. `fs/open` 会解析当前工作区内的相对路径，以及绝对路径——仅当它们已位于工作区、`<data_dir>/scratch/` 或 `<data_dir>/attachments/` 之下时才解析。路径穿越、`~` 以及这些根目录之外的路径会被拒绝。主机协议或存储 schema 无变更。
4. 尚未由内联 `@path` chip 表示的结构化消息附件使用相同的 chip 和点击契约。工具行摘要保留现有的工作面板文件/URL 预览。

## 考虑过的替代方案

- **保留完整路径文本链接：** 被否决，因为用户一旦发送，它就会破坏 ADR 0070 的紧凑显示。
- **始终在文件标签页中打开：** 被否决，因为 HTML 应作为页面预览，且许多后缀需要操作系统处理程序。
- **始终使用 `shell.openPath`：** 对工作区 HTML 被否决，因为它已有实时重载的应用内浏览器。

## 后果

- 已发送的用户回合显示的节点与输入框中的文件节点相同。
- 用户可以在应用内预览 HTML，并使用默认应用打开其他文件。
- 主进程新增一个加入允许列表的打开通道，其包含根目录与 scratch/工作区文件工具相同。
