# ADR 0165：撤回 A2A / Peer 协调栈

> **翻译说明：** 本页是与 [英文源决策](/adr/0165-withdraw-a2a-peer-stack) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 背景

ADR 0138 引入了进程内子代理对等消息传递（`PeerSend` / `PeerInbox` / `PeerWait`）。ADR 0140 将这些合并为一个 `Peer` 工具。ADR 0147 用主机核心 Agent2Agent (A2A) 消息代理、一个 `a2a.*` RPC 域、持久化的 `a2a_*` SQLite 表以及一个委派的 `A2A` 工具取代了该邮箱。ADR 0162 随后取消了仅限同一会话内的寻址；ADR 0164 / D325 为 Agent 模式的父代理提供了核心 `A2A` 工具，以便对话可以协调。

这套栈已不再需要。同级通道和父代理到父代理通道与现有的 `Task` / `TaskWait` / `TaskList` / `TaskStop` 契约并存，增加了一个应用其余部分并未使用的协议能力，并且模型很容易遗漏或误用它。并发子代理已经通过父代理上报；这已经足够。

## 决策

从产品中移除 A2A / Peer 协调栈：

1. **取消 A2A 或 Peer 工具。** 这两个名称都不是核心 Agent 工具、可分配的子代理工具或 `ToolSearch` 结果。列出 `A2A` 或 `Peer` 的定义会像任何其他未知工具名称一样被处理：丢弃并给出解析警告。
2. **取消消息代理。** 删除主机核心 `a2a` 模块、内存注册表、遗留的进程内 `SubagentMailbox`，以及每个 `a2a.*` RPC 方法和 `a2a.task.event` / `a2a.push` 通知。
3. **取消父代理或同级通道。** 并发子代理仅通过编写自包含报告来协调，父代理通过 `Task*` 收集这些报告。父代理不会查找、向其他对话发消息或等待其他对话。
4. **协议 v11。** 握手 `PROTOCOL_VERSION` 从 10 变为 11。`capabilities` 数组不再声明 `"a2a"`。v10 主机或客户端会在握手时被拒绝，与之前每次版本提升相同的精确匹配规则。
5. **Schema v13。** `SCHEMA_VERSION` 从 12 变为 13。`migrate_v12_to_v13` 删除 A2A 表（`a2a_tasks`、`a2a_messages`、`a2a_artifacts`、`a2a_push_configs`）。全新的数据库永远不会创建这些表。v11→v12 步骤仍保留在链条中，作为仅版本号的提升，以便现有备份和链式迁移继续工作；它不再创建 v13 会立即删除的表。

委派本身（ADR 0062 / ADR 0089）保持不变：`Task` 仍然会分派有界 worker，报告仍然不会进入父代理的模型上下文，直到 `TaskWait`，并且内置工具默认保持只读。

## 后果

- 跨对话和同级消息传递已移除。希望两个会话共享事实的用户应通过提示词来实现，而不是通过工具。
- 圆桌示例插件不再指示子代理调用 `Peer` 或 `A2A`。它运行独立的并发 `Task`，并由父代理综合这些报告，可选地将较早的报告输入到后续回合的简报中。
- 0.11.3（对等消息传递）和 0.12.0（A2A）的历史变更日志条目作为已发布历史保留。产品 README 删除当前对 A2A 的声明。
- ADR 0138、0140、0147、0162 和 0164 作为记录保留在磁盘上。
