# ADR 0166：由父级判定的子代理生命周期

> **翻译说明：** 本页是与 [英文源决策](/adr/0166-parent-judged-subagent-lifetime) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 上下文

ADR 0089 让 `Task` 变为非阻塞，并要求父级在结束回合前调用 `TaskWait`
或 `TaskStop`。安全网是在父级 `agent_end` 时中止遗留的委托。ADR 0119 /
ADR 0129 随后启用了 300 秒空闲看门狗和 6 小时时长上限。

这种组合在实践中失败了：父级看不到委托的实时工作，`TaskWait` 最多在
900 秒后返回，模型将此视为可以结束的许可，而 `agent_end` 会杀死仍在
运行的委托。长时间编译、测试和审计之所以死亡，是因为父级关闭了，而不是
因为工作已完成。

再次提示模型等待并不能解决这个问题。等待是一个事件循环；模型不是可靠的
事件循环。

## 决策

1. **不要按时间杀死委托。** 不启用空闲和时长看门狗。`idle-timeout` /
   `max-duration` 仍然会被解析，以便现有文档能够加载，但它们没有效果。
   显式的 `maxTurns` 仍然是定义层面的兜底。并发仍然上限为 10。
2. **不要在父级空闲时中止。** 委托仍在运行时，`agent_end` /
   `turn_end` 会被吞掉。持久的回合保持打开。
   用户 Stop、`TaskStop` 和运行时 dispose 仍然是仅有的中止方式。
3. **在报告完成时交付报告。** 父级循环在仍有委托运行时进入空闲后，
   运行时会等待它们，并将合并后的报告注入父级提示（不作为用户气泡
   显示）。父级随后进行判断：集成、启动更多工作，或 `TaskStop`。
4. **给父级心跳，而不是完整转录。** `TaskList` 和超时的 `TaskWait`
   会包含代理、状态、已用秒数、回合数、工具调用次数和最后一个工具名。
   进程行不进入父级上下文。

## 后果

- 长时间运行的委托可以比父级最后一次工具调用活得更久。用户仍然能看到
  一个活跃的回合（Stop 仍然可用），直到报告被交付且父级真正结束。
- 父级不再需要正确地轮询才能让任务存活。
- 没有 `maxTurns` 的循环委托可以一直运行，直到用户将其 Stop。
- ADR 0119 / ADR 0129 的看门狗策略在杀死方面被撤回。它们关于
  "沉默 vs 缓慢"的分析仍保留为历史记录。

## 被拒绝的替代方案

- **父级读取进度文件（Claude Code）。** 会把实时转录放入父级上下文，
  并要求模型记得轮询。
- **保留结束即中止，只提高 TaskWait。** 模型仍然会关闭。
- **让回合存活但不自动恢复。** 用户必须发送"继续"。
