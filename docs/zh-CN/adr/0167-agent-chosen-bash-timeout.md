# ADR 0167：由代理选择的 Bash 超时

> **翻译说明：** 本页是与 [英文源决策](/adr/0167-agent-chosen-bash-timeout) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 背景

ADR 0054 / D190 要求 Bash 默认超时为 60 秒，并拒绝 1–300 秒之外的任何覆盖值。这个 5 分钟的上限会终止合法的构建、测试和审计，而 `timeout: 600` / `1800` 会立即以 `INVALID_ARGUMENT` 失败。

D273 已经放宽了 schema，使以毫秒为单位的习惯写法能够通过校验，随后又将其钳制到同样的 300 秒上限。代理即使请求 30 分钟，仍会在 5 分钟时被终止。

超时仍然是强制性的：每一次进程启动都需要一个有限的截止时间，超时/中止也仍会终止整个进程树。需要防堵的失败模式是无界挂起，而不是整数 300。

## 决策

1. 缺少 `timeout` 时仍然精确表示 60 秒。
2. 显式覆盖的取值为 1 到 21,600 秒（6 小时）。这是主机安全边界，用以让 RPC 和进程计时器保持有限，而不是期望代理触及的产品上限。
3. 大于 21,600 的值会按毫秒解读（D273），转换后钳制到 21,600 秒。范围内的值，包括 600 和 1800，均按秒处理。
4. 超出范围的值仍然无法通过校验，且绝不会启动进程。
5. 超时和用户中止仍然会终止完整的进程树。

## 后果

- `timeout: 600` / `1800` / `1800000` 可兑现 10 分钟和 30 分钟的超时。
- 未设置超时的命令仍会在 60 秒时被终止。
- 主机核心的 `MAX_BASH_TIMEOUT_MS` 与运行时保持同步。
