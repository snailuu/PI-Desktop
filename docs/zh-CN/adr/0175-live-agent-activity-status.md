# ADR 0175：用实时代理活动状态解释安静的活跃回合

> **翻译说明：** 本页是与 [英文源决策](/adr/0175-live-agent-activity-status) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-07

## 上下文

转录已经在首个模型或工具事件之前显示一行紧凑的 `Working…` 行，并为具体的思考和工具活动显示内联行。供应商请求仍可能在首个事件之前花费很长时间，而且有界重试退避或父端委托任务等待可能不包含任何转录行。在这些间隔期间，唯一可见的信号是停止按钮和一个通用的本地计时器。用户无法判断该回合是在正常等待、正在重试，还是在等待委托的工作（Issue #56）。

## 决策

使用可选的、由运行时拥有的 `AgentActivity` 值扩展现有的规范化 `status` 事件：

1. `starting` 涵盖初始提示交接。
2. `waiting-model` 在发出供应商请求时开始，持续到首个助手事件。
3. `retrying` 涵盖可中止的供应商退避，并在可用时携带尝试编号和计算出的延迟。
4. `waiting-subagents` 涵盖父端对委托工作的收敛等待，并携带运行中的目标数量。

sidecar 从拥有供应商请求、重试延迟和委托等待的相同边界发出这些阶段。当助手输出开始或回合到达终止事件时，它会清除该阶段。渲染器按会话存储最新的状态，并渲染一行紧凑的、本地化的内联行，带有单调的阶段计时器。该行不是第二个进度卡片，不声称完成百分比，也不改变停止或中止语义。

## 后果

- 安静的活跃回合能够解释其当前由运行时拥有的等待，而不会添加装饰性或重复的进度界面元素。
- 重试生命周期在转录中保持静默，而重试退避变得可观察且仍可取消。
- 会话切换保持隔离，因为状态以会话 id 为键，并随终止事件和会话删除而清除。
- 该状态有意保持粗粒度：供应商内部细节和子代理子事件仍不进入渲染器协议，除非它们能解释这些用户可见的等待之一。

## 备选方案

### 对每次等待都保留通用的 Working 行

拒绝，因为它无法区分正常的供应商等待与重试或委托等待，而这正是 Issue #56 中报告的不明确之处。

### 添加一个永久的多步骤进度卡片

拒绝，因为代理回合没有可靠的总步骤或百分比模型，而且现有的活跃回合契约使下层转录表面的界面元素保持内联和紧凑。

### 发出原始供应商或子代理事件

拒绝，因为它会暴露不稳定的实现细节，并创建比用户所需更大的协议表面。由运行时拥有的阶段提供了最小且有用的解释。
