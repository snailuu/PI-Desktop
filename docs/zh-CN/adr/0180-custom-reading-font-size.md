# ADR 0180：自定义全局 UI 字号比例

> **翻译说明：** 本页是与 [英文源决策](/adr/0180-custom-reading-font-size) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 背景

`--text-*` 字号阶梯是一组固定的产品字号（`--text-base` 为 14px，界面控件更紧凑、标题更大）。应用菜单提供放大 / 缩小 / 重置缩放，但那些会缩放整个窗口，包括布局和控件。希望字号更紧凑或更大的用户，没有一个能记住的偏好来保持正文、界面控件和标题之间的相对层级。

本决策的早期草案仅存储一个只作用于阅读区的 px 值，并且只重新映射对话记录和输入框。这会使侧边栏和设置仍保持产品字号，要求用户自行选择 px 数值，也无法缩放那些已经使用同一字号阶梯中不同级别的界面区域。

## 决策

1. **设置 → 通用 → 外观**在字体下新增**字体大小**一行。四个星巴克式杯型预设（Tall 85% / Grande 100% / Venti 115% / Trenta 125%；zh-CN：中杯 / 大杯 / 超大杯 / 超超大杯）位于百分比滑块上方。有效值为 80%–150%，步长 2.5%。缺省表示 100%。UI 从不要求提供 px 值。

2. **持久化**使用可选的 `AppSettings.fontScale`（`1` = 产品字号阶梯）。无效写入会在渲染器边界被拒绝；读取时通过 `normalizeFontScale` 进行钳制。一个未发布的遗留 `fontSize` px 字段，若存在且没有 `fontScale`，则按 `px / 14` 迁移。主机协议和存储 schema 版本号均不变。

3. **应用**是全局的。渲染器在 `document.documentElement` 上设置 `--font-scale`。每个 `--text-*` token 和 `--leading-row` 都是 `calc(<product px> * var(--font-scale))`，因此正文、界面控件、标题、代码、侧边栏和设置在无需重新加载的情况下保持比例一致。共享的 Lucide 包装组件使用 `calc(<px> * var(--font-scale))` 来设定字形尺寸，因此工具栏、侧边栏、输入框和设置图标会跟随同一乘数。

4. **缩放保持独立。**菜单和快捷键的放大 / 缩小 / 重置缩放继续缩放整个窗口。字号比例与缩放叠加生效。

## 影响

- 单个控件即可缩放所有使用 `--text-*` 的地方；本来就比正文更小或更大的区域仍保持相对更小或更大。
- 用户无需选择一个只与 `--text-base` 匹配的 px 数值。
- 较大的比例也会放大紧凑的界面控件，包括 Lucide 字形。高度为固定 px 值（而非 `--leading-row`）的行可能仍会显得更紧；150% 的上限对此做了限定。

## 备选方案

- **仅重映射 `.thread-wrap` / `.composer-dock` 的阅读区域：**可保持界面控件紧凑，但用户会在同一个窗口中出现两种字号，并且正文层级仍需要 px 数值。
- **仅使用放大/缩小：**已存在；它会把界面控件与文本一起缩放，并不是字号偏好设置。
- **修改 `html { font-size }` 并将字号阶梯改为 rem：**改动范围更大；产品字号阶梯是 px token，且 token 守护规则禁止在组件 CSS 中使用裸 rem。
