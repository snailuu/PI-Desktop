# ADR 0181：主进程所有的选择器能力

## 上下文

输入框附件可以通过 Electron 原生文件选择器来选择，然后被复制到所属会话的暂存目录中。渲染器需要在它具体化 home 草稿之后请求这次复制，但渲染器 IPC 载荷不得被视为用户选择了其中所包含路径的证明。

早先的选择器流程会把原生绝对路径返回给渲染器，随后再通过 `composer/importFiles` 接受这些路径。这使得任何有权访问 bridge 的渲染器代码都能请求复制任意常规文件，包括工作区和附件根目录之外的文件。同一流程还宣称支持目录选择，尽管导入器只接受常规文件。

## 决策

1. `composer/pickFiles` 和 `composer/pickPhotos` 在 Electron 主进程中执行原生对话框。主进程将所选路径与一个绑定到调用方 `WebContents` 的随机 token 关联存储。
2. 选择器 token 在 60 秒后过期，并在导入开始前被消费。`composer/importFiles` 接受 token 和持久的 `sessionId`，从不接受渲染器提供的源路径。token 不能被重放，也不能被另一个渲染器 WebContents 使用。
3. `pickFiles` 在 MVP 中仅提供常规文件。文件夹导入仍是独立的未来功能，在将其暴露到 UI 之前，必须定义有界遍历和所有权规则。
4. 主进程仍会对每个记录的源执行 realpath 和 stat，强制执行现有的单文件和总大小限制，并且只复制到会话暂存目录中。

## 后果

- 被攻陷或已过期的渲染器无法将选择器导入通道变成任意绝对路径复制原语。
- 取消选择器不会创建草稿会话，也不会写入暂存文件。
- 导入后，渲染器仅保留返回的会话自有暂存引用，而源路径保留在 Electron 主进程中。
- 不再以误导性的“不支持”标签提供目录选择。

## 被拒绝的备选方案

- 从选择器返回原生路径，并在导入 IPC 中再次验证它们：拒绝，因为验证并不能证明用户进行了选择。
- 在从选择器 IPC 返回之前直接导入：拒绝，因为渲染器必须仅在非取消的选择之后才具体化 home 草稿。
- 在本次变更中通过递归复制支持文件夹：拒绝，因为这需要明确的遍历、大小、符号链接和 UI 语义，超出了当前 MVP 的范围。
