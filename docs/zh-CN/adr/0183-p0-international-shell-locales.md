# ADR 0183：P0 国际化 shell 语言区域

> **翻译说明：** 本页是与 [英文源决策](/adr/0183-p0-international-shell-locales) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-08
- 决策负责人：PI-Desktop desktop/i18n 维护者
- 相关：ADR 0160、ADR 0182、D346、E2E-091

## 上下文

语言区域注册表可以在没有渲染器专属选择器工作的情况下添加语言，但已发布的 shell 止步于英语、简体中文、繁体中文和土耳其语。西班牙语、法语和德语是桌面产品的高价值国际化语言区域，却缺失于 UI 目录和应用内发布说明中。

## 决策

1. 为 `de`、`es` 和 `fr` 发布完整的 shell 目录，保留英语作为源目录，并保持键与插值的一致性。
2. 注册本地名称 `Deutsch`、`Español` 和 `Français`；可搜索的选择器继续从共享语言区域注册表派生其选项。
3. 将 `de-*`、`es-*` 和 `fr-*` 操作系统语言区域标签解析到其已发布的基础目录。持久化的 `AppSettings.language` 接受这三个新 id。
4. 发布匹配的产品更新日志目录，使发布说明跟随当前激活的语言区域。不改变主机协议、存储 schema 或 Electron IPC 版本。

## 后果

- 用户无需重新加载渲染器即可选择德语、西班牙语或法语。
- 语言区域一致性测试覆盖 shell 字符串、两种插值风格，以及发布说明的版本/亮点一致性。
- 区域变体有意共享一个基础目录；区域特定的拼写可稍后添加，而无需更改选择器契约。

## 备选方案

- 仅添加注册表行并回退到英语：被拒绝，因为它会宣称支持某些语言，却没有本地化 shell。
- 立即添加区域特定目录：被拒绝，因为 P0 目标是以每种语言一个可维护目录实现广泛覆盖。
