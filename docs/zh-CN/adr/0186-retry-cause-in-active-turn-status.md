# ADR 0186：在活动回合状态中显示供应商重试原因

> **翻译说明：** 本页是与 [英文源决策](/adr/0186-retry-cause-in-active-turn-status) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-08
- 相关：ADR 0175、D349、US-UI-60d

## 上下文

实时的 `retrying` 状态行告知用户某个供应商请求正在重试，但没有说明原因。当重试预算耗尽时，同样的已分类供应商失败已经会变成结构化的助手错误。在退避期间，用户应当能够查看当前原因，而不必产生重复的对话记录错误，也不必等到重试结束。

## 决策

扩展共享的 `AgentActivity.retrying` 载荷，加入可选的、有界的错误详情：稳定的错误码、已经过脱敏和长度限制的供应商消息，以及已知时的 HTTP 状态。运行时为请求建立阶段和流中重试两处都提供这些详情。

渲染器在静止状态下保留现有的紧凑重试行。悬停或聚焦其重试标签时，会显露出一个小型的错误样式提示框，复用助手错误卡片的层级结构：图标、本地化摘要、稳定的代码/状态，以及供应商消息。该触发器可通过键盘聚焦，并通过其无障碍名称暴露相同的原因。当活动阶段清除时提示框关闭；最终助手错误和结果呈现仍是唯一的终结性错误呈现。

## 后果

- 用户可以在重试等待期间识别速率限制、超时、网络故障和供应商错误。
- 对话记录中仍不出现中间错误行，重试行为保持不变。
- 协议只暴露运行时已经分类和脱敏的诊断信息；任意供应商载荷不会跨越该边界。
- 不带 `error` 的旧状态载荷仍然渲染普通的重试标签。

## 备选方案

### 仅使用原生 `title`

被否决，因为它无法与现有的错误呈现保持一致，对于较长的供应商消息难以阅读，并且提供的键盘访问不一致。

### 为每次重试都添加一条助手错误行

被否决，因为中间失败会与最终助手错误重复，并使同一回合内成功的重试看起来像失败的回合。

### 暴露完整的供应商响应

被否决，因为供应商响应可能包含不稳定或敏感数据。现有分类器所提供的有界消息和低基数状态已足以进行诊断。
