# ADR 0187：焦点感知的原生任务通知

> **翻译说明：** 本页是与 [英文源决策](/adr/0187-focus-aware-native-task-notifications) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- Status: Accepted
- Date: 2026-09-08

## 上下文

持久任务完成行是为处于焦点的后台会话创建的，但渲染器与 Electron 主进程曾与交互式询问/权限/计划提示共享同一个原生通知请求。因此，仅基于当前会话抑制原生输出会在应用焦点位于另一会话时仍显示完成横幅，违反了 D117 与 E2E-065。

## 决策

为仅由 Electron 使用的原生通知请求添加显式的 `kind`：`task` 或 `interactive`。当主窗口既可见又处于焦点时，任务完成绝不原生显示，无论当前选中的是哪个会话。当窗口处于隐藏、最小化或未聚焦状态时，它仍然符合显示条件。交互式提示保留其原有规则：仅抑制恰好可见且处于焦点的会话，而处于焦点的后台请求仍保持可见，以便用户能够作答。

持久任务插入策略保持不变：恰好可见且处于焦点的会话抑制收件箱行，而后台、隐藏、未知和未聚焦状态则创建该行。插件原生通知仍走其单独的、受权限门控的路径。

## 后果

- 处于焦点的后台会话完成任务时，会生成持久收件箱行，且不会产生重复的原生横幅。
- 当选中另一会话时，交互式请求仍然可操作。
- 该行为无需启动 Electron 即可进行单元测试，并且缺少 kind 的旧调用方会安全失败并回退到 task 行为。

## 考虑过的替代方案

- 对所有调用放宽共享焦点门控：已拒绝，因为这会隐藏可操作的交互式提示。
- 新增第二条原生 IPC 通道：已拒绝，因为显式的 kind 可以复用共享的验证与点击激活路径，而无需重复编写宿主代码。
