# ADR 0187：分离任务通知与交互式原生通知的投递

> **翻译说明：** 本页是与 [英文源决策](/adr/0187-separate-task-and-interactive-native-notification-delivery) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

- 状态：已接受
- 日期：2026-09-08
- 相关：ADR 0107、D117、D350、E2E-065、E2E-065a

## 上下文

PR #84 通过复用应用自有的 `notification/showNative` 处理器，为 asktool、tool-permission 和 Plan 审批提示添加了原生通知。其更宽泛的可见性判定条件允许已聚焦的后台终端完成事件显示原生横幅。这在试图支持已聚焦后台的交互式提示时，破坏了既有的任务通知约定。

## 决策

保留一个仅限 Electron 的应用通知通道，并添加可选的 `source` 字段，取值为：

- `"task"` 标识终端完成/失败的投递。它仍然仅在未聚焦时投递，包括聚焦窗口正在查看另一个会话的情况。
- `"interactive"` 标识 asktool、tool-permission 和 Plan 审批提示。仅当确切的提示会话在聚焦窗口中可见时才被抑制；聚焦的是另一个会话时可以接收横幅。

应用调用方显式传入 source。省略或未知的取值默认回退为 `"task"`，以保持兼容性并实现故障安全的投递。交互式提示仍然仅使用原生通知，不会创建持久化的任务收件箱行。插件通知继续通过其单独的、受权限门控的 API 投递，不属于此 source 字段的范畴。

## 影响

- 已聚焦的后台终端完成事件保留其持久化行，而不会产生重复的原生横幅。
- 当聚焦的是另一个会话时，用户会收到原生提示提醒；而当前可见的提示仍仅以内联方式呈现。
- source 的区分在 Electron 边界处是显式的，并由单元测试和约定测试覆盖。
- 该变更对 IPC payload 是新增式的，不改变主机协议、存储 schema 或插件权限。

## 替代方案

### 保留一个共享的可见性判定条件

被否决，因为任务结果与交互式提示具有不同的用户可见抑制策略；单一判定条件无法同时维持这两套约定。

### 新增第二个原生通知 IPC 通道

被否决，因为这会重复校验、点击激活和原生投递生命周期相关代码，却不会增加任何安全边界。

### 从通知 id 或标题推断 source

被否决，因为这些字段属于呈现数据，无法提供稳定或可审计的策略边界。
