# ADR 0188：在模型配置导入期间保留不同的凭证

> **翻译说明：** 本页是与 [英文源决策](/adr/0188-preserve-distinct-import-credentials) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 背景

CC Switch 可以为一个网关端点保留多个命名配置。这些配置可能使用不同的 API 密钥，例如不同的账户或配额。最初的导入幂等规则将归一化端点和 API 风格视为完整身份，因此导入一个选择时会创建第一个配置，并静默跳过其余配置。

渲染器仍必须不接收任何原始凭证，并且重新导入相同的配置应保持幂等。

## 决策

1. 导入的供应商仅当其归一化端点、API 风格和凭证与现有供应商匹配时才算等价。
2. 在同一端点使用不同凭证的配置将创建为独立的供应商行，并在输入框模型菜单中保持可分别选择。
3. Electron 主进程通过主机密钥边界解析现有 API 密钥以进行比较。原始值保留在主进程内存中，绝不会包含在扫描结果、渲染器状态、日志或供应商元数据中。
4. 无凭证候选者只能匹配同一端点和 API 风格的另一个无凭证供应商。仅 OAuth 凭证不会匹配 API 密钥候选者。
5. live-tool 与 CC Switch 的扫描应用相同的凭证感知规则，因此相同的 live 配置会被省略，而不同密钥的配置会被保留。主机协议或存储 schema 版本无变化。

## 后果

- 一个网关的多个 CC Switch 配置可以在一次运行中导入。
- 重新导入未更改的配置仍会报告为已跳过。
- 如果源密钥发生变化，导入会创建一个新的独立行；旧行不会被覆盖。

## 备选方案

- 仅按端点匹配被拒绝，因为它会丢失有效凭证。
- 按显示名称匹配被拒绝，因为名称可编辑，不是稳定的凭证。
- 用新密钥更新现有行被拒绝，因为它会覆盖一个可用的账户，并违反显式的导入审查边界。
