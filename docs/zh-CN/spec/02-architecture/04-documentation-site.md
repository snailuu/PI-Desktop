# 文档站点

> **翻译说明：** 本页是与 [英文源规格](/spec/02-architecture/04-documentation-site) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

## 状态

已接受。见 [ADR 0079](/zh-CN/adr/0079-vitepress-documentation-site)。

## 决策

`docs/` 目录是 pnpm 工作区内一个独立的 VitePress 项目。Markdown 仍是唯一事实来源；VitePress 提供本地开发服务器、静态构建、本地搜索索引、代码高亮以及带版本管理的导航外壳。

站点暴露两个语言区域入口：

- `/` —— 以英文为主的完整文档导航。
- `/zh-CN/` —— 每篇已记录页面的简体中文镜像，位于相同的相对路径。

对于根目录（Root Directory）为 `docs` 的 Vercel 部署，`docs/vercel.json` 将 VitePress 的构建输出声明为 `.vitepress/dist`，并启用 Vercel 的 `cleanUrls` 路由。这样，诸如 `/spec/README` 和 `/adr/README` 这类无扩展名链接在直接刷新页面后仍能正常访问，而不会变成静态托管的 404。

现有的 `spec/`、`adr/`、`project/` 及指南 Markdown 文件保持原位，以便仓库链接和审查历史保持稳定。中文页面位于 `docs/zh-CN/` 下，相对路径与其英文源文件相同。每个已翻译页面都链接到规范英文页面，并保持代码、协议字段和标识符不变。两个语言目录树暴露相同的路由，因此 VitePress 语言切换器在每一页都能正确解析；仅中文的导航页面（规格地图、其主题落地页以及精选 ADR 入口）的英文对应页面位于相同的相对路径。

## 本地命令

```bash
pnpm docs:dev
pnpm docs:build
pnpm docs:preview
pnpm docs:check
```

生产构建是静态的，不需要运行时服务。站点可能在开发或部署期间加载 Google Fonts，但内容与搜索索引均由 VitePress 在本地生成。

`pnpm docs:check` 会验证：每篇被镜像的英文页面在相同相对路径下都有对应的中文 Markdown 文件，每个中文页面都有英文源文件，并且中文伴生页面满足以下全部条件：

1. 具有一级标题，
2. 正文某处包含中文字符，
3. 包含指向其规范英文路由的链接，
4. 不残留未翻译占位 token（检查脚本以裸子串形式进行 grep，因此本页无法逐字引用该 token），
5. 与英文页面具有相同数量的围栏代码块，
6. 与英文页面具有相同的表格形状——相同的表格行数，以及每行相同数量的 `|` 单元格。

条件 5 和 6 使该检查具备结构性而非表面性的作用：即使中文页面的散文读起来完整，只要它遗漏了一行表格或一个代码块，也会被报告。该检查还会报告 `/zh-CN/` 下无法解析到镜像页面的链接，并在出现任何覆盖率、保真度或链接失败时以非零状态退出。VitePress 生产构建会单独校验渲染后的路由与内部链接。

## 内容规则

1. 英文仍是规格、ADR、代码标识符与协议术语的规范源语言。
2. 被镜像目录树（`spec/`、`adr/`、`project/`、`guide/`、`plugin-development.md` 以及本文档 README）下的每个英文页面，都在 `docs/zh-CN/` 下相同相对路径处有简体中文伴生页面；两个语言区域暴露相同的章节、路由与阅读顺序。
3. 中文页面翻译完整散文，回链到英文源文件，并逐字保留代码、协议字段与标识符。当措辞存在差异时，以英文契约为准。
4. 侧边栏由 Markdown 目录树派生，因此新的规格不会意外地从深层导航中遗漏。
5. 用户可见或协议可见的文档行为应纳入 E2E 测试计划。
6. 导航应呈现最短的有用路径；深层文件仍可被搜索并直接链接。
7. 新页面必须在同一次逻辑变更中同时落地到两个语言区域；只要缺少镜像页面或镜像表格行，语言区域检查就会失败。
